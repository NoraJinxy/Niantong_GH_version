## 一、预处理交互页 `/ica`（IcaPage）

### 1.1 设计定位

`/ica` 是科研流程中**人机协作**最密集的环节。ICA 成分剔除、坏通道标记、坏段标注都需要专业人员目视判断——算法可以提建议，最终决策必须是人。

设计原则：
- **算法辅助，人工决策**：自动推荐但不强制执行，用户可接受、拒绝、手动调整。
- **可视化优先**：拓扑图、时序图、PSD 三种视角联动，帮助用户快速判断。
- **决策可溯源**：用户的每次剔除/保留决策都记录在 decision_version，可回溯和重做。

### 1.2 页面在工作流中的位置

```
工作流运行 → ICA Compute 节点 → 产生候选成分
    ↓
   节点状态 = waiting_review（暂停）
    ↓
用户进入 /ica 审核
    ↓
提交决策 → 通知 Worker 恢复
    ↓
ICA Apply 节点继续执行 → 结果产物
```

`interactive=true` 的节点（目前主要是 `eeg/ica/apply`）在执行时会暂停，等待人工审核后才继续。`/ica` 是这个等待点的用户界面。

### 1.3 计划的三类审核 Tab

> **现状**：`IcaPage.vue` 当前只实现了 ICA 成分网格（且用的是硬编码示例数据，如"20 个独立成分"），坏通道、坏段两个 Tab 仍是规划。下面三个 Tab 是目标设计。

#### Tab 1：ICA 成分剔除

| 元素 | 说明 |
|---|---|
| 成分卡网格 | 每个 IC 一张卡，含拓扑图 + 成分 ID |
| 时序图 | 选中成分后展示时序 |
| PSD 曲线 | 频域特征辅助判断（眼电/肌电峰值特征） |
| 方差占比 | 帮助评估该成分的信号权重 |
| 自动建议标签 | `eye / muscle / cardiac / noise / brain`（来自自动分类器） |
| 勾选 / 取消 | 标记需要剔除的成分 |

**判断逻辑**：用户将看到算法建议的成分标签（如"眼电"），但可以自行决定是否剔除。常见操作：接受算法标签 → 批量勾选同类 → 确认。

#### Tab 2：坏通道标记

| 元素 | 说明 |
|---|---|
| 头皮拓扑 | 以颜色深浅显示各通道方差 |
| 通道方差柱图 | 快速定位异常通道 |
| 自动建议列表 | 算法识别的疑似坏通道 |
| 增删按钮 | 手动添加/移除坏通道 |

#### Tab 3：坏段标注

| 元素 | 说明 |
|---|---|
| 连续时序 | 多通道叠放，时间轴对齐 |
| 候选坏段色块 | 自动识别的噪声段（红色半透明遮罩） |
| 拖拽调整 | 拖动色块边界调整起止时间 |
| 增删 | 手动添加新坏段标注 |

### 1.4 与后端的对接（规划）

审核页计划使用以下 API：

| API | 用途 |
|---|---|
| `GET /pipeline-executions/{execution_id}/jobs?status=waiting_review` | 拉取待审核 Job 列表 |
| `GET /pipeline-executions/{execution_id}/jobs/{job_id}/interaction` | 获取候选成分/通道/坏段数据 |
| `POST /pipeline-executions/{execution_id}/jobs/{job_id}/decision` | 提交审核决策 |
| `POST /pipeline-executions/{execution_id}/jobs/{job_id}/resume` | 通知 Worker 恢复执行 |

## 二、观察入口 `/observe`

`/observe` 是六个分析类型子页的导航入口，由 `StaticWorkbenchPage.vue` 渲染。

当前只提供侧栏导航，不加载任何实际数据。接入后，本页计划改为：

## 三、六类观察子页 `/observe/*`

### 3.1 共同设计原则

所有观察页共享 `ObserveTabs` 组件，提供在六个子页之间切换的 tab 栏。

观察页的设计哲学：
- **结果驱动**：用户进入观察页时，已有工作流产物（Execution 产生的分析结果），观察页负责可视化这些产物，而不是重新计算。
- **多维对比**：支持多被试、多条件、多 Execution 的结果叠加对比，这是科研出版质量要求的基础功能。
- **交互式探索**：缩放、选通道、调时窗是标配——静态图够不了科研需求。

### 3.2 ERP 时域观察页 `/observe/erp`

**对应分析**：M5-10 ERP 时域分析。针对 `eeg/analysis/erp` 节点产物（Evoked）。

计划功能：

| 功能 | 说明 |
|---|---|
| 波形叠加图 | 多条件 ERP 叠加，时间轴可缩放 |
| 拓扑时序 | 时间点对应头皮分布图（可拖动时间滑块） |
| 通道选择器 | 按分区（Frontal/Central/Occipital...）快速选通道组 |
| 差异波 | 条件差值（A-B）一键计算 |
| 峰值标注 | N100/P200/N200/P300 等成分时间窗自动标注 |
| 多被试均值 | 个体 ERP + 组均值叠加显示 |

### 3.3 PSD 频域观察页 `/observe/psd`

**对应分析**：M5-20 PSD 频域分析。针对 `epochs → PSD` 产物。

计划功能：

| 功能 | 说明 |
|---|---|
| PSD 曲线 | 对数/线性频率轴，多通道叠加 |
| 频段功率柱图 | Delta/Theta/Alpha/Beta/Gamma 分频段功率 |
| 地形图（Topo） | 特定频率下的头皮分布 |
| 相对/绝对功率切换 | 相对功率排除个体差异 |
| 多条件对比 | 同一通道下不同条件的 PSD 叠加 |

### 3.4 TFR 时频观察页 `/observe/tfr`

**对应分析**：M5-30 TFR 时频分析。针对 Morlet 小波或 Multitaper 产物。

计划功能：

| 功能 | 说明 |
|---|---|
| 时频热图 | 横轴时间、纵轴频率、颜色编码功率 |
| 单通道/均值切换 | 查看单电极或通道组均值 |
| 颜色轴调节 | 手动设置 color limit，突出感兴趣频段 |
| 时频窗框选 | 在热图上框选区域，导出到统计分析 |

### 3.5 微状态观察页 `/observe/microstate`

**对应分析**：M6 微状态模块。

微状态分析将连续 EEG 切分为离散的"准稳态"（通常 4-8 类），每类对应一种头皮地形模式。

计划功能：

| 功能 | 说明 |
|---|---|
| 微状态地形图 | 每类微状态的头皮拓扑（A/B/C/D...） |
| 时序标签 | 随时间变化的微状态类别序列（颜色条） |
| 统计指标 | 平均持续时间、覆盖度、出现频率、转移矩阵 |
| 对比条件 | 不同条件/组别的微状态统计指标对比 |

### 3.6 脑连接观察页 `/observe/connectivity`

**对应分析**：M7 脑连接模块。

计划功能：

| 功能 | 说明 |
|---|---|
| 连接矩阵热图 | 通道/ROI 之间的连接强度矩阵 |
| 脑网络图 | 节点（通道/ROI）+ 边（连接强度） |
| 频段切换 | Alpha/Theta/Beta 等不同频段的连接图 |
| 阈值滑块 | 只展示超过阈值的连接 |
| 有向连接（GC/PDC） | 格兰杰因果 / 偏有向相干（规划） |

### 3.7 溯源观察页 `/observe/source`

**对应分析**：M8 溯源分析模块。将头皮 EEG 映射回大脑皮层信号。

计划功能：

| 功能 | 说明 |
|---|---|
| 皮层激活图 | 3D 大脑模型 + 激活热图 |
| MRI 配准支持 | 个体 MRI 或 MNI 标准空间 |
| 时间滑块 | 按时间点播放皮层激活动画 |
| ROI 时序提取 | 选中脑区后导出其平均时序 |

## 五、数据传输与缓存策略（已接真实数据的页面）

> 本节描述**已接真实后端**的几个观察 / 审核页（时域 / 伪迹审核 / PSD / TFR / ICA / 统计）如何把数据从服务器搬到浏览器，以及怎么**少搬、不重复搬**。与上文「仅前端预览」的页面无关——那些还没接数据。

### 5.1 为什么要专门优化传输

这些页画的是**真实脑电**（动辄 63 通道、上千采样点、多产物对比），数据量大、还跨「本地 → 阿里云双服务器」。朴素地把数组转成 JSON 文本传过来，序列化 / 网络 / 解析的开销（俗称"格式税"）能占到取数总耗时一大半。三招压它：

1. **全局 gzip**（用通用压缩算法把响应体压小）：后端对所有 JSON 响应自动压缩（`GZipMiddleware`，>1KB 才压），浏览器透明解压，省 2–3× 带宽，零代码改动、全端点受益。
2. **二进制传输**（不转文本、直接按字节传数值数组）：省掉 JSON 的序列化 / 解析。只给「大块 / 高频」的数据用——小数据 gzip 已够，上二进制是负收益。两种容器：`EEGBIN01`（时序专用：时域 / 伪迹波形）、`ELYSBIN1`（通用容器：TFR cube、PSD power 矩阵）。
3. **三级缓存**（命中哪级就到哪级、就近回填）：内存 LRU → IndexedDB（浏览器自带的本地数据库，跨刷新 / 跨会话存活）→ 网络。缓存键用**内容寻址**（产物不变 → 键不变），所以重看看过的窗 / 通道 = 零网络。

> **「JSON 回退」是什么**：开了二进制的端点，主路走二进制（快），但留了 JSON 作**备胎**——后端编码异常 / 数据形状对不上 / 传输损坏时自动切回 JSON。保证二进制优化**永不把页面搞崩、永不显示错数据**，最坏只是悄悄用回慢一点的 JSON。

### 5.2 各页现状对照

| 视图 | 端点 | 客户端 | 二进制? | 前端缓存 | 级数 |
|---|---|---|---|---|---|
| 时域 Waveform | `/timeseries` | dataApi | ✅ EEGBIN01（JSON 回退） | 内存 LRU64 + IndexedDB（plotCache） | 3 级 |
| 去伪迹 Artifact | `/input-timeseries` | dataApi | ✅ EEGBIN01（JSON 回退） | 内存 Map + IndexedDB | 3 级 |
| 频域 PSD | `/psd` | api | ✅ ELYSBIN1（JSON 回退） | 内存 + IndexedDB（useTieredFetch） | 3 级 |
| 时频 TFR · cube | `/tfr/cube` | api | ✅ ELYSBIN1（JSON 回退） | 内存 + IndexedDB | 3 级 |
| 时频 TFR · 单通道热图 | `/tfr` | api | ❌ JSON | 内存 + IndexedDB | 3 级 |
| ICA · 成分详情 | `/ica-components/{i}` | dataApi | ❌ JSON | 内存 + IndexedDB | 3 级 |
| ICA · 成分网格 | `/ica-components` | dataApi | ❌ JSON | ❌ 无（仅会话态·含可变 exclude） | 1 级 |
| 统计 Stats | `/stat` | api | ❌ JSON | ❌ 无 | 1 级 |

读表：
- **客户端**：`api` = 入口服务器、`dataApi` = 计算服务器（双服务器部署，前端按调用选用哪台）。
- **❌ JSON ≠ 没优化**：那块数据小、gzip 已够，不必再上二进制（如 TFR 单通道热图只是 cube 的 ~1/63 切片、ICA 详情小）。
- **级数**：3 级 = 内存 → IndexedDB → 网络；1 级 = 仅网络（无前端持久缓存）。
- **两个「1 级」是有意**：ICA 成分网格带可变的剔除决策（缓存会陈旧）、统计 Stats 优先级低暂没接持久缓存。

### 5.3 取数粒度（"看什么传什么"）

另一根轴是「开页传多少」，按三个维度看：

- **时间窗**：时域 / 伪迹只取可见窗（默认 ~10s），滚动 / 缩放纯前端不发请求、换窗自动进缓存 ✅。
- **通道**：开页取**全部通道**、前端只画选中的——看似浪费，实则有意：一个窗全通道（已降采样）也就几百 KB，而缓存键**不含通道名** → 换通道是**零网络瞬时切换**。改成"按通道取"反而把零延迟换成每切一次一个网络往返，net loss，**不做**。
- **数据集 / 成分**：开页只取第一个，其余按需 / 多选才批取 ✅。

> 小结：「看什么传什么」在**时间窗 + 数据集**维度已实现，**缓存免重传**是内容寻址的标准实现；通道维度的"全取"是便宜又跟手的有意取舍。唯一待办是 PSD 多选数据集时无并发上限（应加批窗节流护后端，非省流）。

> 已知功能缺口（非性能）：>64 通道的文件，**前 64 之外的通道当前选不到**（后端按位置截断 `_data_picks` + 前端选择器只认返回的通道）；仅当真有 >64 通道数据集且需看后段通道时才需补。
