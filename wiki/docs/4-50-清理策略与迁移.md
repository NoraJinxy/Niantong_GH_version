## 1. 清理策略

清理任务（`study_output_cleanup`）只能处理满足全部条件的 StudyOutput：

1. `retention_status in ('temporary', 'cached')`。
2. 不属于任何 Pipeline 的当前结果。
3. 没有被 `pipeline_execution_dependencies`、`pipeline_execution_inputs.upstream_dataset_id` 或报告引用。
4. 没有被用户固定。
5. 文件 hash、重建信息和 DB 记录已经保存。

标准清理后：

- 物理文件可删除或移动到 `trash/`。
- `study_outputs.retention_status` 改为 `deleted`。
- 写入 `audit_events`。
- Execution 记录、输入快照、参数、错误、输出摘要都保留。

当前 MVP 的 `study_output_cleanup` 先做保守逻辑清理：只把可清理 StudyOutput 标记为 `deleted` 并写入 `deleted_at/deleted_by`，不物理删除文件。物理删除或移动到 `trash/` 需要后续再打开。

## 2. 不同文件的生命周期

本表是**跨 Dataset / Study 的文件级总览**，4-30 不涵盖（4-30 只讲 Study 内的 StudyOutput）：

| 文件类型 | 生命周期 |
|---|---|
| `sourcedata/original_uploads` | 永久保留，作为上传证据 |
| `raw_bids` | 权威原始数据入口，原则上不清理 |
| `raw_bids` 视图中的硬链接 | 可删除视图链接，但不能删除底层原始对象，且必须能重建视图 |
| `canonical_fif` | 可重建缓存，可按策略清理 |
| `execution_manifest.json` | 永久保留 |
| `study_outputs.current/pinned` | 不清理 |
| `study_outputs.cached/temporary` | 可按策略清理（cached 默认 7 天过期） |
| `deleted` | 只表示文件不可用，记录不删 |
| `quarantined` | 合规隔离，普通用户不可读 |

## 3. 依赖检查

删除或清理 StudyOutput 前必须检查：

| 依赖来源 | 检查字段 |
|---|---|
| 下游 Execution 输入 | `pipeline_execution_inputs.upstream_dataset_id` |
| Execution 依赖 | `pipeline_execution_dependencies.upstream_dataset_id` / `depends_on_execution_id` |
| 当前结果 | StudyOutput `retention_status='current'`（无专用 current 指针列） |
| 用户固定 | StudyOutput `retention_status='pinned'` |
| 报告引用（规划） | 报告索引中的 `study_output_id`（报告索引表当前不存在，未实现） |

被依赖的文件不能直接物理删除，只能固定、归档、隐藏或在可重算时标记为 `deleted` 并保留重建信息。

## 4. 缓存清理顺序

缓存清理不应该按目录盲删，应按数据库策略扫描。

建议排序：

1. 失败 Execution 的临时文件。
2. 长时间未访问的 `temporary`。
3. 可重算且未被依赖的 `cached`。
4. 超出 Study 配额的旧缓存。
5. 可从 Raw BIDS 重建的 canonical FIF。

不要清理：

- `current`。
- `pinned`。
- 被下游 Execution 使用的 StudyOutput。
- 被报告引用的 StudyOutput。
- 有伦理隔离标记但需要保留证据的文件。
- `sourcedata/original_uploads` 和 Raw BIDS 权威文件。

## 5. 存储路径与命名

| 位置 | 用途 |
|---|---|
| `${STUDIES_STORAGE_ROOT}/{study_id}` | Study 工作输出根（`executions/`、`derived/` 等） |
| `${STUDIES_DIR}/{study_id}` | legacy 数据根（`studies.data_root`，仍创建以兼容旧 URI） |
| `sourcedata/original_uploads/` | 用户原始上传文件 |
| `derivatives/elys-canonical-fif/` | canonical FIF 物理位置 |
| `studies/{study_id}/outputs/{sha256[:2]}/{sha256}/...` | Pipeline Execution 派生输出（内容寻址，不按 execution_id 分目录） |
| `study_outputs.storage_uri` | 结果物理位置事实源（`elys://studies/...`）|
| `sha256` | 文件校验值字段 |

## 6. 当前存储能力

- 新上传写入标准 Dataset Version 目录。
- Raw BIDS 当前是**纯数据库逻辑路径**（`storage_uri` 指原始上传），硬链接 / reflink / 对象引用避免复制大文件为规划（见 [4-60](4-60-raw_bids视图与零复制策略.md)）。
- canonical FIF 写入 `derivatives/elys-canonical-fif`,记录 provenance。
- 新写入统一走 `dataset_files` / `study_outputs`。
- `StorageService.resolve_uri` 接受 `study://`（legacy，→ `data_root`）、`elys://datasets`、`elys://studies`（→ `STUDIES_STORAGE_ROOT`）；生成端产出的 `study://` 由 legacy 分支解析（见 [4-10](4-10-存储原则与后端选择.md)）。
- content-addressed 存储避免新输出重复写大文件。

> 调试期**不写迁移、不做 backfill 工具**（无 `file_backfill.py`）：升级走 DROP + 重建，不把旧物理目录从 `${STUDIES_DIR}` 搬到 `${ELYS_STORAGE_ROOT}`。新写入直接进新目录。

## 7. MinIO / 对象存储迁移（未来规划）

迁移到 MinIO/S3 时,业务层不应感知路径变化:

| 层 | 变化 |
|---|---|
| 数据库 | `storage_uri` 从 `elys://` 映射到 `s3://bucket/key` |
| API | 下载、预览、读取仍通过后端服务 |
| Worker | 使用统一 StorageService 读写文件 |
| 前端 | 不感知 MinIO,只拿 `dataset_file_id` / `study_output_id` |

不要在前端暴露永久对象存储地址;需要下载时由 API 生成短期 URL 或直接流式返回。
