## 1. 一个节点在代码里涉及哪些层

在 ELYS 里，**新增一个节点 ≈ 填一份 JSON 规格 + 写一个 dispatcher 分支 + 写一个 engine 算法函数**；其余基础设施（缓存 / 血缘 / 存盘 / 校验）是所有节点共用的，新增节点通常不用碰。

> 名词铺垫：**NodeSpec**＝节点的 JSON 规格（声明端口、参数、后端绑定）；**dispatcher**＝派发器，按节点类型把"读输入 → 调算法 → 存盘 → 产出 data_info"串起来；**engine**＝纯 MNE 计算函数，不碰数据库；**data_info**＝节点之间传递的轻量字典（记 .fif 文件路径 + 元数据），节点不直接传 MNE 对象，而是上游存盘、下游再加载。

| # | 层 | 文件 | 新增节点是否要动 |
|---|---|---|---|
| 1 | NodeSpec 规格 | `app/pipeline/nodes/xxx.json` | **必写**：端口、参数表单、后端绑定、缓存、存盘策略、UI |
| 2 | 注册表 | `app/pipeline/registry.py` | 不动（启动时自动扫 `nodes/*.json` 并校验必填字段、`phase`） |
| 3 | 派发器 | `app/pipeline/dispatcher.py` | **必写**：`_handlers` 注册 `node_type → _execute_xxx` + 写 handler |
| 4 | 算法 engine | `app/engine/{preprocess,ica,analysis}/*.py` | **必写**：`run_xxx(obj, params) → 新对象` |
| 5 | IO 读写摘要 | `app/engine/io.py` | 复用（`read_*_from_data_info` / `save_*_fif` / `summarize_*`）；产出新数据类型时加一对读写 + 摘要 |
| 6 | 存盘 / 标签 / 保留 | `app/pipeline/save_settings.py` | 复用：读 NodeSpec 的 `save` 块算出 `display_name / tags / retention_status` |
| 7 | 结果登记 | `app/pipeline/study_output_store.py` | 复用：落盘 + 写 `study_outputs` 表 |
| 8 | 缓存 / 哈希 | `app/pipeline/cache.py` · `hash.py` | 复用：按 `node_hash`（参数 + 输入 + spec）做内容级缓存 |
| 9 | 校验 | `app/pipeline/validator.py` | 复用：端口类型兼容、必填参数、环检测、游离节点 warning |
| 10 | 血缘 / manifest / 预览 | `app/services/execution_dependencies.py` · `app/pipeline/execution_manifest.py` · `previews.py` | 复用 |
| — | 前端 | `frontend/elys-web` 的 `PipelinePage.vue` · `api/pipelines.ts` | 节点库 / 检视器靠 `GET /pipeline/node-specs` 自动渲染；**纯新增节点一般不改前端**，只有引入新参数类型才加表单控件 |

NodeSpec 字段骨架（以 `elys_project/backend/app/pipeline/nodes/eeg_filter_apply.json` 为最新模板，演示 `visible_when` / `advanced` 两个原语）：

```jsonc
{
  "schema_version": "3.0",                  // 引入 visible_when / advanced
  "type": "eeg/filter/apply",               // 命名空间类型，必须带 "/"
  "category": "preprocessing",              // UI 分组
  "phase": "phase1",                        // 分期 phase1/2/3，决定上线批次
  "inputs":  [{ "name":"input",  "type":"eeg_data", "cardinality":"one_or_many" }],
  "outputs": [{ "name":"output", "type":"eeg_data", "cardinality":"same_as_input" }],
  "properties": [
    { "name":"filter_type", "type":"select", "options":[/* 带通/高通/低通/陷波 */] },
    { "name":"l_freq", "type":"number", "required":true,
      "visible_when":{ "filter_type":["bandpass","highpass"] } },   // 条件显示：选对类型才出现
    { "name":"method", "type":"select", "advanced":true },          // 折进「高级设置」
    { "name":"order",  "type":"integer", "advanced":true,
      "visible_when":{ "method":["iir"] } }
  ],
  "backend": { "module":"app.engine.preprocess.filters", "function":"run_filter" },
  "save":  { "data_type":"filtered_raw", "auto_tags":["step:filter"], "step_label":"filter" },
  "cache": { "enabled":true, "strategy":"content_hash" },
  "ui":    { "color":"#00A5A8", "preview_type":"time_series" }
}
```

> **两个原语（2026-06-05 落地）**：`visible_when`={控制字段:[允许值]} 让参数按其它参数取值条件显隐；`advanced`=true 把工程参数折进「高级设置」。validator 的必填校验改为"可见才必填"，前端 `PipelinePage.vue` 按可见性渲染。这俩是所有节点通用的 UI 基建，不只滤波。

## 3. 已实现节点清单（13 个，全部已接执行器）

全部在 `dispatcher.py` 注册了真实 handler，engine 为真实 MNE 实现。已能跑通完整链：
`LoadData → 通道定位 → 滤波 → 重采样 → 重参考 → 坏道处理 → Compute ICA → Apply ICA(人工剔除) → Epoch → Baseline → Reject Trials → ERP / TFR / PSD`。

| 类别 | 节点 type | 标题 | engine 函数 | 输入 → 输出端口 | 关键参数 |
|---|---|---|---|---|---|
| data | `eeg/data/load` | LoadData | `load_data.resolve_load_data_selection` | (无) → `eeg_data` | selection_mode / dataset_filter / dataset_ids |
| preprocessing | `eeg/filter/apply` | Filter | `preprocess.filters.run_filter` | `eeg_data` → `eeg_data` | filter_type / l_freq / h_freq / notch_freq / method / phase / order（带通·高通·低通·陷波合一） |
| preprocessing | `eeg/preproc/resample` | Resample | `preprocess.resample.run_resample` | `eeg_data` → `eeg_data` | sfreq |
| preprocessing | `eeg/preproc/rereference` | Re-reference | `preprocess.reference.run_rereference` | `eeg_data` → `eeg_data` | ref_channels |
| preprocessing | `eeg/preproc/channel_location` | Ch Loc Assign | `preprocess.channel_location.run_channel_location` | `eeg_data` → `eeg_data` | montage / rename / on_missing |
| preprocessing | `eeg/preproc/bad_channels` | Bad Channels | `preprocess.bad_channels.run_bad_channels` | `eeg_data` → `eeg_data` | action（插值 / 仅标记）/ method（lof / ransac）/ threshold / n_neighbors / corr_thresh（LOF 或 RANSAC 检测 + 球面样条插值） |
| ica | `eeg/ica/compute` | Compute ICA | `ica.compute.run_compute_ica` | `eeg_data` → `eeg_data` + `ica_matrix` | n_components / method |
| ica | `eeg/ica/apply` | Apply ICA | `ica.apply.run_apply_ica` | `eeg_data` + `ica_matrix` → `eeg_data` | excluded_components（**交互式**，可暂停等人工审核） |
| epoch | `eeg/epoch/segment` | Epoch | `analysis.epoching.run_epoch_segment` | `eeg_data` → `epochs` | tmin / tmax / event / split_by |
| epoch | `eeg/epoch/baseline` | Baseline | `analysis.baseline.run_baseline` | `epochs` → `epochs` | baseline 窗（独立基线校正节点） |
| epoch | `eeg/epoch/reject` | Reject Trials | `analysis.reject.run_reject_trials` | `epochs` → `epochs` | method（threshold 峰峰值/平坦 · autoreject）/ reject_peak_to_peak / flat / n_interpolate（自动剔坏试次，剔除溯源进 preview） |
| analysis | `eeg/analysis/erp` | ERP Average | `analysis.erp.run_erp_average` | `epochs` → `evoked` | condition（按条件平均，多条件展开成多产物） |
| analysis | `eeg/analysis/tfr` | TFR | `analysis.tfr.run_tfr` | `epochs` → `tfr` | freqs / n_cycles / condition / baseline_mode（Morlet 小波时频） |
| analysis | `eeg/analysis/psd` | PSD | `analysis.psd.run_psd` | `epochs` / `eeg_data`（入口端口 `spectral_source`）→ `psd` | fmin / fmax / method / condition（condition 仅 Epochs 需要；连续数据整段算一条谱。Welch / multitaper） |

两个值得注意的高级能力（说明引擎已不是占位）：

- **Apply ICA 的人机交互**：执行到这一步返回 `waiting_user_input`，把成分预览推给前端等人工勾选，确认后 resume（`dispatcher.py` 的 `_execute_ica_apply`）。这是目前唯一的"暂停—续跑"节点。
- **Epoch / ERP 的按条件拆分**（`split_by` / `always_per_condition`）：一进可以 N 出，每个 condition 单独存一份结果。

## 4. 补全规划（应该写哪些节点）

把"已声明但无产出的端口类型" + [8-00 模块地图](8-00-功能模块总览.md) M2–M12 + MNE 常用步骤对齐，按"先补闭环、再补广度"排批次。`phase` 字段可直接用来标上线批次（B/C 标 `phase2`、高级分析标 `phase3`）。

### 批次 A · 预处理与质控闭环（M2 + M4，性价比最高）

与现有节点同属 Raw→Raw，复用度极高，每个基本就是"一份 JSON + 一个 engine 函数 + 一个 dispatcher 分支"：

| 建议节点 type | 作用 | 端口 | 难度 |
|---|---|---|---|
| ~~`eeg/filter/fir` `/butterworth` `/notch`~~ → 合一为 `eeg/filter/apply` | 带通/高通/低通 + 工频陷波（FIR/IIR/谱拟合） | `eeg_data`→`eeg_data` | <span class="elys-badge elys-badge--done">已实现（2026-06-05，含 visible_when/advanced 原语）</span> |
| `eeg/preproc/crop` | 按时间裁剪 | `eeg_data`→`eeg_data` | 低 |
| ~~`eeg/preproc/montage`~~ → `eeg/preproc/channel_location` | 设置电极坐标（montage） | `eeg_data`→`eeg_data` | <span class="elys-badge elys-badge--done">已实现（2026-06-15，Ch Loc Assign）</span> |
| ~~`eeg/qc/bad_channels`~~ → `eeg/preproc/bad_channels` | 坏道检测（LOF / RANSAC）/ 插值（球面样条），归入预处理 | `eeg_data`→`eeg_data` | <span class="elys-badge elys-badge--done">已实现（2026-06-15，RANSAC 06-16 补）</span> |
| ~~`eeg/qc/autoreject`~~ → `eeg/epoch/reject` | 自动剔除坏 epoch（峰峰值/平坦阈值 + AutoReject 二合一） | `epochs`→`epochs` | <span class="elys-badge elys-badge--done">已实现（2026-06-16，Reject Trials，一节点两算法）</span> |
| `eeg/output/save_result` | 导出 / 固化结果（曾在文档承诺、代码缺失，建议补） | `analysis_result`→(无) | 低 |

### 批次 B · 时频分析（M5，激活 `psd` / `tfr` 端口）

| 节点 type | 作用 | 端口 |
|---|---|---|
| `eeg/analysis/psd` | 功率谱（Welch / multitaper） | `epochs` / `eeg_data` → `psd` |
| `eeg/analysis/tfr` | 时频（Morlet / multitaper） | `epochs` → `tfr` |
