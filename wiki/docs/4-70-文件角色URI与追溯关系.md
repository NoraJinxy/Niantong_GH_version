## 1. 数据库是平台事实源

文件旁边的 JSON 是为了导出和离线复现；平台内的事实源应是数据库。

| 事实 | 数据库位置 |
|---|---|
| 文件属于哪个 Dataset/Study | `dataset_files` / `derived_datasets` |
| 文件角色 | `file_role` / `data_type` |
| 逻辑路径 | `logical_path`，`relative_path` 保留旧兼容 |
| 真实读取位置 | `storage_uri` |
| 内容校验 | `sha256` |
| 转换来源 | `produced_by_params` / `dataset_file_derivations` |
| Execution 输入 | `pipeline_execution_inputs` |
| Execution 输出 | `derived_datasets` |

## 2. Dataset 文件角色

建议标准化 `dataset_files.file_role`：

| file_role | 含义 |
|---|---|
| `original_upload` | 用户上传原始文件 |
| `original_manifest` | 上传批次 manifest |
| `raw_bids_data` | Raw BIDS 主数据，如 EDF/BDF/VHDR/SET |
| `raw_bids_eeg_json` | Raw BIDS `*_eeg.json` |
| `raw_bids_channels` | Raw BIDS `*_channels.tsv` |
| `raw_bids_events` | Raw BIDS `*_events.tsv` |
| `raw_bids_electrodes` | Raw BIDS `*_electrodes.tsv` |
| `raw_bids_coordsystem` | Raw BIDS `*_coordsystem.json` |
| `canonical_fif` | MNE-ready canonical FIF |
| `canonical_fif_provenance` | canonical FIF 旁边的轻量 JSON |
| `qc_report` | 导入或基础 QC 报告 |
| `event_summary` | marker/event 摘要 |
| `channel_summary` | 通道摘要 |

当前代码保留 `raw_source`、`sidecar` 等兼容角色，同时已写入 `original_upload`、`raw_bids_data`、`raw_bids_eeg_json`、`raw_bids_channels`、`raw_bids_events`、`canonical_fif`、`canonical_fif_provenance` 等标准角色。

## 3. DerivedDataset 文件角色

建议标准化 `derived_datasets.file_role`：

| 角色 | 含义 |
|---|---|
| `clean_raw` | 清洗后的连续数据 |
| `epochs` | epoch 数据 |
| `ica_solution` | ICA 模型或分量信息 |
| `evoked` | ERP/evoked 结果 |
| `spectrum` | PSD/TFR 等频域结果 |
| `table` | 统计表、特征表 |
| `figure` | 图片 |
| `report` | HTML/PDF/Markdown 报告 |
| `cache` | 可重算缓存 |

DerivedDataset 是否可清理不由角色单独决定，而由 `retention_status`、依赖关系和报告引用共同决定。

## 4. URI 规则

建议业务层统一使用逻辑 URI：

```text
elys://datasets/ds-000001/versions/v0001/raw_bids/sub-001/ses-01/eeg/...
elys://studies/202605000001/derived/ab/abcdef...
```

StorageService 负责把它映射成：

```text
file:///mnt/elys_data/storage/datasets/...
s3://elys-storage/datasets/...
```

legacy scheme：`resolve_uri` 实际解析的 legacy 前缀是 `project://`；历史写入端还存在 `study://{study_id}/...` 形态，但解析端**未覆盖** `study://`（见 [4-10](4-10-存储原则与后端选择.md) 已知不一致）。

```text
project://202605000001/fifdata/sub-001/...
```

前端不接触 `file://`、`s3://` 或服务器绝对路径，只拿 `dataset_file_id` / `derived_dataset_id`。

## 5. canonical FIF provenance

canonical FIF 的轻量 JSON 可以由数据库自动生成：

```json
{
  "Description": "Canonical FIF generated from Raw BIDS for MNE processing.",
  "SourceRawBIDS": "raw_bids/sub-001/ses-01/eeg/sub-001_ses-01_task-rest_run-01_eeg.vhdr",
  "SourceChannels": "raw_bids/sub-001/ses-01/eeg/sub-001_ses-01_task-rest_run-01_channels.tsv",
  "SourceEvents": "raw_bids/sub-001/ses-01/eeg/sub-001_ses-01_task-rest_run-01_events.tsv",
  "GeneratedBy": {
    "Name": "ELYS canonical FIF converter",
    "Version": "1.0.0"
  },
  "GeneratedAt": "2026-05-21 17:59:13 +08:00"
}
```

数据库对应关系：

| JSON 字段 | 数据库位置 |
|---|---|
| `SourceRawBIDS` | `dataset_files.file_role='raw_bids_data'` |
| `SourceEvents` | `dataset_files.file_role='raw_bids_events'` |
| `SourceChannels` | `dataset_files.file_role='raw_bids_channels'` |
| `CanonicalFIF` | `dataset_files.file_role='canonical_fif'` |
| `GeneratedBy` | `dataset_files.metadata_json` |
| `GeneratedAt` | `dataset_files.created_at` |
| `SourceSHA256` | source 文件的 `sha256` |
| `ConversionParams` | `metadata_json` |

## 6. 派生关系表

当前已新增 `dataset_file_derivations`，用于记录 Raw BIDS、sidecar、canonical FIF 和 provenance 之间的来源关系。标准字段可继续演进为：

```text
dataset_file_derivations
  id
  study_id
  source_file_id
  derived_file_id
  execution_id
  derived_dataset_id
  derivation_kind
  transform_name
  transform_version
  parameters_json
  metadata_json
  created_at
```

示例关系：

```text
canonical_fif generated_from raw_bids_data
canonical_fif metadata_from raw_bids_events
canonical_fif metadata_from raw_bids_channels
canonical_fif metadata_from raw_bids_eeg_json
```

这样 canonical FIF 删除后也能知道如何重建。

## 7. Execution 输入与输出追溯

Execution 创建时冻结输入：

```text
pipeline_execution_inputs
  execution_id
  dataset_asset_id
  recording_id
  recording_version_id
  dataset_file_id
  file_role
  storage_uri
  sha256
  selector_json
  resolved_metadata_json
```

Execution 完成后登记输出：

```text
derived_datasets
  produced_by_execution_id
  produced_by_job_id
  produced_by_node_type
  data_type
  upstream_dataset_ids
  upstream_recording_ids
  storage_uri
  sha256
  retention_status
  display_name
  tags
```

历史 Execution 不依赖“当前数据”，只依赖它自己的输入快照。
