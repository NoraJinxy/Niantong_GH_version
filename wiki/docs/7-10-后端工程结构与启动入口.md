## 1. 目录结构

```text
backend/app/
  main.py                 FastAPI app、CORS、路由注册、health
  config.py               pydantic-settings 配置
  database.py             SQLAlchemy engine、SessionLocal、get_db
  routers/                HTTP 路由
  schemas/                Pydantic 请求/响应模型
  services/               共享业务服务
  models/                 SQLAlchemy ORM 模型
  pipeline/               工作流执行框架
  engine/                 EEG 算法实现
  tasks/                  Celery 应用与任务
  utils/                  JWT、密码等工具
```

## 2. 启动入口

`main.py` 当前负责：

| 步骤 | 说明 |
|---|---|
| 读取配置 | `settings = get_settings()` |
| 设置 JSON 响应 | `CustomJSONResponse` 支持 UUID 序列化和中文 |
| 创建应用 | `FastAPI(title, version, description)` |
| 注册 CORS | 从 `CORS_ORIGINS` 读取允许来源 |
| 注册路由 | `auth_router`、`dashboard_router`、`studies_router`、`dataset_assets_router`、`dataset_files_router`、`recording_router`、`datasets_router`、`dataset_versions_router`、`dataset_withdrawals_router`、`pipelines_router` |
| 异常处理 | 422 校验错误中文化、RecursionError 与未捕获异常的兜底响应 |
| 健康检查 | `GET /api/v1/health` |

启动链路：

```mermaid
flowchart LR
  Config[config.py] --> Main[main.py]
  Main --> CORS[CORS]
  Main --> Routers[include_router]
  Main --> Handlers[exception_handlers]
  Main --> Health[/api/v1/health]
```

应用启动不再执行任何 schema 变更；数据库初始化由部署脚本完成（见下文 §6）。

## 3. 配置项

`config.py` 使用 `BaseSettings`，支持 `.env` 覆盖。

| 配置 | 用途 |
|---|---|
| `APP_NAME` / `VERSION` / `DEBUG` | 应用信息 |
| `DB_HOST` / `DB_PORT` / `DB_NAME` / `DB_USER` / `DB_PASSWORD` | PostgreSQL 连接 |
| `REDIS_HOST` / `REDIS_PORT` / `REDIS_DB` / `REDIS_PASSWORD` | Redis 连接 |
| `CELERY_BROKER_URL` / `CELERY_RESULT_BACKEND` | Celery broker/backend，可覆盖 Redis 默认拼接 |
| `CELERY_WORKFLOW_QUEUE` | 工作流队列，当前默认 `workflow.default` |
| `PIPELINE_EXECUTION_MODE` | `auto`（默认）/ `celery` / `inline`——决定 Execution 走 Celery 异步还是 API 进程内联同步，详见 [7-40](7-40-工作流执行与后台任务.md) |
| `CELERY_WORKER_PING_TIMEOUT_SECONDS` | `auto` 模式下探测 worker 可用性的超时，默认 `0.5` |
| `STUDIES_DIR` | legacy Study 数据根（`studies.data_root` 基目录），默认 `/mnt/elys_data/studies` |
| `ELYS_STORAGE_ROOT` | 新存储根，默认 `/mnt/elys_data/storage` |
| `DATASETS_STORAGE_ROOT` / `STUDIES_STORAGE_ROOT` / `TRASH_STORAGE_ROOT` | Dataset / Study 工作输出 / 回收站存储根（`storage/datasets`、`storage/studies`、`storage/trash`） |
| `CORS_ORIGINS` | 前端和数据域名白名单 |
| `SECRET_KEY` / `ALGORITHM` / `ACCESS_TOKEN_EXPIRE_MINUTES` | JWT 配置 |

## 4. 数据库连接

`database.py` 当前负责：

| 对象 | 说明 |
|---|---|
| `DATABASE_URL` | 由配置拼接 PostgreSQL URL |
| `engine` | SQLAlchemy engine，启用 `pool_pre_ping=True` |
| `SessionLocal` | 请求级 Session 工厂 |
| `Base` | ORM declarative base |
| `get_db()` | FastAPI dependency，yield 后关闭 Session |

路由中统一通过 `db: Session = Depends(get_db)` 获取数据库会话。

## 5. 路由注册

`routers/__init__.py` 当前导出以下 router：

| Router | Prefix | 说明 |
|---|---|---|
| `auth_router` | `/api/v1/auth` | 登录、刷新、当前用户 |
| `dashboard_router` | `/api/v1/dashboard` | 首页聚合摘要 |
| `studies_router` | `/api/v1/studies` | Study 与成员管理 |
| `dataset_assets_router` | `/api/v1/dataset-assets` | 平台级 Dataset 资产 |
| `dataset_files_router` | `/api/v1/dataset-files` | Dataset 文件 metadata、preview、download |
| `recording_router` | `/api/v1/studies/{study_id}/recordings` | 只读采集记录视图 |
| `datasets_router` | `/api/v1/studies/{study_id}/datasets` | Study 内 Dataset 挂载与导入 |
| `dataset_versions_router` | `/api/v1/dataset-versions` | Dataset 发版与撤回 |
| `dataset_withdrawals_router` | `/api/v1/dataset-withdrawals` | 撤回审核与紧急下架 |
| `pipelines_router` | `/api/v1` | NodeSpec、Pipeline、Execution、Job、StudyOutput、Task |

`main.py` 只负责 include，不在入口文件里写业务路由。

## 6. 数据库初始化与升级

**事实源**：schema 单一事实源在 `elys_project/database/schema/`，按业务模块拆为 6 个 SQL 文件：

| 文件 | 内容 |
|---|---|
| `01_auth.sql` | 用户、角色、token |
| `02_studies.sql` | Study、成员、锁、审计 |
| `03_datasets.sql` | Dataset asset / version / mount / recording |
| `04_pipelines.sql` | Pipeline、PipelineExecution、PipelineJob、execution 输入与依赖 |
| `05_outputs.sql` | StudyOutput |
| `06_async.sql` | async_tasks 与 task_events |

`database/init.sql` 是组合入口，按顺序加载上述 6 个文件。

**升级方式**：当前为调试期，schema 升级直接走 **DROP DATABASE + 重建**，由部署脚本 `deploy_remote.cmd` 处理。后端启动**不执行**任何 schema 变更——既不建表也不打补丁；启动期只依赖 SQLAlchemy 元数据访问已存在的库。

未来进入正式环境后再评估是否引入版本化迁移工具。

## 7. 代码文件头约定

后端 Python 文件统一在最顶部写模块 docstring，用两行说明职责和关联：

```python
"""
Purpose: Define FastAPI routes for the pipeline API area and translate HTTP requests into services/database calls.
Related: app/schemas/*, app/models/*, app/services/*, app/routers/auth.py, wiki/docs/2-50.
"""
```

约定：

- `Purpose` 写这个文件负责什么，不写函数级细节。
- `Related` 写最关键的相邻模块、数据库/部署脚本或 `wiki/docs` 页面。
- `from __future__`、imports、业务代码都放在文件头之后。
- `database/*.sql`、`deploy/*.sh`、`deploy/*.ps1`、`deploy/profiles/*.env` 使用对应语言的注释头。
