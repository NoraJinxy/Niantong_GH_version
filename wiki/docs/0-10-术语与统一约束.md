## 3. Study ID

产品语义上称为 **Study ID / 研究项 ID**。它是 12 位数字主键，同时也是研究项数据目录名。

```text
YYYYMM + NNNNNN
202605   000001
```

`YYYYMM` 表示研究项创建年月，`NNNNNN` 是当月递增序号。后端通过 `next_study_id()` 函数和 `study_id_counters` 表生成。`study.code` 只用于 UI 展示和搜索，不参与文件路径生成。

## 5. BIDS 实体命名

| 实体 | 前缀 | 示例 | 出现位置 |
|---|---|---|---|
| subject | `sub-` | `sub-093` | `subjects.bids_subject_id` |
| session | `ses-` | `ses-01`，可空 | `datasets.session` |
| task | `task-` | `task-rest` | `datasets.task`，必填 |
| run | `run-` | `run-02`，可空 | `datasets.run` |

后端会规范化 BIDS label。BIDS 文件名保持 ASCII；说明性中文正文不受这个限制。

## 6. 命名与排版

- 中文正文使用自然中文标点。
- 代码、API、路径、JSON、SQL、命令和数据库字段保留原始写法。
- 代码路径写相对 `elys_project/` 的路径，不做 Markdown 链接。
- 同一事实只在少数权威页维护，其它页面引用。
- 页面优先使用短段落、表格、清单和明确验收条件，方便人读，也方便大模型继续接手。

## 7. 平台边界

- 当前只讨论 EEG 数据。
- 不做 SSO、ORCID 或机构统一身份。
- 用户上传的 `.fif` 当前不作为原始数据接收，FIF 由平台导入流程生成。
- 不做通用统计软件的完整替代，只内置 EEG 常用方法。
