## 上手第一步：先搞清项目当前进展

不管用 Claude Code、Codex 还是 Trae，**接手任何 ELYS 任务前先花两分钟扫一遍进展**，顺序固定：

1. [9-00 更新日志（周报总览）](9-00-更新日志.md)——按周给出最近的标题级变更，一眼看清“最近在改什么”。
2. 最近的月度页（如 [9-02 2026 年 6 月](9-02-2026年6月.md)）——看本月每条改动的“为什么 / 影响哪些页面”。
3. [首页 index](index.md)——主线流程图和模块状态，掌握整体盘子。

项目根的 `AGENTS.md`（Codex / Trae 通用）和 `CLAUDE.md`（Claude Code 自动读）已经把这套顺序写进去，新会话一般会自动读到。需要手动兜底时，下面这段开场白可以直接复制给任何大模型：

```text
先读 wiki/docs/9-00-更新日志.md（周报总览）和最近的月度页 wiki/docs/9-0x，
再读 wiki/docs/index.md，搞清楚 ELYS 最近的进展和当前主线，然后再开始我接下来交代的任务。
事实源优先级：P0 当前代码（elys_project/）> P1 wiki/docs/，两者冲突时以代码为准。
```

## 1. 给 LLM 的最小上下文包

| 字段 | 示例 |
|---|---|
| 任务 | 给某个 wiki 页加一节 / 修一处事实 |
| 必读 wiki | `0-00` · `0-10` · 当前任务相关总览页 |
| 代码范围 | `wiki/docs/` · `wiki/mkdocs.yml` |
| 不要改 | 与任务无关的业务代码 |
| 事实源优先级 | **P0 当前代码 (`elys_project/`) · P1 `wiki/docs/`**（冲突时以 P0 为准） |
| 验收 | 页面存在、nav 可访问、`mkdocs build` 成功 |

任务越具体，越容易得到可验证的结果。不要只说"帮我完善一下"，而应说明要改哪些页面、参考什么、怎样验收。

## 2. 推荐引用格式

讨论、issue、commit 和 prompt 中优先使用“页面编号 + 小节名”，不要复制大段正文。

```text
目标: 补充 5-30 Execution 执行项管理的异步任务规划
相关: 0-10 状态语义, 3-40 pipeline_executions, 4-30 Artifact, 5-30 当前运行链路
约束: 规划能力不能写成已实现
验收: mkdocs build 成功, nav 可访问
```

## 3. LLM 写文档原则

- 先看当前代码（`elys_project/`），再看 `wiki/docs/`。代码与文档冲突时以代码为准。
- 只有当前代码真实具备的能力，才能写成 <span class="elys-badge elys-badge--done">已实现</span>。
- 规划能力必须标为 <span class="elys-badge elys-badge--planned">规划</span>，并列出前置条件。
- 每改一页，都按 [0-20 文档编写规范](0-20-文档编写规范.md) 保持结构。

## 4. 判断输出是否可信

| 检查项 | 验证方式 |
|---|---|
| 路径是否真实 | 查看 `elys_project/<path>` 或 `wiki/docs/<path>` 是否存在 |
| 接口是否存在 | 检查后端 router |
| 数据库字段是否存在 | 检查 `database/init.sql` 或 SQLAlchemy 模型 |
| 状态是否准确 | 对照代码能力与页面描述 |
| nav 是否同步 | 检查 `wiki/mkdocs.yml` 并运行 `mkdocs build` |

如果大模型声称某能力“已实现”，但路径、字段或接口无法找到，应以当前代码为准，改为“规划”或“部分接入”。

## 5. 写回 wiki 的要求

- 最终页面要人工审一遍，确认状态徽章、代码路径和页面链接。
- 长段总结压缩成短段落、表格、清单和验收条件。
- 改了规则页、总表或模块边界，要同步记录到 [9-00 更新日志](9-00-更新日志.md)。
- 改完 nav 或新增页面后，运行 `mkdocs build --clean`。

## 6. 常见反模式

| 不够清楚的说法 | 更好的说法 |
|---|---|
| "帮我完善文档" | "在 `wiki/docs/7-20` 第 8 节加一段 LLM 安全护栏，并在 9-00 记一条变更。" |
| "看一下当前实现" | "在 `elys_project/backend/app/routers/datasets.py` 找 `bootstrap` 端点，对照 wiki 2-50 第 4.1 节，不一致的以代码为准。" |
| "把功能都写上" | "只写当前代码可核验的已实现能力，其余标为规划。" |
