## 1. 生产服务器落盘位置

生产环境把应用代码和数据盘分开：

```text
/opt/elys/
  app/                 # 代码、虚拟环境、前端构建、部署脚本

/mnt/elys_data/
  storage/             # 目标标准数据根
  studies/            # 当前代码兼容根，STUDIES_DIR 指向这里
  backups/             # 数据库备份、索引导出、关键配置备份
  logs/                # 可选应用日志；systemd/journald 仍是首选
```

当前后端配置项是：

```env
STUDIES_DIR=/mnt/elys_data/studies
```

创建 Study/Study 时，数据库字段 `studies.data_root` 会写成：

```text
/mnt/elys_data/studies/{study_id}
```

短期继续兼容 `studies/{study_id}`；新标准逐步引入 `storage/datasets` 与 `storage/studies`。

## 2. 存储原则

| 原则 | 说明 |
|---|---|
| 路径不暴露给用户 | 上传、下载、预览和清理都走 API 鉴权 |
| 逻辑路径和物理对象分离 | `raw_bids` 可以是标准视图（当前为纯数据库逻辑视图，`storage_uri` 指原始上传）；硬链接 / reflink / 对象引用为规划 |
| 数据库解释文件 | 文件角色、逻辑路径、物理 URI、版本、hash、状态、依赖关系都在数据库 |
| 原始上传只追加 | `sourcedata/original_uploads` 永不覆盖，重传生成新版本 |
| canonical FIF 属于 Dataset derivative | 它是 MNE-ready 工作副本，不是 Raw BIDS 权威源 |
| Execution 输出属于 Study | clean raw、epochs、ERP、报告等先作为研究项内输出 |
| 大文件可清理 | Execution 记录长期保留，输出文件按策略保留或清理 |

## 3. 存储后端选择

MVP 推荐先用本地文件系统，不必一开始上 MinIO。

| 方案 | 适合阶段 | 优点 | 风险 |
|---|---|---|---|
| 本地文件系统 | MVP、单计算服务器 | 简单、快、调试方便、部署成本低 | 多机器共享、生命周期策略、横向扩展较弱 |
| MinIO / S3 兼容对象存储 | 多计算节点、正式共享平台、大规模归档 | 适合大文件、生命周期策略、对象级权限、跨机器访问 | 运维复杂度更高，调试链路更长 |

标准设计不把后端写死。数据库保存统一的 `storage_uri`：

```text
storage_uri = elys://datasets/ds-000001/versions/v0001/raw_bids/...
storage_uri = elys://studies/202605000001/derived/ab/abcdef...
storage_uri = file:///mnt/elys_data/storage/datasets/...
storage_uri = s3://elys-storage/datasets/...
```

业务层优先使用 `elys://` 逻辑 URI，由 StorageService 映射成本地 `file://` 或对象存储 `s3://`。`StorageService.resolve_uri` 当前接受的 scheme 是 `study://`（legacy，解析到研究项 `data_root` = `STUDIES_DIR/{study_id}`）、`elys://datasets`、`elys://studies`（解析到新根 `STUDIES_STORAGE_ROOT`）（见 `storage.py:58-65`）。写入端（`datasets.py`、`studies.py` 的 `legacy_study_uri`、`cache.py`）产出的 `study://{study_id}/...` 即由 legacy 分支解析到 `data_root`——也就是这些文件实际落盘的位置。

## 4. 当前兼容目录

当前可运行代码会在 `studies.data_root` 下创建：

```text
/mnt/elys_data/studies/{study_id}/
  .elys_study.json
  source_uploads/
  fifdata/
  upload_staging/
  validation/
  bids_exports/
  derivatives/
    preprocessing/
  pipeline/
  pipeline_runs/
```

兼容映射：

| 当前目录 | 标准语义 | 后续迁移 |
|---|---|---|
| `source_uploads/` | `sourcedata/original_uploads/` | 可保留为旧路径，新增写入转向标准路径 |
| `fifdata/` | `derivatives/elys-canonical-fif/` | canonical FIF 不作为 Raw BIDS |
| `pipeline_runs/` | `studies/{study_id}/executions` + `derived` | Execution manifest 与派生数据分离 |
| `bids_exports/` | `exports/` | 导出包目录 |
| `upload_staging/` | `temp/` | 上传临时区，可清理 |

## 5. 标准目标目录

```text
/mnt/elys_data/storage/
  datasets/
    ds-000001/
      dataset_asset.json
      versions/
        v0001/
          dataset_version.json
          sourcedata/
          raw_bids/
          derivatives/
            elys-canonical-fif/
          qc/
  studies/
    202605000001/
      .elys_study.json
      executions/
      derived/
      previews/
      temp/
      exports/
      pipeline_snapshots/
  exports/
  trash/
```

说明（`datasets/` + `studies/` 双根、`executions/`+`derived/` 命名当前都已落地）：

- `datasets/` 存数据资产本身，和具体 Study 解耦。
- `studies/` 存研究项内的执行输出、缓存、日志和预览。
- `executions/{execution_id}/execution_manifest.json` 是可导出的执行证据单。
- `derived/{sha256[:2]}/{sha256}/` 用于内容寻址和去重（DerivedDataset 输出）。
- `temp/` 只存运行中的临时文件，失败或超时后可清理。

## 6. 部署保护规则

生产配置必须避免部署脚本误删数据：

```env
STUDIES_DIR=/mnt/elys_data/studies
KEEP_EXISTING_DATA=true
RESET_DB=false
RESET_STORAGE=false
RESET_DATA_ROOT=false
```

任何“重置数据根”的操作都必须是显式治理动作，不得作为普通部署默认行为。
