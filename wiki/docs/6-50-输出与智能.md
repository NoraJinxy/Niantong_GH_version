## 一、统计分析 `/statistics`（StatisticsPage）

### 1.1 设计定位

统计分析是连接"观察"和"结论"的桥梁。观察页让研究者看到数据，统计页让研究者用规范的方法**检验差异是否显著**。

设计原则：
- **假设驱动**：用户选择统计检验，工具提示设计是否满足假设（正态性、方差齐性），而不是让用户自己去检查。
- **EEG 友好**：提供 Cluster Permutation Test 这类 EEG 特色检验（时空多重比较校正），而不只是通用的 t-test。
- **从数据到报告**：一次分析流程结束后可导出完整统计报告（包含方法描述、结果表、显著性图），满足期刊投稿需求。

### 1.2 规划视图布局

三栏布局：

| 区域 | 内容 |
|---|---|
| 左侧 | 数据选择：按 result_type 浏览 M5/M6/M7/M8 分析产物（长表预览） |
| 中间 | 检验配置：类型选择 + 因子设置 + 多重比较校正 + 假设检查开关 |
| 右侧 | 结果展示：统计结果表 + 显著性图（在原始观察图上叠加 cluster shading） |
| 下方 | 完整统计报告（HTML / PDF 导出） |

### 1.3 主要功能规划

#### 检验类型

| 检验 | 适用场景 |
|---|---|
| 独立样本 t-test / Wilcoxon | 两组比较 |
| 配对 t-test / Wilcoxon | 配对数据（同被试两条件） |
| 单因素 ANOVA / Kruskal-Wallis | 三组及以上 |
| 重复测量 ANOVA | 同被试多条件 |
| Cluster Permutation Test | 时域/频域连续数据（EEG 首选） |
| FDR / Bonferroni 校正 | 多通道多时间点校正 |

#### 假设检查（自动提示）

| 假设 | 检查方法 | 提示行为 |
|---|---|---|
| 正态性 | Shapiro-Wilk | 不满足时提示切非参数 |
| 方差齐性 | Levene 检验 | 不满足时提示改方案 |
| 球形性 | Mauchly 检验 | 重复测量时自动校正（Greenhouse-Geisser）|

#### Cluster Permutation Test

这是 EEG 时域/频域显著性检验的标准方案，解决多重比较问题而不损失敏感性。

- 选定时间轴（或时频轴）的数据矩阵。
- 指定被试分组（独立/配对）。
- 输出：cluster mask（时间点×通道的显著区域）可视化叠加到观察图上。

### 1.4 规划 API

| 接口 | 用途 |
|---|---|
| `POST /stats/test` | 创建统计任务（异步） |
| `GET /stats/{id}` | 查询任务状态和结果 |
| `GET /stats/{id}/report` | 导出 HTML / PDF 报告 |

后端计划使用：`scipy.stats` · `statsmodels` · `pingouin` · `mne.stats`。

## 二、科研作图 `/figures`（FiguresPage）

### 2.1 设计定位

ELYS 的作图模块不是"截图"——截图无法做到期刊级别的矢量图质量，也无法批量更新参数。

设计目标：
- **可复现作图**：图形定义（FigureSpec）是声明式 JSON，存在数据库里，可以任意时间用不同数据重新渲染。
- **期刊级质量**：导出 SVG / EPS（矢量），精确控制字号、线宽、颜色，满足期刊投稿分辨率要求。
- **所见即所得**：画布实时预览，调整参数立刻看到效果。

### 2.2 规划三栏布局

| 区域 | 内容 |
|---|---|
| 左侧 | 数据源浏览（pipeline_executions · results · stats）+ 图表模板库 |
| 中间 | 画布预览（按 FigureSpec 实时渲染，后端 matplotlib 生成 PNG 预览） |
| 右侧 | 面板属性编辑（类型 / 数据 / 样式 / 标注） |
| 顶部 | 期刊预设切换（Nature / eLife / custom）+ 导出按钮 |

### 2.3 主要功能规划

#### 面板类型

| 类型 | 对应数据 |
|---|---|
| ERP 波形图 | M5-10 evoked |
| 头皮拓扑图 | 任意时间点的头皮分布 |
| 频谱图 | M5-20 PSD |
| 时频热图 | M5-30 TFR |
| 连接矩阵 | M7 connectivity |
| 微状态地形 | M6 microstate |
| 统计显著性叠加 | 任意观察图 + cluster mask |
| 箱型图 / 小提琴图 | 统计汇总数据 |

#### FigureSpec 设计

每个图形是一个 JSON 定义：

```json
{
  "panels": [
    {
      "type": "erp",
      "data_source": { "result_id": "...", "conditions": ["A", "B"] },
      "style": { "linewidth": 1.5, "colors": ["#1f77b4", "#ff7f0e"] },
      "annotations": [{ "type": "peak", "time": 0.3, "label": "P300" }]
    }
  ],
  "layout": { "ncols": 2, "size_cm": [18, 12] },
  "journal_preset": "nature"
}
```

FigureSpec 存入数据库，可以随时用不同数据或参数重新渲染，支持批量生成（多被试同一图表类型）。

#### 渲染策略

- **预览**：后端 matplotlib 渲染 PNG（快速，用于画布实时预览）。
- **导出**：SVG（论文用，矢量，完全可编辑）/ EPS / PDF / PNG（多分辨率）。

#### 期刊预设

内置主流期刊格式：字号、线宽、图幅大小、颜色方案符合期刊规范，一键切换。

### 2.4 规划 API

| 接口 | 用途 |
|---|---|
| `GET /studies/{id}/results` | 数据源浏览 |
| `POST /figures` | 保存 FigureSpec |
| `PUT /figures/{id}` | 更新 FigureSpec |
| `POST /figures/{id}/render` | 触发渲染（返回 PNG 预览 URL） |
| `GET /figures/{id}/export` | 导出 SVG / EPS / PDF |

## 三、机器学习工作台 `/ml`（MlPage）

### 3.1 设计定位

EEG 机器学习有几个容易犯的错误（数据泄漏、被试分组不当、嵌套 CV 缺失），导致模型评估过于乐观。ELYS 的 ML 工作台把**防泄漏检查清单**内置到 UI 流程中，而不是让用户自己去查文献。

设计原则：
- **防数据泄漏优先**：数据划分、标准化、特征选择都在 CV 内执行。UI 在关键步骤提示用户检查。
- **可复现训练**：随机种子、模型超参数、数据版本全部记录，训练结果可完整追溯。
- **可解释输出**：不只是给出准确率，还提供 SHAP 值、特征重要性、通道贡献分析。

### 3.2 规划 Tab 流程

流程设计为线性 Tab，引导用户一步步完成：

| Tab | 内容 | 关键检查 |
|---|---|---|
| 1. 数据集构建 | 选 result_id · 配置 target / groups · 导入 label | 被试 ID 是否正确作为分组变量 |
| 2. 特征设置 | 选特征集 · 配置标准化位置 | 标准化必须在 CV 内（防泄漏） |
| 3. 模型选择 | 经典 ML / 深度学习 / AutoML | 给出对当前数据规模的推荐 |
| 4. 验证策略 | LOSO / GroupKFold / nested CV | 验证方式与分析目标匹配 |
| 5. 训练 | 启动 + 实时进度 | 随机种子已设置 |
| 6. 评估 | 性能表 + 混淆矩阵 + ROC + 校准曲线 | 是否展示了置信区间 |
| 7. 解释 | SHAP / 通道贡献 / 重要性排名 | — |
| 8. 报告 | 完整模型卡片导出 | — |

### 3.3 防数据泄漏检查清单

UI 在进入训练前自动检查并展示：

```
□ 是否指定了被试分组变量（groups）？
□ 测试集被试是否与训练集完全隔离（LOSO / GroupKFold）？
□ 特征标准化是否在 CV fold 内执行（非全局）？
□ 是否使用嵌套 CV 进行超参数搜索（防过拟合）？
□ 随机种子是否已锁定（保证复现）？
```

这是 EEG-ML 文献中常见问题的明确化，帮助没有深厚 ML 背景的研究者避免常见陷阱。

### 3.4 规划 API

| 接口 | 用途 |
|---|---|
| `POST /ml/datasets` | 构建 ML 数据集 |
| `POST /ml/train` | 启动训练任务（异步） |
| `GET /ml/runs/{id}` | 查询任务状态和结果 |
| `GET /ml/models/{id}/report` | 导出评估报告（HTML / PDF） |

后端计划使用：`scikit-learn` · `xgboost` · `optuna` · `shap`（未来扩展 `PyTorch`）。

## 四、管理后台 `/admin`（Admin）

### 4.1 设计定位

管理后台是**系统管理员**（`admin` 角色）专用的运维入口。

设计原则：
- **最小必要暴露**：只展示管理操作需要的信息，绝不暴露数据库密码、SECRET_KEY、服务器内部路径。
- **操作必须可追溯**：所有管理操作（改角色、删用户、强制删研究项）都写审计日志。
- **高危操作二次确认**：改角色、永久删除研究项需要输入确认信息，不只是"确定"按钮。

### 4.2 规划 Tab

| Tab | 主要功能 |
|---|---|
| 系统状态 | API / DB / Redis 健康检查；CPU / 磁盘 / 网络监控 |
| 用户管理 | 列表 + 创建/禁用用户 + 重置密码 + 修改系统角色 |
| 角色权限 | 系统角色（admin / pi）配置和权限组合查看 |
| 研究项总览 | 全局研究项列表（跨所有用户）+ 管理员强制删除 |
| 资源档位 | PI / PI Plus / PI Pro 档位配置（存储配额 / 并发 Execution 数） |
| 审计日志 | 登录历史 + 研究项操作 + 权限变更日志（可按时间/用户/操作类型筛选） |
| 存储管理 | 各研究项配额使用情况 + 孤立文件清理 |
| 任务队列 | Celery Worker 状态 + 排队/运行中任务（M3-50 接入后） |

### 4.3 安全边界

| 规则 | 说明 |
|---|---|
| 入口权限 | 仅 `admin` 系统角色可见导航入口和访问 `/admin` |
| 敏感操作确认 | 改角色、删用户需输入密码再次确认 |
| 永久删除确认 | 需输入 12 位 Study ID |
| 不展示内容 | `SECRET_KEY`、DB 密码、服务器绝对路径 |
| 审计全覆盖 | 所有管理员操作写 `admin_audit_events` |
| 未来 | 管理员操作使用专门的 elevated token，与普通操作 token 区分 |
