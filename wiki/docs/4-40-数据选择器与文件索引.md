## 1. 基本原则

前端数据选择器不读取文件夹，只读数据库索引。

可筛选维度：

- Dataset Asset、Dataset Version、Study mount。
- subject、session、task、run。
- group、sex、age、handedness 等被试元数据。
- sampling rate、channel count、duration。
- marker/event label、event count。
- QC 状态。
- 是否已有 `raw_bids`、是否已有 `canonical_fif`。
- 是否已有某类 Execution 输出。

文件系统只在用户真正预览、运行或下载时被后端访问。

## 2. 大规模数据场景

即使有：

```text
4000 subjects * 2 sessions * 12 runs * 多种 marker
```

用户也不应该通过目录选择文件。推荐交互方式：

- 表格筛选。
- 批量选择。
- 保存选择规则。
- 按 subject/session/task/run 分组预览。
- 按 marker/event 快速分层。
- 显示预计命中数量和缺失数据。
- 一键选择“当前 Study 挂载的 working Dataset”。

## 2.1 DerivedDataset 跨 Execution 浏览复用同一筛选模型

`/results` 跨 Execution 浏览页（详见 [3-45](3-45-DerivedDataset.md) 和 [6-00](6-00-前端页面总览.md)）使用与 LoadData 一致的 chip 多维筛选交互：

- 维度直接复用 BIDS（`bids_subject_id` / `session` / `task` / `condition`）。
- 额外维度有 `data_type` 枚举、`node_types`、`tags[]`、`retention_status`、`run_ids`。
- 选择 chip 后立即调 `GET /studies/{id}/derived-datasets?...` 刷新列表。
- 选择规则不写回任何"派生选择器表"，只作为前端 URL query 参数；保存选择请走 Study `default_dataset_filter` 或 Pipeline LoadData。

也就是说"派生数据浏览"不引入额外索引表 —— `derived_datasets` 行本身就承载了筛选所需字段，前端 chip 直接映射后端查询参数。

## 3. 文件索引模型

数据选择器看到的是逻辑文件，不是服务器路径。

| 字段 | 说明 |
|---|---|
| `dataset_file_id` | 文件索引 ID，前端传这个而不是路径 |
| `file_role` | `raw_bids_data`、`canonical_fif`、`raw_bids_events` 等 |
| `logical_path` / `relative_path` | BIDS 或兼容相对路径 |
| `storage_uri` | 后端读取文件的位置，可为 `elys://`、`file://`、`s3://` |
| `sha256` | 内容校验 |
| `metadata_json` | provenance、转换参数、BIDS entities、显示摘要 |

当前代码已有 `dataset_files.logical_path` 和 `dataset_files.storage_uri`；`relative_path` 继续作为旧 API 兼容字段。

## 4. 摘要索引（规划，未落地）

建议维护两个轻量索引表（**当前 schema / ORM 中均无此两表**，属后续目标）：

| 表 | 用途 |
|---|---|
| `recording_event_summaries` | 每个 recording version 中各 marker/event 的数量、首末时间、标签别名 |
| `recording_channel_summaries` | 通道类型、坏通道候选、缺失通道、定位状态摘要 |

详细事件仍可保存在 Raw BIDS 的 `events.tsv` 中；选择器只需要摘要即可。

## 5. LoadData 解析

Pipeline 可以保存动态规则：

```text
使用本研究项中 task=rest 且 group=control 的当前数据
```

Execution 启动时必须冻结成静态输入：

```text
sub-001 ses-01 task-rest run-01 version=v0002 file=canonical_fif sha256=...
sub-002 ses-01 task-rest run-01 version=v0001 file=canonical_fif sha256=...
```

冻结结果写入 `pipeline_execution_inputs`，后续 Dataset 继续上传不会改变旧 Execution。

## 6. raw_bids 与 canonical_fif 的选择

默认策略：

| 场景 | 优先文件 |
|---|---|
| 长期引用、导出、分享、伦理审查 | `raw_bids` |
| MNE 快速预览和 Pipeline 运算 | `canonical_fif` |
| canonical FIF 缺失但 Raw BIDS 存在 | 自动生成或提示生成 canonical FIF |
| canonical FIF 已被清理 | 按 provenance 从 Raw BIDS 重建 |

数据选择器可以同时显示“Raw BIDS 可用”和“FIF 可用”两个状态，而不是让用户理解目录。

## 7. 文件索引与预览

| 操作 | 后端动作 |
|---|---|
| 波形预览 | API 鉴权后根据 `dataset_file_id` 读取 canonical FIF；缺失时触发生成 |
| marker 分割 | API 读取事件摘要或 Raw BIDS `events.tsv` |
| 批量运行 | Execution 创建时解析选择规则，写 `pipeline_execution_inputs` |
| 下载 | API 生成下载响应或短期下载 URL |
| 导出 BIDS | 根据 `raw_bids` 逻辑路径和 `storage_uri` 组装导出包 |

## 8. 当前代码状态

| 能力 | 状态 |
|---|---|
| LoadData 实时解析 | 已有 `/studies/{study_id}/pipeline/load-data/resolve` |
| Study default filter | LoadData 已读取 `study_settings.default_dataset_filter` |
| Execution 输入冻结 | 已写入 `pipeline_execution_inputs`，包括 selector 快照和解析后的数据清单 |
| Dataset File 匹配 | `PipelineExecutor.prepare_execution()` 会优先按 `canonical_fif` / `raw_source` 匹配 `dataset_files` |
| Dataset/Recording/Asset 文件查询 | 已有 `/datasets/{dataset_id}/files`、`/recordings/{recording_id}/files`、`/dataset-assets/{asset_id}/files` |
| Raw BIDS tree | 已有 `/dataset-assets/{asset_id}/bids-tree` |
| 文件 metadata/preview/download | 已有 `/dataset-files/{file_id}/metadata|preview|download` |
| Mount 过滤 | Dataset/Recording 列表已支持 `dataset_asset_id`、`mount_id`、`mount_name` |
| 大规模摘要索引 | `recording_event_summaries` / `recording_channel_summaries` 仍是后续目标（当前 schema / ORM 无此两表） |
| Raw BIDS 逻辑路径 | 新上传导入时写入 `logical_path`（调试期无 backfill 工具，不回填旧数据）；BIDS validator 仍待后续 |
