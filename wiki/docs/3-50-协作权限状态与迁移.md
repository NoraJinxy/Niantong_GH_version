## 1. 协作、审计与锁

| 表 | 用途 |
|---|---|
| `audit_events` | 上传、重传、挂载、运行、固定输出、清理、删除、权限变化等必须留痕的行为；含 `event_scope=study/system` 与 `snapshot` 字段 |
| `study_locks` | 研究项或工作流的编辑/运行锁，避免多人同时修改同一条执行链 |

MVP 推荐规则：

- 同一 Study 内可以多人查看。
- 同一 Pipeline 同时只允许一个人编辑。
- 同一 Pipeline 同时只允许一个 active Execution。
- 是否升级到“同一 Study 只允许一个 active Execution”，由 Study 设置决定。

## 2. 状态枚举

| 字段 | 建议值 | 说明 |
|---|---|---|
| `dataset_assets.status` | 当前为 `working` · `active` · `archived` · `deleted` · `quarantined` | 资产生命周期/内部记账，`quarantined` 用于伦理、合规或安全问题。**UI 不作徽章展示，仅 L3 技术信息可见** |
| `dataset_assets.visibility` | 当前为 `private` · `shared` · `public` | 可见范围。默认 `private`；发布默认私有，是否对外可见由负责人在发布后显式开放，**只升不降、无降级接口**（`private→shared→public` 可跳级开放，任何降级都无入口）。**这是数据集 UI 的状态徽章轴（6-05 B 方案）**，去掉了旧 `workspace` 档 |
| `recording_versions.status` | 默认 `current`，重传后旧版本转为 `replaced` | 当前版本由 DB 指针 `recordings.current_version_id` 决定 |
| `recordings.qa_status` | `VARCHAR(16)` 默认 `pending`，**无 CHECK 约束**（自由取值） | QA（质量核查，质检导入文件是否可用）不作为运行硬门槛；字段名是 `qa_status`，不是 `qc_status`。注意 `converted` 是 `recording_versions.qa_status` 的默认值，不是 `recordings` 的 |
| `studies.status` | `active` · `archived` · `trashed` | 研究项生命周期 |
| `pipeline_definitions.status` | CHECK `draft` · `active` · `archived` · `deleted`（均已落地，默认 `active`） | 工作流生命周期 |
| `pipeline_executions.status` | `queued` · `running` · `waiting_user_input` · `completed` · `failed` · `canceled` | 执行项状态 |
| `async_tasks.status` | `queued` · `running` · `succeeded` · `failed` · `canceled` · `retrying` | 后台任务状态 |
| `study_outputs.retention_status` | 当前为 `current` · `pinned` · `cached` · `temporary` · `deleted` · `quarantined` | 输出保留策略 |

## 3. 角色权限种子

权限分两层：平台级 RBAC 和 Study 级成员权限。

| 层级 | 表 | 说明 |
|---|---|---|
| 平台级 | `users` · `roles` · `permissions` · `user_roles` · `role_permissions` | 控制系统管理、数据集管理、全局模板等能力 |
| Study 级 | `study_members` | 控制某个研究项内的查看、编辑、运行、导出能力 |
| Dataset 级 | `dataset_members` | 共享邀请制授权表（按用户）：数据集开放为 `shared` 后，由负责人按用户授权，仅被授权者可读 / 可关联。共享 ≠ 任意登录用户可见（任意登录可见是 `public`）。表结构 `(id, asset_id, user_id, granted_by, granted_at)`，唯一约束 `(asset_id, user_id)` 防重复授权 |

建议内置角色：

| 角色 | 含义 |
|---|---|
| `admin` | 平台管理员，拥有系统配置、用户管理、隔离数据等权限 |
| `pi` | 课题负责人或高级研究者，可创建 Study、管理成员、导入数据、运行流程 |
| `owner` | Study 或 Dataset 所有者 |
| `editor` | 可编辑工作流、运行 Pipeline、管理 Study 内结果 |
| `viewer` | 只读查看数据、运行记录和结果 |

涉及数据删除、伦理隔离、权限变更、结果固定和缓存清理的行为必须写入 `audit_events`。

## 4. 当前代码表对照

| 表 | 说明 |
|---|---|
| `studies` | 研究项主表 |
| `study_members` | 研究项内成员与权限 |
| `recordings` | 采集记录主表，一条 BIDS subject/session/task/run（原 `datasets` 改名而来，是真实主表，无兼容视图）|
| `recording_versions` | 采集记录的上传/重传版本主表（原 `dataset_uploads` 改名而来，是真实主表，无兼容视图）|
| `dataset_assets` | Dataset 资产本体（用户视角的“数据集”）|
| `dataset_files` | 文件统一索引，外键 `recording_id` + `recording_version_id` + `dataset_version_id` |
| `pipeline_definitions` | Pipeline 定义（含版本号、模板标记）|
| `pipeline_executions` | 含 `manifest_json`、`save_policy` |
| `pipeline_jobs` | 节点级执行记录 |
| `study_outputs` | 输出统一登记，含 `storage_uri`、`retention_status`、`deleted_at` |

## 5. 主干能力清单

1. `studies`、`pipeline_executions`、`pipeline_jobs` 主干已落地。
2. `dataset_assets`、`dataset_versions` 已作为数据资产本体。
3. `dataset_files` 已统一登记 raw source、canonical FIF、sidecar。
4. `study_dataset_mounts` 已支持 Study 通过挂载引用 Dataset。
5. `pipeline_execution_inputs` 已在 Execution 启动时冻结实际输入。
6. `study_outputs` 已含 `retention_status`、`storage_uri`、`deleted_at`。
7. "当前认可结果"（指这条 Pipeline 被采纳为正式结论的那一次 Execution，区分于最新一次）：设计中的 `pipeline_definitions.current_execution_id` 指针列已核实在后端代码中查无，`PipelineDefinition` 模型未定义此列，目前只见于设计页 [3-30 Study与Pipeline表](3-30-Study与Pipeline表.md)。该语义当前由 `current` 保留档承载——Execution 以 `save_policy='current'` 落库、产物落在 `study_outputs.retention_status='current'`（即"被 Save 节点引用"的正式结果，见 [4-30 Study输出与Artifact](4-30-Study输出与Artifact.md)），并经 `study_outputs.produced_by_execution_id` 反查到对应 Execution；专用指针列仍是设计项。
8. `audit_events` 和 `study_locks` 已支持审计和编辑/运行锁。
