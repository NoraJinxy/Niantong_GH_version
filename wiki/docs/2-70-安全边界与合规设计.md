## 一句话现状

v1 已经实现了 **JWT 登录 + RBAC 双层权限 + 研究项数据目录鉴权访问 + 数据层只监听本机**。主域名 `elysbrain.site` 已备案（`粤ICP备2026062729号`），生产前还需要补：HTTPS、token 存储升级、密钥轮换、日志审计、备份策略。

## 1. 认证

| 项 | 当前 | 备注 |
|---|---|---|
| 登录方式 | 用户名 + 密码 | `POST /auth/login` |
| 密码存储 | bcrypt hash | `bcrypt.gensalt()` 默认 12 rounds |
| Token 类型 | JWT（access + refresh） | `python-jose` |
| 算法 | `settings.ALGORITHM`（默认 HS256） | 生产需切 RS256 + 密钥轮换 |
| 过期 | `ACCESS_TOKEN_EXPIRE_MINUTES`（默认短期） | refresh token 用于自动续签 |
| 前端存储 | `localStorage` | **需在生产前重新评估**：HttpOnly cookie + CSRF token 更安全 |
| Refresh 拦截 | `frontend/.../api/client.ts` 401 后自动刷新 | 失败则跳 `/login` |

## 2. 授权（RBAC 双层）

| 层 | 模型 | 数据 |
|---|---|---|
| **系统角色** | `admin` / `pi` 二选一（写在 `user_roles`） | `roles` + `permissions` + `role_permissions` |
| **研究项角色** | `owner` / `editor` / `viewer`（写在 `study_members.role`） | `study_members` |
| **细粒度权限** | 20 个 `xxx:read/write/delete/export` | `permissions` |

完整列表与种子见 [3-00 数据库设计总览](3-00-数据库设计总览.md)。模型细节见 [M0-20 RBAC](2-70-安全边界与合规设计.md)、[2-70 安全边界与合规设计](2-70-安全边界与合规设计.md)。

## 3. 鉴权点（路由层强制检查）

每个业务路由必经的两道关：

| 检查 | 实现 | 用例 |
|---|---|---|
| **系统权限** | `require_system_permission(user, "data:read", ...)` 等内联函数 | `admin` 直通；普通用户检查 `roles` 是否含对应 `permissions` |
| **研究项权限** | `require_study_read(study, db, user)` / `require_study_write(...)`（`services/study_access.py`） | 检查用户是否研究项 owner / member，且 `can_read/write` 为 true |

两道关都不通过 → `403 FORBIDDEN`。

## 4. 网络与文件边界

| 层 | 约束 | 风险点 |
|---|---|---|
| 入口服务器 | 不存 DB、不存研究项数据，仅返回前端 + 反代轻 API | 入口服被攻陷不直接暴露数据层 |
| 计算服务器 | FastAPI 监听 `127.0.0.1:8000`，由 Nginx 反代 | 不绑公网；外部访问需经 Nginx |
| PostgreSQL | 只监听 `127.0.0.1:5432` | 不开放公网 |
| Redis | 只监听 `127.0.0.1:6379` | 不开放公网 |
| 研究项数据目录 | `/mnt/elys_data/studies/` **不配 Nginx alias** | 所有文件访问必经 FastAPI 鉴权 |
| 认证 | 普通 + 数据 API 均要 `Authorization: Bearer <token>` | 大数据 API 直连计算服也要带 token |
| CORS | `backend/app/main.py` 由 `CORS_ORIGINS` 控制 | 生产环境只放行 `https://elysbrain.site`、`https://www.elysbrain.site`、`https://data.elysbrain.site` 等正式域名 |
| 部署 SSH | 专门部署 key（不复用人工登录 key） | `~/.ssh/elys_deploy_ed25519` · `~/.ssh/elys_doc_deploy_ed25519` |

## 5. 当前已落地清单

**已实现**

- ✅ bcrypt 密码 hash
- ✅ JWT access + refresh token
- ✅ 401 前端自动刷新
- ✅ 系统权限 + 研究项权限双层检查
- ✅ FastAPI 监听本机，由 Nginx 反代
- ✅ DB / Redis 仅本机监听
- ✅ 研究项数据目录不配公开访问，所有访问经 API 鉴权
- ✅ Bearer Token 鉴权大数据 API（上传 / 下载）
- ✅ 部署 SSH 与人工登录 key 分离

## 6. 生产前必补

| 项 | 现状 | 风险 |
|---|---|---|
| **HTTPS** | 备案已完成；DNS 解析和证书切换后启用 | token 在传输中可被嗅探 |
| **Token 存储** | `localStorage` | XSS 攻击可直接读 token，应改 HttpOnly cookie + CSRF |
| **`SECRET_KEY`** | 部署时设置，但未做轮换 | 长期不换有泄露风险 |
| **CORS 白名单** | 现状 `*` 风险 | 必须收窄到入口服域名 |
| **限流** | 无 | 暴力登录 / 接口洪水风险 |
| **审计日志** | 仅 `audit_events`（带 `event_scope=study` 子集）研究项级 | 缺登录、token 刷新、权限变更日志 |
| **DB 备份** | 无文档化策略 | 数据丢失风险 |

## 7. 合规边界

- **不在 wiki 写**：服务器账号 / DB 密码 / SECRET_KEY / 真实用户名密码。
- **EEG 数据隐私**：导出 / 共享必须保留脱敏与授权记录；未来 `bids_exports/` 时落地。
- **公共数据使用**：必须保留 license、来源、引用。
- **PI / PI Plus / PI Pro 资源档位**：只控制额度，不绕过数据隔离（见 [M0-40](8-00-功能模块总览.md)）。
