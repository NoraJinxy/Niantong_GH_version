## 一、首页 `/`（Index）

### 1.1 设计定位

首页是面向**访客和潜在用户**的品牌展示页，而不是功能入口。用户通过它了解产品，然后跳转到登录页进入工作台。

核心诉求：
- 传递产品价值（脑电科研 Web 工作台）
- 提供清晰的进入路径（登录按钮）
- 满足 ICP 备案展示的合规要求

首页**不走** `WorkbenchShell`，是独立的全页面布局，区别于工作台的三栏结构。

### 1.2 主要功能

| 区域 | 内容 |
|---|---|
| 导航栏 | Logo + 产品名 + 进入工作台按钮 |
| Hero 区 | 产品定位标语 + 简短描述 + 登录 CTA |
| 特性列表（规划） | 可追溯工作流、科研作图、机器学习等模块概览 |
| 底部 | ICP 备案号 + 工信部备案链接 |

### 1.3 备案合规

正式域名 `elysbrain.site` 已备案，备案号为 **粤ICP备2026062729号**。

- 底部始终展示备案号。
- 链接到 `https://beian.miit.gov.cn/`。
- 若后续子域名（文档站、营销页）落在同域下，各子页底部也需保留此展示。

## 二、登录页 `/login`（Login）

### 2.1 设计定位

登录页是工作台的唯一入口，面向已知用户（科研人员、管理员）。

设计目标：
- **极简**——只有必填字段，没有注册和找回密码入口（当前版本），减少认知负担。
- **明确反馈**——登录失败时立即给出具体原因（错误用户名/密码 vs 账号禁用），而不是通用"登录失败"。
- **安全意识**——不在页面明文暴露密码，提供密码可见切换。

### 2.2 主要功能

#### 表单字段

| 字段 | 类型 | 说明 |
|---|---|---|
| 用户名 | text | autocomplete=username，必填 |
| 密码 | password | autocomplete=current-password，可切换显示/隐藏 |
| 记住此设备 | checkbox | 默认勾选；当前影响 localStorage 行为（未来可差异化 token 有效期） |

#### 登录流程

```
用户输入 → 前端必填校验 → POST /api/v1/auth/login
→ 成功：保存 access_token + refresh_token + user 到 auth store + localStorage → 跳 /dashboard
→ 失败：显示红色 alert（具体错误文本来自后端 detail 字段）
```

#### JWT 双 Token 策略

- `access_token`：短期有效，每次请求携带（Authorization: Bearer）。
- `refresh_token`：长期有效，存入 localStorage；`api/client.ts` 拦截 401 后自动用 refresh 换新 access，对业务代码透明。
- 页面本身不直接处理 refresh，refresh 逻辑集中在 `api/client.ts` 拦截器。

### 2.3 错误处理

| 后端返回 | 前端展示 |
|---|---|
| 401 "用户名或密码错误" | 红色 alert + 输入框红色边框 |
| 401 "账号已被禁用" | 红色 alert，不显示红边框（不是用户输错） |
| 网络错误 / 5xx | 红色 alert "登录失败，请重试"（兜底文案） |

### 2.4 路由守卫与页面访问控制

- 已登录用户访问 `/login` → 路由守卫自动跳转 `/dashboard`，不进入此页。
- 未登录用户访问任何 `requiresAuth=true` 的页面 → 跳转 `/login`。
- Enter 键可提交表单（`@submit.prevent`）。

### 2.5 当前限制与规划

| 项 | 状态 | 说明 |
|---|---|---|
| 暴力登录限流提示 | 规划 | 后端已有频率限制，前端未展示具体提示 |
| 找回密码 | 规划 | 当前无 UI 入口，需联系管理员 |
| 多因素认证 | 规划 | 生产环境需考虑 MFA |
| HttpOnly cookie | 规划 | 生产部署建议将 token 迁移至 HttpOnly cookie + CSRF 防护，替代 localStorage |
