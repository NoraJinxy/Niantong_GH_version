## 〇、Pipeline 和 Execution 在四对象链路中的位置

Pipeline 编辑器和 Execution 执行是 ELYS **Dataset → Study → Pipeline → Execution** 主线的中后段。理解这两个页面的前提是知道四对象的边界：

```
Dataset（数据资产，可变） → Study（协作空间）→ Pipeline（流程定义） → Execution（执行事实，不可变）
                          挂载                  selector              冻结快照 + 产物
```

| Pipeline 编辑器看到的 | 实际背后是 |
|---|---|
| LoadData 面板的"研究项" / "Study" | 当前 Study 通过 `study_dataset_mounts` 挂载的所有 Dataset |
| LoadData 实时解析的"命中数据集" | selector 应用到挂载范围后解析出的具体 `dataset_files` |
| 节点参数 | 保存在 Pipeline `definition_json` 的默认值，Execution 时可被 override |
| "保存" | 写 `pipeline_definitions`，乐观锁 `expected_version + 1` |
| "运行" | 创建 Execution，把 selector 展开为静态快照写入 `pipeline_execution_inputs`，**此时与 Pipeline 解耦** |

**关键边界**：用户在画布上看到的"工作流"是定义，运行后的"产物"属于 Execution，不再属于 Pipeline。后续 Pipeline 怎么改，旧 Execution 也不变。详见 [5-00 研究管理总览](5-00-研究管理总览.md) 的"核心设计原则"。

## 一、工作流编辑器 `/pipeline`（PipelinePage）

### 1.1 设计定位

Pipeline 页面是 ELYS 分析流程的核心界面，承载三个相互关联的角色：
1. **工作流设计器**：用可视化节点图定义分析流程。
2. **参数配置器**：在右侧检视器内调整每个节点的参数。
3. **执行监控器**：触发运行、查看最近的 Execution 结果。

三个角色共存在一个页面，而不是拆成三个页面，原因是：科研人员在实际工作中频繁在"调整参数 → 运行 → 看结果"之间来回，减少页面跳转降低摩擦。

### 1.2 布局三分区

```
┌──────────────┬──────────────────────────────┬────────────────┐
│  左：节点库   │     中：LiteGraph 画布        │  右：检视器    │
│  研究项选择    │  工具栏（名称/保存/校验/运行） │  工作流信息   │
│  工作流选择  │  节点拖拽区                   │  节点参数表单 │
│  节点分类    │  连线、缩放、平移             │  LoadData面板 │
│  搜索        │  状态栏（校验/Execution 结果）       │  连接面板     │
└──────────────┴──────────────────────────────┴────────────────┘
```

**为什么关闭全局侧栏？**  
Pipeline 页只保留自身的左侧节点库/工作流选择栏，关闭 `WorkbenchShell` 的全局侧栏——避免双左栏，给画布最大空间。

### 1.3 节点库（8 个节点，全部已接执行器）

| 类型 | 类别 | 执行器状态 |
|---|---|---|
| `eeg/data/load`（LoadData） | data | <span class="elys-badge elys-badge--done">已接</span> |
| `eeg/filter/apply`（Filter） | preprocessing | <span class="elys-badge elys-badge--done">已接</span>（带通 / 高通 / 低通 / 陷波合一；FIR / IIR / 谱拟合） |
| `eeg/preproc/resample` | preprocessing | <span class="elys-badge elys-badge--done">已接</span> |
| `eeg/preproc/rereference` | preprocessing | <span class="elys-badge elys-badge--done">已接</span> |
| `eeg/ica/compute` | ica | <span class="elys-badge elys-badge--done">已接</span> |
| `eeg/ica/apply` | ica | <span class="elys-badge elys-badge--done">已接</span>（交互式，可暂停等人工剔除成分） |
| `eeg/epoch/segment` | epoch | <span class="elys-badge elys-badge--done">已接</span> |
| `eeg/analysis/erp` | analysis | <span class="elys-badge elys-badge--done">已接</span> |

!!! note "历史记录更正（2026-06-05）"
    本页早期写"10 个节点仅 LoadData 已接执行器"且列了一个 `eeg/output/save_result` 节点——前者与代码不符（`dispatcher.py` 已注册全部 handler），后者在代码中并不存在（无 JSON、无执行器），现已分别更正 / 移除。FIR / Butterworth / Notch 三个滤波节点已于 2026-06-05 合并为统一的 `eeg/filter/apply`（Filter，靠 `visible_when` 按 filter_type 切换参数 + `advanced` 高级折叠）。节点补全规划见 [5-25 工作流节点路线图](5-25-工作流节点路线图.md)。

节点之间通过端口类型约束连接：`eeg_data → eeg_data`，`epochs → evoked`，`analysis_result` 可接多种分析结果类型。不兼容的连线后端校验时返回 `LINK_PORT_TYPE_MISMATCH`。

### 1.4 主要功能

#### 工作流编辑

- 从节点库拖入节点到画布，按端口连线。
- 右键菜单：居中视图、100% 缩放、删除节点。
- 节点参数表单根据参数类型动态渲染：`text / number / integer / boolean / select / event_select / channel_list / dataset_filter / dataset_ids`。

#### 工作流版本管理（乐观锁）

保存时携带 `expected_version`。若并发修改导致版本冲突，后端返回 409，前端提示用户刷新后重新编辑。每次成功保存 `version+1`，保留版本迭代记录。

#### LoadData 实时解析

LoadData 节点有专属检视器面板，支持两种筛选模式：

| 模式 | 行为 |
|---|---|
| `filter`（按 BIDS 实体筛选） | 实时调 `POST /pipeline/load-data/resolve`，面板显示命中数据集数量和列表 |
| `explicit`（固定 dataset_ids） | 直接指定数据集 ID，丢失/状态异常时报 error |

修改筛选条件时立即触发 resolve，让用户在配参数时就能看到"这会命中哪些数据集"，而不是等到运行才发现选错了。

`__elys_null__` 占位符：Session 或 Run 为空的数据集用这个特殊值表示，前端 `encodeFilterValue` 统一处理，后端能正确匹配无 session/run 的条目。

#### 工作流校验

校验（`POST /validate`）会一次性返回所有 error 和 warning，分桶展示。不是遇到第一个就停——科研人员希望一次性知道所有问题，批量修复。

主要校验维度：
- **结构**：节点 ID 重复、循环依赖（环检测）
- **节点/参数**：节点规格不存在、必填参数缺失
- **连线**：端口类型不匹配、引用了不存在的节点
- **LoadData**：筛选模式非法、命中数据集状态异常（被 blocked）

#### 运行（Execution 创建）

运行时可配置 `execution_mode` 和 `save_policy`。运行按钮根据 Pipeline 状态（有未保存改动时）禁用，引导用户先保存。

Execution detail 分栏展示：`派生数据 / 节点 / 任务 / 输入 / 摘要 / Manifest / Lineage`，默认进派生数据分栏。

**当前限制**：节点级进度暂无 SSE / WebSocket 推送（运行已默认派发到 Celery worker，见 [7-40](7-40-工作流执行与后台任务.md)）。8 个内置节点都有执行器，能跑通"预处理 → ICA → Epoch → ERP"整条链；只有引用了无 handler 的未知节点类型才会返回 `PIPELINE_NODE_EXECUTOR_NOT_IMPLEMENTED`。

### 1.5 派生数据行内操作

在 Execution detail 的派生数据分栏：
- **inline 改名**：直接在行内编辑显示名。
- **行内 tag 编辑**：添加/删除标签，用于后续筛选。
- **状态切换**：固定（pin）、设为正式、隐藏。
- **底部清理**：调用 `runStudyOutputCleanup()` 批量清理 cached 状态的派生数据。

### 1.6 工作流定义格式

前端将 LiteGraph 图序列化为统一的 JSON 格式存入后端（JSONB 类型）：

```json
{
  "schema_version": "1.0",
  "name": "Filter-Epoch-ERP",
  "graph": {
    "nodes": [
      { "id": "n-1", "type": "eeg/data/load", "params": { ... } },
      { "id": "n-2", "type": "eeg/filter/apply", "params": { "filter_type": "bandpass", "l_freq": 1, "h_freq": 30 } }
    ],
    "links": [
      { "id": "e-1", "from": { "node": "n-1", "port": "output" }, "to": { "node": "n-2", "port": "input" } }
    ]
  }
}
```

后端以 JSONB 存储，节点规格（NodeSpec）在 `backend/app/pipeline/nodes/*.json` 中定义，前端通过 `GET /pipeline/nodes` 加载。

## 二、派生数据浏览 `/results`（ResultsPage）

### 2.1 设计定位

`/results` 是**跨 Execution 查看分析产物**的主界面。科研实际工作中，一个研究项会产生数十甚至上百个 Execution，每个 Execution 生成多个输出。研究者需要：

- 快速找到某个条件下最新的 ERP 结果。
- 对比不同参数下的派生数据。
- 决定哪些产物值得"固定"（pin）为正式版本，哪些可以清理。

Results 页的核心设计是：**多维筛选 + 列表管理 + 可追溯来源**。

### 2.2 主要功能

#### 多维筛选（顶部 chip 区）

| 筛选维度 | 说明 |
|---|---|
| `data_type` | 数据类型（evoked / epochs / psd / ...） |
| `node_types` | 产生来源的节点类型 |
| `bids_subject_ids` | 被试 |
| `sessions` | Session |
| `tasks` | 任务 |
| `conditions` | 条件 |
| `tags` | 用户自定义标签 |
| `retention_statuses` | cached / pinned / official / hidden |
| `run_ids` | 来源 Execution |

筛选条件多维可叠加，结果实时更新（调 `listStudyOutputs` 带 filter 参数）。默认按 `created_at` 降序展示。

#### 派生数据列表

| 列 | 说明 |
|---|---|
| 显示名 | 可 inline 修改 |
| 数据类型 | evoked / psd 等 |
| 被试/Session/任务/条件 | BIDS 实体 |
| 保留状态 | cached / pinned / official / hidden |
| 标签 | 用户自定义 |
| 来源 Execution | Execution ID + 序号 |
| 创建时间 | |

#### 行内动作与批量动作

**行内**：固定 / 设为正式 / 隐藏 / 下载单条派生数据。

**批量**：
- 批量改 retention 状态
- 批量加标签
- 批量隐藏
- 清理全部 cached（调 `runStudyOutputCleanup`，不可逆，有二次确认）

#### 详情抽屉：来源链可视化

点击派生数据行，右侧抽屉展开：

- **来源链**：`upstream_dataset_ids → upstream_recording_ids`，可视化展示数据从哪些 EEG 记录派生而来。
- **inline 编辑**：改显示名、改描述、改标签，无需跳转新页面。

来源链可追溯性是科研复现的基础——研究者发表结果时，能追溯到使用了哪批原始数据。

### 2.3 与 Pipeline 页的关系

- 在 Pipeline 页运行 Execution 后，产生的派生数据自动出现在 Results 页（共享同一套 `listStudyOutputs` API）。
- Pipeline 页的 Execution detail 是"某次运行的产物"视角；Results 页是"跨运行的产物管理"视角。
- 两者互补，研究者可以在 Pipeline 页触发运行，在 Results 页统一管理和筛选产物。
