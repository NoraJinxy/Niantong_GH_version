## 一句话标准

API 不暴露服务器目录，不让前端拼文件路径；前端只操作 Dataset、Study、Pipeline、Execution、DerivedDataset 和 Task。耗时操作返回 `202 Accepted` 和 `task_id`，业务结果通过 Execution、DerivedDataset、Dataset File 等资源查询。

## 三端调用模型

API 同时服务 Web UI、SDK Scripts、未来 LLM Agent 三类调用方，按 L1 / L2 / L3 分层。分层架构与 L3 任务级 API 规划见 [7-20 后端 API 设计与三端调用模型](7-20-后端API设计与三端调用模型.md)；历次端点收敛记录见 [9-00 更新日志](9-00-更新日志.md)。

## Pipeline/Execution 现状

Pipeline/Execution 创建入口为 `POST /studies/{study_id}/pipelines/{pipeline_id}/executions`。`execution_mode/save_policy`、`expected_version`、Execution cancel/retry、Task cancel/retry、Task events/SSE、Execution lineage 与 DerivedDataset `retention_status` PATCH 均已具备后端 API 或前端接入。该入口是否派发 Celery 取决于 `PIPELINE_EXECUTION_MODE`：`celery` 或 `auto`+有 worker 才派发异步任务，否则在 API 进程内联同步执行（见 [2-60](2-60-任务队列与异步架构.md) / [7-40](7-40-工作流执行与后台任务.md)）。

Study 路径已确定为 `/studies`，产品语义即「研究项」，不再保留迁名计划。真实部署级的登录、真实上传、真实 Celery/MNE 执行和浏览器端 SSE 仍需在 staging 环境补端到端验收。

## Dataset-first 现状

Dataset-first 导入链路代码级贯通：`POST /api/v1/dataset-assets/bootstrap` 是唯一的 Dataset 创建入口，可以创建 `DatasetAsset`、working `DatasetVersion`、配套 Study 和 `study_dataset_mounts`，并返回下一步上传上下文；导入接口（现位于 `/studies/{study_id}/recordings/import`）已支持显式 `dataset_asset_id` / `mount_name`，未挂载 `DatasetAsset` 会被拒绝；采集记录列表（`/studies/{study_id}/recordings`）、LoadData resolve 和 Execution 输入冻结已按当前 Study active mounts 查询外部 Dataset，并保留旧 `study_id` fallback。

## 1. 全局契约

| 项 | 约定 |
|---|---|
| Base URL | `/api/v1` |
| 认证 | `Authorization: Bearer <jwt_token>` |
| JSON 请求 | `Content-Type: application/json; charset=utf-8` |
| 文件上传 | `multipart/form-data`；大文件后续升级为 upload session |
| 幂等头 | 写操作可支持 `Idempotency-Key`，尤其是导入、运行、重试 |
| 时间格式 | ISO 8601，带时区；后端入库可用 UTC |
| 分页 | `?limit=50&cursor=...` 或 `?page=1&page_size=50`，同一模块内保持一致 |
| 错误响应 | 统一 `{"detail": {"code": "...", "message": "...", ...}}` |
| 文件访问 | 不返回裸路径；返回 `file_id` / `artifact_id` / download endpoint |

标准错误结构：

```json
{
  "detail": {
    "code": "PIPELINE_VERSION_CONFLICT",
    "message": "Pipeline has been updated by another user.",
    "resource_id": "uuid",
    "request_id": "uuid"
  }
}
```

## 2. 资源命名

「数据集」（Dataset Asset，用户视角的数据资产）独立于 Study，由 `/dataset-assets` 管；「采集记录」（Recording，一条 BIDS `subject/session/task/run`）则挂在所属 Study 下查询。

| 产品对象 | ORM 类 | 当前实际路径前缀 | 说明 |
|---|---|---|---|
| Dataset Asset | `DatasetAsset` | `/dataset-assets` | 用户视角的数据资产，独立于 Study；创建走 `POST /dataset-assets/bootstrap` |
| Recording | `Recording` | `/studies/{study_id}/recordings` | 一条 `subject/session/task/run` 采集记录；列表、导入、QA 都在此前缀下 |
| Dataset File | `DatasetFile` | `/dataset-files/{file_id}` | 原始文件、canonical FIF、sidecar 的索引（外键是 `recording_id` + `recording_version_id`） |
| Study | `Study` | `/studies` | 产品语义即「研究项」，路径已确定为 `/studies` |
| Study Dataset Mount | `StudyDatasetMount` | `/studies/{study_id}/datasets/mounts` | Study 通过挂载引用 Dataset Asset |
| Pipeline | `PipelineDefinition` | `/studies/{study_id}/pipelines` | 工作流定义 |
| Execution | `PipelineExecution` | `/studies/{study_id}/pipeline-executions` | 执行项记录 |
| DerivedDataset | `DerivedDataset` | `/studies/{study_id}/derived-datasets` | Execution 输出的派生数据集。完整端点见 [3-45](3-45-DerivedDataset.md) |
| Task | `AsyncTask` | `/studies/{study_id}/tasks` | 后台调度任务 |

命名约定：

- Study 路径就是 `/studies`，文档、UI 和接口文案统一叫「研究项」；不再保留任何迁名或 alias 计划。
- 采集记录的列表、导入、QA 都在 `/studies/{study_id}/recordings` 前缀下；`/studies/{study_id}/datasets` 现在只剩 `/mounts`（挂载管理）。
- Dataset Asset 由 `/dataset-assets` 管，独立于 Study；创建只能走 `POST /dataset-assets/bootstrap`。

## 3. 健康与认证

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/health` | 健康检查，无认证 |
| `POST` | `/auth/login` | 用户名密码登录，返回 access token / refresh token |
| `POST` | `/auth/refresh` | 刷新 access token |

认证接口保持轻量，不绑定 Study 或 Dataset 权限。**无 logout 端点**：JWT 是无状态的，登出即前端清本地 token；如将来要做服务端撤销，需新增 refresh token 黑名单表。

## 4. Dataset Asset API

Dataset Asset（用户视角的「数据集」/数据资产，ORM `DatasetAsset`）由 `/dataset-assets` 前缀统一管理：资产本体、发布版本（`DatasetVersion`，draft/published/withdrawn 生命周期见 [3-25](3-25-数据集生命周期与发布机制.md)）、文件索引和 BIDS 重建。采集记录（Recording）的列表与导入不在这里，见 §5。

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/dataset-assets/bootstrap` | **唯一 Dataset 创建入口**，见 §4.1 |
| `GET` | `/dataset-assets` | 列出当前用户可见 Dataset Asset |
| `GET` | `/dataset-assets/{asset_id}/versions` | 列出该资产的发布版本（`DatasetVersion`） |
| `POST` | `/dataset-assets/{asset_id}/versions` | 新建一个发布版本 |
| `GET` | `/dataset-assets/{asset_id}/files` | 资产文件列表，支持 `version_label` 和 `file_role` |
| `GET` | `/dataset-assets/{asset_id}/bids-tree` | Raw BIDS 逻辑树 |
| `POST` | `/dataset-assets/{asset_id}/raw-bids-build` | 触发 Raw BIDS 构建任务，返回 `201 + task` |
| `POST` | `/dataset-assets/{asset_id}/canonical-fif-rebuild` | 触发 canonical FIF 重建任务，返回 `201 + task` |
| `PATCH` | `/dataset-assets/{asset_id}` | 修改名称、描述、元数据；不直接改文件 |

> 已删除「`POST /dataset-assets` 裸建端点」：创建 Dataset 只能走 `bootstrap`，由它一并建好配套 Study 和挂载，避免出现没有挂载上下文的孤立资产。

### 4.1 Dataset-first bootstrap

导入主入口从 Dataset 开始，而不是从 Study 开始。`POST /api/v1/dataset-assets/bootstrap` 是**唯一**的 Dataset 创建入口：

| 方法 | 路径 | 说明 |
|---|---|---|
| `POST` | `/dataset-assets/bootstrap` | 创建或选择 `DatasetAsset`，同时创建或选择配套 Study，写入 `study_dataset_mounts`，并返回后续上传所需的 `study_id`、`dataset_asset_id`、`mount_name` 和上传 endpoint |

上传走 `POST /api/v1/studies/{study_id}/recordings/import`（见 §5），Dataset-first 页面会从 bootstrap 返回的 `next_upload` 中取 `study_id`、`dataset_asset_id` 和 `mount_name`。上传时直接传 `dataset_asset_id` 会要求该 `DatasetAsset` 已 active 挂载到当前 Study；传 `mount_name` 时会解析到对应 `DatasetAsset`，并校验二者不冲突。

## 5. Recording 与导入 API

采集记录（Recording，一条 BIDS `subject/session/task/run`）的列表、版本、文件、导入和 QA 都挂在 `/studies/{study_id}/recordings` 前缀下（ORM `Recording`，真实主表，由原 `Dataset`/`datasets` 改名而来）。导入是长耗时操作，提供同步（`/import`）和异步（`/import-task`）两条入口。

采集记录与版本（`recording_router`，前缀 `/api/v1/studies/{study_id}/recordings`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/studies/{study_id}/recordings` | 列出 Study 内采集记录，支持 `dataset_asset_id` / `mount_id` / `mount_name` 过滤 |
| `GET` | `/studies/{study_id}/recordings/{recording_id}/versions` | 上传/重传版本列表（`RecordingVersion`） |
| `GET` | `/studies/{study_id}/recordings/{recording_id}/files` | 该采集记录的文件索引列表，支持 `file_role` 过滤 |
| `POST` | `/studies/{study_id}/recordings/import` | 同步上传并转换源文件，返回 `201` 和 Recording/版本信息 |
| `POST` | `/studies/{study_id}/recordings/import-task` | 异步导入，创建后台任务，返回 `201 + task` |

QA 三件套（同在 `recording_router` 下）：

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/studies/{study_id}/recordings/{recording_id}/qa` | 读取 QA 状态和报告 |
| `POST` | `/studies/{study_id}/recordings/{recording_id}/qa/mock-run` | 生成 mock QA 报告 |
| `POST` | `/studies/{study_id}/recordings/{recording_id}/qa/review` | 人工确认 QA |

资产级文件入口（`asset_router`，见 §4）与文件访问（`file_router`，前缀 `/api/v1/dataset-files`）：

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/dataset-assets/{asset_id}/files` | Dataset Asset 文件列表，支持 `version_label` 和 `file_role` |
| `GET` | `/dataset-assets/{asset_id}/bids-tree` | Raw BIDS 逻辑树 |
| `GET` | `/dataset-files/{file_id}/metadata` | 文件索引详情，不返回裸绝对路径 |
| `GET` | `/dataset-files/{file_id}/preview` | 轻量预览 |
| `GET` | `/dataset-files/{file_id}/download` | 鉴权后下载或返回短期下载 URL |

导入成功后必须产生：

- `recordings`：新建或更新既有 `Recording`。
- `recording_versions`：本次上传/重传对应的 `RecordingVersion`。
- `dataset_files`：至少包含 `raw_source` 和 `canonical_fif`，可包含 sidecar；外键指向 `recording_id` + `recording_version_id`。

## 6. 数据选择 API

数据选择器只查数据库索引，不扫描目录。当前代码里已落地的只有 LoadData 实时解析（挂在 Pipeline 下）：

| 方法 | 路径 | 状态 | 说明 |
|---|---|---|---|
| `POST` | `/studies/{study_id}/pipeline/load-data/resolve` | 已实现 | 按 LoadData 选择规则解析当前命中的 Recording / File，供编辑器预览使用 |
| `GET` | `/dataset-assets/{asset_id}/event-summaries` | 规划 | marker/event 摘要，用于批量选择 |
| `GET` | `/dataset-assets/{asset_id}/channel-summaries` | 规划 | 通道摘要、坏通道候选、定位状态 |
| `POST` `GET` | `/studies/{study_id}/saved-selections` | 规划 | 保存 / 读取常用数据选择规则 |

> 「规划」表示尚未落地的设计端点，路径以最终实现为准。

选择规则可以动态，例如「task=rest 且 group=control」。LoadData 当前支持按 `mount_id`、`mount_name`、`dataset_asset_id` 先校验当前 Study active mount，再解析 `DatasetAsset` 和 `DatasetFile`；没有显式过滤时默认使用当前 Study active mounts，同时保留旧 `study_id` fallback。Execution 启动时必须把动态规则冻结到 `pipeline_execution_inputs`，记录 `dataset_asset_id`、`dataset_file_id`、`storage_uri`、`logical_path`、`sha256`，并在 metadata 中保留 `mount_id/mount_name`。

## 8. Study Dataset Mount API

Study 通过挂载引用 Dataset Asset，不复制 Dataset 文件。挂载端点挂在 `/studies/{study_id}/datasets/mounts` 下（这是 `/studies/{study_id}/datasets` 前缀目前唯一剩下的一组端点）。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/studies/{study_id}/datasets/mounts` | 当前 Study 挂载的数据集 |
| `POST` | `/studies/{study_id}/datasets/mounts` | 挂载 Dataset Asset，可附带默认选择规则 |
| `PATCH` | `/studies/{study_id}/datasets/mounts/{mount_id}` | 修改显示名、默认选择范围、启用状态 |
| `DELETE` | `/studies/{study_id}/datasets/mounts/{mount_id}` | 取消挂载，不删除 Dataset 文件 |

取消挂载不能破坏既有 Execution 追溯；旧 Execution 的 `pipeline_execution_inputs` 仍保留当时输入。

## 12. Task API

Task 是后台调度任务，适用于导入、转换、Pipeline Execution、预览生成、缓存清理和导出。下表用简写路径表达资源语义；当前代码里 Task 端点都挂在 Study 作用域下（`/studies/{study_id}/tasks/...`），实际清单见 §16.6。

| 方法 | 路径 | 说明 |
|---|---|---|
| `GET` | `/tasks/{task_id}` | 查询任务状态、进度、错误、关联资源 |
| `GET` | `/tasks/{task_id}/events` | 事件列表，支持 `since` 增量查询 |
| `GET` | `/tasks/{task_id}/events/stream` | SSE 事件流，支持 `since` 和 `Last-Event-ID` |

## 14. HTTP 状态码

| HTTP | 含义 | 场景 |
|---|---|---|
| `200` | 成功读取或同步轻操作成功 | 查询、普通更新 |
| `201` | 创建成功 | 创建 Dataset、Study、Pipeline |
| `202` | 已接受，后台执行 | 导入、转换、Execution、导出、清理 |
| `204` | 成功且无响应体 | 删除成员、取消挂载 |
| `400` | 请求语义错误 | 选择规则非法、上传组合不完整 |
| `401` | 未登录或 token 失效 | 缺认证 |
| `403` | 权限不足 | 非成员访问 Study |
| `404` | 资源不存在 | id 错误或无可见权限 |
| `409` | 冲突 | 版本冲突、锁冲突、同名、重复导入 |
| `422` | 字段校验失败 | Pydantic 校验失败 |
| `423` | 资源已锁定 | Pipeline 正在被编辑或运行 |
| `500` | 服务端错误 | 未预期异常 |
| `503` | 后台服务不可用 | Redis/Celery/预览引擎不可用 |

Execution 创建请求当前支持：

```json
{
  "trigger": "manual",
  "execution_mode": "analysis",
  "save_policy": "current",
  "selection_override": {
    "load-1": {
      "selection_mode": "explicit",
      "dataset_ids": ["..."],
      "dataset_filter": {
        "require_fif": true
      }
    }
  }
}
```

其中 `execution_mode` 可为 `trial`、`analysis`、`replay`、`system`，`save_policy` 可为 `temporary`、`current`、`pinned`、`discard`。

当前创建规则：

| Pipeline 状态 | 允许创建 |
|---|---|
| `active` | `analysis` / `trial` |
| `draft` | `trial` |
| `archived` | 禁止，返回 409 |
| `deleted` | 不可见，返回 404 |

## 17. 维护规则

- 新增后端路由必须同步更新本页和对应模块页。
- 前端 `api/*.ts` 不写裸 axios 路径，统一封装资源 API。
- API 返回 ID、状态和可访问 endpoint，不返回服务器绝对路径。
- 写操作必须考虑幂等、权限、审计和锁。
- 长耗时操作优先返回 Task，不让 HTTP 请求线程长期阻塞。
