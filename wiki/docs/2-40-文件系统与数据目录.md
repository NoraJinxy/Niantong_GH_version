## 1. 生产落盘原则

生产环境应用代码和数据盘分开：

```text
/opt/elys/
  app/                 # 应用代码、虚拟环境、前端构建、部署脚本

/mnt/elys_data/
  studies/            # 当前代码实际使用的数据根
  storage/             # 新标准目标数据根
  backups/             # 数据库备份、索引导出、关键配置备份
  logs/                # 可选日志目录
```

当前配置（`backend/app/config.py`）：

```env
STUDIES_DIR=/mnt/elys_data/studies            # legacy：studies.data_root 的基目录
ELYS_STORAGE_ROOT=/mnt/elys_data/storage      # 新存储根
DATASETS_STORAGE_ROOT=/mnt/elys_data/storage/datasets
STUDIES_STORAGE_ROOT=/mnt/elys_data/storage/studies   # 研究项工作输出根（executions/derived 等）
TRASH_STORAGE_ROOT=/mnt/elys_data/storage/trash
```

创建 Study 时，`studies.data_root` 写成 `STUDIES_DIR/{study_id}`（`backend/app/services/studies.py:247`，即 `/mnt/elys_data/studies/{study_id}`）；而 Execution / StudyOutput 等工作产物落在 `study_storage_root = STUDIES_STORAGE_ROOT/{study_id}`（`studies.py:80`）。两套目录在 `create_study_storage_directories` 里**都会创建**（先建 legacy，再建新存储），不是"二选一"。

字段名 `data_root` 是历史遗留，当前表示研究项的 legacy 数据根目录，不等于官方 Raw BIDS 数据集根。

## 3. 标准目标目录

新标准目标是把 Dataset 数据资产和 Study 输出拆开：

```text
/mnt/elys_data/storage/
  datasets/
    ds-000001/
      versions/
        v0001/
          sourcedata/
          raw_bids/
          derivatives/
            elys-canonical-fif/
          qc/
  studies/
    202605000001/
      executions/
      derived/
      previews/
      temp/
      exports/
      pipeline_snapshots/
  exports/
  trash/
```

> 数据集与 Study 拆分、`storage/datasets` 与 `storage/studies` 双根、`executions/`+`derived/` 命名当前都已落地（见上面"新存储根"），这一节描述的就是现状。

关键变化：

| 当前 | 目标 |
|---|---|
| 每个 Study 目录里既放原始数据又放输出 | Dataset 与 Study 分开 |
| `source_uploads/`（legacy） | `sourcedata/original_uploads/` |
| `fifdata/`（legacy） | `derivatives/elys-canonical-fif/` |
| 旧 `runs/` + `artifacts/`（legacy `pipeline_runs/`） | `studies/{study_id}/executions/` + 内容寻址 `derived/{sha256[:2]}/{sha256}/` |
| `bids_exports/`（legacy） | `storage/exports` 或 Study 内 `exports` |

## 4. Raw BIDS 不是复制要求

目标目录里的 `raw_bids/` 是标准 Raw BIDS 入口，但不要求物理复制一份大文件。

实现方式：

- **当前已落地** —— 纯数据库逻辑视图：`dataset_files.logical_path` 是 Raw BIDS 路径，`storage_uri` 指向原始上传物理文件（导入时只登记逻辑行、不复制、不建链接，见 `backend/app/routers/datasets.py`）。
- **规划，未实现** —— 硬链接 / reflink：在目录上摆出 Raw BIDS 文件树、大文件共享底层数据块。
- **规划，未实现** —— 对象引用：用 `storage_objects` 让一个物理对象对应多个逻辑文件（`storage_objects` 表当前不存在）。

详细规则见 [4-60 raw_bids 视图与零复制策略](4-60-raw_bids视图与零复制策略.md)。

## 5. 配置与安全

生产配置建议：

```env
STUDIES_DIR=/mnt/elys_data/studies
KEEP_EXISTING_DATA=true
RESET_DB=false
RESET_STORAGE=false
RESET_DATA_ROOT=false
```

部署脚本不得默认清空 `/mnt/elys_data`。任何重置数据根的动作都必须是显式治理操作。
