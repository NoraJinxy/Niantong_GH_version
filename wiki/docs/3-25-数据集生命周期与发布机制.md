## 一句话现状

数据集生命周期建立在**两根正交轴**之上：**发布状态轴**（版本级 `DatasetVersion.state`，管能否改 / 能否删 / 是否冻结 / 是否铸 DOI）与**可见范围轴**（资产级 `DatasetAsset.visibility`，管谁能看 / 谁能关联）。核心原则是**发布 ≠ 分享**：发布只冻结版本并铸 DOI、可见范围默认私有；是否对外可见由负责人在发布后单独、单向地开放。schema 字段（`state` / `visibility` / `dataset_members` 授权表等）与撤回审计表均已就位，发布 / 撤回 / 关联 / 可见范围开放的业务流转按本页基线实现。

## 1. 概念模型：两根正交轴

数据集的生命周期由两根**互不耦合**的轴描述。理解这两根轴各管什么、为什么不互相驱动，是读懂本页其余部分的前提。

| 轴 | 落在哪 | 取值（中文 / 枚举） | 管什么 |
|---|---|---|---|
| **发布状态** | 版本级 `DatasetVersion.state` | 未发布 `unpublished` · 已发布 `published` · 撤回审核中 `withdraw_requested` · 已撤回 `withdrawn` | 能否改文件、能否删、是否冻结、是否已铸 DOI |
| **可见范围** | 资产级 `DatasetAsset.visibility` | 私有 `private` · 共享 `shared` · 公开 `public` | 谁能读、谁能把它关联进自己的研究项 |

> 还有第三根**内部记账轴** `DatasetAsset.status`（`working` / `archived` / `deleted` / `quarantined`），仅供平台内部使用、不上界面徽章。它和上面两根轴各自独立。（`working` 是唯一存活态——历史上的 `active` 已并入 `working`。）

### 1.1 设计原则

1. **数据集先于研究项**：数据集（DatasetAsset）是独立的物理身份，不属于任何单个研究项。研究项通过**关联（Link）**引用数据集，并不拥有它。
2. **发布 ≠ 分享**（最核心）：发布只做两件事——把版本**冻结**为不可变快照、**铸 DOI**；它**不改可见范围**。新发布的版本默认私有，是否对外可见，由负责人事后单独决定。
3. **不可变发布**：每个已发布版本都是不可变快照，文件不可再改。要修改必须开新版本（v+1）前进，旧版本保留。
4. **版本即引用**：关联（Link）、Pipeline 输入、派生数据引用的都是具体某个 `DatasetVersion`，不是数据集本身。
5. **跨研究项关联受双重门控**：要被别的研究项关联，既要**版本已发布**，又要**可见范围允许**（公开，或该用户已被授权）；未发布版本与私有数据集只在主研究项内可用。
6. **可见范围只升不降**：私有 → 共享 → 公开可逐级或跳级开放，但**不提供任何降级 / 取消接口**。共享 / 公开是不可逆的对外释放；要可撤销的协作，请用「私有 + 把人加进研究项团队」（见 §8.3）。
7. **撤回不删除**：撤回的版本变成墓碑，版本号 / DOI / 引用关系 / 审计历史全部永久保留。
8. **发布是合规关口**：未发布 → 已发布时强制确认「已脱敏」并声明伦理与版权，否则不能发布；每个版本独立声明（见 §5.2）。

## 3. 发布状态轴：状态机

### 3.1 状态机定义

发布状态轴落在版本级（`DatasetVersion.state`）。注意图中标注的「谁可见 / 谁可关联」是**可见范围轴叠加后的结果**——状态机本身只管冻结 / DOI / 出口动作，可见范围细则见第 4 节。

```
                ┌─────────┐
                │ created │
                └────┬────┘
                     │ bootstrap 建数据集即进入
                     ▼
              ┌────────────────────┐  文件可改、可整体删除
              │  未发布 (v1)        │  仅主研究项可见 / 可关联（无论可见范围）
              │  unpublished        │  主研究项内可跑 Pipeline（产物自动未发布）
              └──────┬─────────────┘
                     │
                     │ [仅负责人 点发布]
                     │ ─ 校验 SemVer 格式
                     │ ─ **强制合规关口**：勾选「已脱敏」+ 声明伦理 + 声明版权（缺则拒绝）
                     │ ─ 不强制 QA pass，但展示 qa_status
                     │ ─ 计算 content_hash（异步）
                     │ ─ 铸 Version DOI；首次发布建 Concept DOI（私有发布也铸，解析到受限页）
                     │ ─ **可见范围不变**（默认私有，不自动转共享）
                     ▼
              ┌────────────────────┐  immutable，已冻结
              │  已发布 (v1)        │  可见范围决定谁能读 / 谁能关联
              │  published          │  跨研究项关联还需：公开 或 已被授权
              │  qa_status:         │  派生数据可升级到已发布
              │   pass/fail/not_run │
              └────┬──────────┬────┘
                   │          │
       [想改]      │          │  [仅负责人 提交撤回申请 + 理由]
                   ▼          ▼
        ┌────────────────┐  ┌────────────────────┐
        │  未发布 (v2)    │  │ 撤回审核中          │  **禁止新关联**（已有关联保留）
        │  unpublished    │  │ withdraw_requested  │
        │  (v1 仍可用)    │  └─────────┬──────────┘
        └────────────────┘            │
                                      │ [管理员审核]
                            ┌─────────┴──────────┐
                            ▼                    ▼
                    approved             rejected
                            │                    │
                            ▼                    ▼
                    ┌────────────┐      回到 已发布
                    │  已撤回    │      (审核记录留痕)
                    │ withdrawn  │
                    │  (终态)    │
                    └────────────┘
                    ─ 墓碑页保留：name/owner/dates/DOI/withdraw_reason/admin_notes
                    ─ 已有关联 / Execution 引用：保留（兼容历史）
                    ─ 新关联 / 新 Execution 引用：禁止
                    ─ 通知所有引用方
```

### 3.2 发布状态轴 · 权限与出口动作

| 发布状态 | 文件可改 | 能删？ | 出口动作（触发者） |
|---|---|---|---|
| 未发布 `unpublished` | ✅ | ✅ **整体删除**（负责人；仅当该资产无任何已发布 / 已撤回版本） | 发布 / 删除 |
| 已发布 `published` | ❌ 冻结 | ❌ 只能撤回 | 开放可见范围↑ / 申请撤回 / 开新版（v+1）/ 丢弃该资产上的 v+1 未发布版本 |
| 撤回审核中 `withdraw_requested` | ❌ | ❌ | 管理员批准 / 驳回 |
| 已撤回 `withdrawn`（终态） | ❌ | ❌ | 仅可开新版本（v+1）前进 |

### 3.3 状态转换权限矩阵

> **触发者口径（重要）**：发布 / 授权 / 申请撤回 / 开新版（v+1）/ 删除 = **仅负责人**（不含创建者 / PI / 编辑）。**管理员**只保留平台治理职责：撤回审核、紧急下架、隔离。（PI 若不是负责人，对本研究项内数据集**没有**生命周期权限——数据集生命周期强绑定到负责人个人。）

| 转换 | 触发者 | 前置条件 | 副作用 |
|---|---|---|---|
| `created → 未发布` | 负责人 | 建数据集即进入未发布 v1 | 主研究项自动设置（来自 bootstrap） |
| `未发布 → 已发布` | **仅负责人** | SemVer 校验通过 + **合规关口**（已脱敏确认 + 伦理声明 + 版权声明），否则 422 | 铸 DOI、冻结 `dataset_files`、写合规审计；**可见范围保持默认私有、不自动转共享**；通知关联该版本的研究项 |
| `已发布 → 未发布 (v+1)` | **仅负责人** | 旧版本保持已发布；同时只能有一个进行中版本 | 创建新版本行，旧版不受影响；v+1 可单独丢弃 |
| `未发布 → 删除` | 负责人 | 该资产无任何已发布 / 已撤回版本 | 整体硬删该资产；已发布历史一律不可删 |
| `已发布 → 撤回审核中` | **仅负责人** | 必须填写 `withdraw_reason` | 进入审核队列；**即起禁止新关联**，已有关联保留 |
| `撤回审核中 → 已撤回` | 管理员 | 审核通过 | 写 `withdrawn_at` / `withdrawn_by` / `withdrawal_admin_notes`，生成墓碑，通知引用方 |
| `撤回审核中 → 已发布` | 管理员 | 审核驳回 | 留存审核记录，清空 `withdraw_requested_*` 字段 |
| `已发布 / 审核中 → 已撤回`（紧急下架） | 管理员 | 仅限 PII 泄露 / 法律风险等紧急场景 | 跳过审核，但必须事后补审计记录 |

### 3.4 派生数据的生命周期继承

派生数据集（`DerivedDataset`）的状态由上游推导：

| 上游状态 | 派生数据初始状态 | 跨研究项可用 |
|---|---|---|
| 未发布 `unpublished` | 未发布 `unpublished` | ✗ |
| 已发布 `published`（主研究项内 Execution 产出） | 未发布 `unpublished`（需负责人选择升级） | ✗ → 升级后 ✓ |
| 已撤回 `withdrawn` | 联动 `withdrawn` | 已有引用保留，新引用禁止 |

## 4. 可见范围轴：谁能看、谁能关联

可见范围轴落在资产级（`DatasetAsset.visibility`），三档**开放度逐级提高**。注意：可见范围只对**已发布版本**生效——无论哪一档，**未发布版本始终仅主研究项可见**。

### 4.1 可见范围 · 权限矩阵

| 可见范围 | 谁能读 | 谁能关联到自己研究项 | 谁来设 |
|---|---|---|---|
| 私有 `private`（发布默认） | 负责人 / 管理员 / **主研究项成员** | 仅主研究项 | 发布即此档 |
| 共享 `shared`（邀请制） | ＋ 负责人**按用户**授权的人（`dataset_members`） | ＋ 被授权用户的研究项 | 负责人逐个授权 |
| 公开 `public` | 任何注册（登录）用户 | 任何研究项 | 负责人 |

- **私有**：除负责人 / 管理员外，只有**主研究项成员**能看。这是默认态，也是「发布 ≠ 分享」的落点。
- **共享 = 邀请制，不是「任何登录用户可见」**：负责人在 `dataset_members` 表里**按用户**授权，只有被授权者可读、可关联。
- **公开 = 任何注册用户**可读、任何研究项可关联。平台无匿名访问，所以「公开」止步于登录边界，不需要匿名只读路由。

### 4.2 开放可见范围（只升不降）

可见范围的变更是**单向**的：

- **只升不降、无降级接口**：私有 → 共享 / 公开可逐级或跳级开放；任何降级 / 取消都**没有入口**（既不在前端给按钮，也不在后端给端点）。`visibility` 已从通用 PATCH 中移除，改由专门的「开放」动作处理（仅负责人，带 `new>current` 守卫）。
- **开放前置**：纯未发布资产恒私有——**至少有一个版本已发布**后，才能开放为共享 / 公开（无已发布内容可分享）。
- **为什么不可逆**：共享 / 公开 = 把数据交出去，对方可能已复制，无法真正收回（优盘能要回，已复制的数据要不回）。要**可撤销**的协作，请用「私有 + 把人加进研究项团队」（随时移除成员即断其后续访问）。详见 §8.3。

### 4.3 跨研究项关联网关

「能否被别的研究项关联」由**两根轴共同**把守，缺一不可：

1. **发布状态**：版本必须**已发布**（`state == 'published'`）。未发布 / 撤回审核中 / 已撤回一律拒绝新关联。
2. **可见范围**：跨研究项关联还要求 **公开**，或**关联发起人已被授权**（命中 `dataset_members`）；**私有**数据集只能在**主研究项**内关联。

> 授权的传递性（已定）：授权控制「谁可发起关联」。数据集一旦被关联进某研究项，即成为该研究项的组内共享资源、其成员皆可使用。即「授权某用户」≈「信任该用户及其协作研究项」——共享会随被授权者带进其研究项，并非逐人滴水不漏。

### 4.4 完整规则清单（审核基准）

1. 两轴正交：发布状态轴管 可改 / 可删 / 冻结 / DOI；可见范围轴管 谁能看 / 谁能关联。
2. 发布 ≠ 分享：发布只冻结 + 铸 DOI，可见范围默认私有、不自动转共享。
3. 发布为 PII / 伦理 / 版权关口：发布强制脱敏确认 ＋ 伦理 / 版权声明。
4. 删除：未发布可整体删除；已发布（含私有）一律不可删、只能撤回；已发布资产上的 v+1 未发布版本可单独丢弃。
5. 可见范围**只升不降、不提供降级接口**：私有 → 共享 → 公开可跳级开放，但任何降级都无入口。
6. 私有 = 负责人 + 管理员 + 主研究项成员可见。
7. 共享 = 邀请制：负责人按用户授权（`dataset_members`），仅被授权者可读 / 可关联，**非「任何登录用户可见」**。
8. 公开 = 任何**注册（登录）用户**可读 / 任何研究项可关联（平台无匿名访问）。
9. 操作权限：发布 / 授权 / 申请撤回 = 仅负责人；撤回审核 / 紧急下架 = 管理员。
10. 撤回审核中：禁止新关联；已有关联保留。
11. 已撤回 = 终态墓碑，禁新关联，只能开新版本前进。
12. 可见范围为资产级，但仅暴露已发布版本；未发布版本始终仅主研究项可见。
13. 关联网关：跨研究项关联要求 版本已发布 **且**（公开 或 用户已被授权）；私有仅主研究项。

## 5. Schema 变更清单

### 5.1 `DatasetAsset` 关键字段

| 字段 | 类型 | 约束 | 用途 |
|---|---|---|---|
| `primary_study_id` | `VARCHAR(12)` | `REFERENCES studies(id) ON DELETE SET NULL`，nullable | 主研究项。未发布时必填；已发布后保留作「出身记录」 |
| `visibility` | `VARCHAR(32)` | `private` · `shared` · `public`，默认 `private` | 可见范围轴；只升不降，由「开放」动作单向设置 |
| `status` | `VARCHAR(32)` | `working` · `archived` · `deleted` · `quarantined`，默认 `working` | 内部记账轴，不上界面徽章（`working` 为唯一存活态） |
| `concept_doi` | `VARCHAR(256)` | nullable，unique | Concept DOI，永远指向最新已发布版本（Zenodo 模式） |
| `current_version_id` | `UUID` | `REFERENCES dataset_versions(id)`，nullable | 当前默认版本指针，UI 默认展示 |

## 6. 版本与发布关键决策

### 6.1 撤回机制

- **撤回可申请**：类比论文撤稿，负责人提交申请 + 理由。
- **管理员审核**：管理员审批，通过后进入已撤回终态。
- **不可逆**：已撤回是终态，不能退回未发布。要继续工作必须开 v+1 新版本（前向演进，不是状态回退）。
- **紧急下架通道**：管理员可绕过审核直接下架，事后补审计记录，用于 PII 泄露 / 法律风险等。

**反例**：不支持「已撤回 → 未发布」状态转换。理由：DataCite DOI 不可逆向、下游引用稳定性、学术撤稿标准（详见 §8.2）。

### 6.2 主研究项在发布后保留

- `DatasetAsset.primary_study_id` 在发布后**保留作「出身记录」**。
- UI 显示为「最初策展于 研究项 X（originally curated in Study X）」。
- 外键 `ON DELETE SET NULL`：删除研究项不影响数据集，但数据集失去主研究项标识。

**反例**：不采用「发布后解除主研究项关系」方案。理由：出身信息有学术价值 + 删除研究项仍能优雅降级。

### 6.3 SemVer 强制

展示版本号必须符合 `x.y.z` 格式：

- **major**：实验设计变更（任务范式变了 / 通道布局变了 / 采样率变了）。
- **minor**：加被试 / 加 session / 加新条件。
- **patch**：元数据笔误 / 注释修正 / sidecar 补全。

**首版默认 1.0.0**，允许负责人显式使用 0.x.y 表示 pre-release / 未稳定状态。

**反例**：不采用任意字符串版本号。理由：OpenNeuro / PhysioNet 实践证明 SemVer 能传递变更语义，任意字符串无法机器解析。

### 6.4 紧急下架通道（管理员）

- 由**管理员**触发（不再专设 superadmin；`superadmin` 角色保留，但用于管理员管理 / 平台治理，与数据集生命周期无关）。
- 跳过审核流程，直接「已发布 / 审核中 → 已撤回」。
- **必须事后补审计**：`dataset_withdrawal_requests.decision = 'emergency'`，`admin_notes` 必填。
- 使用场景：PII 泄露、法律强制下架、严重数据错误。

### 6.5 发布合规关口（脱敏 / 伦理 / 版权）

未发布 → 已发布是平台的合规闸门：

- 发布时**强制勾选「已脱敏」**确认，并**声明伦理与版权**，三者缺一则发布被拒（422）。
- **每次发布独立声明**：每开一个新版本并发布都要重做脱敏 / 伦理 / 版权声明——每个已发布版本都是独立不可变制品，不能用上一版的声明一次性套用。
- 声明随发布写入审计（`audit_events`），可追溯「谁在何时声明了什么」。

### 6.6 DOI 与发布解耦于可见范围

- **私有的已发布版本同样铸 DOI**（解析到受限落地页，Zenodo 同模式），与「已发布不可删」一致——DOI 标识的是「这个版本存在过」，与对外可见与否无关。
- Concept DOI（资产级）+ Version DOI（版本级）双 DOI，首次发布建 Concept DOI 并指向最新已发布版本。

## 7. 业内调研对照

| 平台 | 已发布能否删 | 撤回后墓碑 | DOI 处理 | 版本机制 |
|---|---|---|---|---|
| **OpenNeuro** | owner 自助即可删 | 弱:默认无墓碑,支持 redirect URL | landing page 持久 | git tag = snapshot,推荐 SemVer |
| **Zenodo** | 30 天内可自删;之后需提交理由审核 | **强**:固定墓碑页,保留 DOI + URL + 撤回原因 | DOI 永久,解析到墓碑 | "New Version"按钮,已发布版不可改 |
| **PhysioNet** | 几乎不允许 | 未公开 | 每版独立 DOI + Latest DOI | 强制 x.y.z SemVer |
| **OSF** | Project 可删;Registration 不可删但可 withdraw | 强 (registration 必留墓碑) | DOI 保留 | Registration 不版本化 |
| **Dryad** | "exceptional action",类比文章撤稿 | 弱:原数据保留 + warning | 单一 DOI 跨版本共享 | 可发新版,旧版保留 |

**ELYS 采纳的实践**：

1. **Zenodo 模式**：撤回需审核 + 强制墓碑（`dataset_withdrawal_requests` 表）。
2. **PhysioNet 模式**：强制 SemVer x.y.z 格式。
3. **Zenodo 双 DOI**：`DatasetAsset.concept_doi` + `DatasetVersion.version_doi`（私有发布也铸，见 §6.6）。
4. **OpenNeuro 失败教训**：不允许负责人一键删除已发布版本（避开 Issue #1176 同类问题）。

**ELYS 差异化**：

- **发布 ≠ 分享**：上述平台多把「发表」与「公开」绑死，ELYS 把发布（冻结 + DOI）与可见范围（私有 / 共享 / 公开）拆成两根正交轴，私有也能发布、铸 DOI。
- **邀请制共享**：共享档按用户授权（`dataset_members`），不是「任意登录可见」。
- **下游引用追踪**（`dataset_version_references`）：撤回时主动通知引用方——OpenNeuro / Zenodo 都没做好的环节。

## 8. 关键辨析

### 8.1 「导入 Import」「关联 Link」「加载 Load」三件事

|  | 导入 Import | 关联 Link | 加载 Load |
|---|---|---|---|
| 中文 / English | 导入 / Import | 关联 / Link | 加载 / Load |
| 代码 | `/recordings/import` | `StudyDatasetMount` | LoadData 节点 |
| 含义 | 外部文件（EDF/BDF…）进平台、造出数据集 | 研究项接上一个**已有**数据集、使其可用（数据不搬动） | Pipeline 的 LoadData 节点**运行时**把数据读入流程 |
| 心理图像 | 文件从外面进来 | 两个东西连根线 | 跑的时候把数据读进来 |

原「挂载 Mount」对医生 / 心理学背景用户偏术语，改用更友好的**「关联 Link」**；**「加载 Load」专留给** Pipeline 的 LoadData 节点（它本就叫 Load Data）。三个词中英一一对应、互不混用。代码标识 `StudyDatasetMount` / `mount` 是物理层名字、用户不可见。

### 8.2 「已撤回」不并入「未发布」（保留四态）

|  | 未发布 Unpublished | 已撤回 Withdrawn |
|---|---|---|
| 是否曾发布 | 否 | 是 |
| DOI / 引用 | 无 | 有，须永久保留 |
| 可编辑 / 可删 | 可改、可整体删 | 冻结，墓碑留存 |
| 语义 | 全新草稿 | 曾发布版本的墓碑 |

若把已撤回并入未发布，则他人已引用的版本会变回可编辑草稿、可被悄悄改写——破坏「不可变发布」与跨研究项引用完整性，并丢失「何时发布、何时因何下架」的审计。**继续工作的正确路径是开新版本 v+1**（前向演进），而非复用旧版本槽位。故保留四态。

### 8.3 两种「给别人用」：可撤销的团队 vs 不可逆的释放

|  | 私有 + 团队成员 | 共享 / 公开 |
|---|---|---|
| 怎么做 | 数据集保持私有，把人加进研究项（主研究项成员） | 把可见范围开放为共享 / 公开 |
| 能否收回 | **能**——随时移除成员、断其后续访问 | **不能真正收回**——已开放即等于把数据交出去，对方可能已复制（优盘可要回，已复制的数据要不回） |
| 适用 | 可控的内部协作 | 郑重的对外释放（类比论文发表） |

故可见范围**只升不降、不提供「取消共享」接口**：要可撤销 → 用私有 + 团队成员；要释放 → 接受其不可逆。这与 §4.2「不提供降级接口」一致。

## 9. 边界规则与权衡

| 编号 | 规则 / 权衡 | 结论 |
|---|---|---|
| **可见范围层级** | 三档取值与归属层级 | **资产级**（`DatasetAsset.visibility`）三档：私有 / 共享 / 公开。可见范围是数据集整体的属性，但只对该资产的**已发布版本**暴露；未发布版本恒为「仅主研究项可见」。（本条即原 Q-1 的关闭结论：可见范围已定为资产级三档，不再是未决项。） |
| **开放前置** | 纯未发布资产能否开放 | 不能。纯未发布资产恒私有，至少一个版本已发布后方可开放为共享 / 公开（无已发布内容可分享）。 |
| **唯一已发布版本被撤回后** | 可见范围是否回退 | 保持原值，**不自动改回私有**；非成员只看到墓碑（无可暴露的已发布版本）。 |
| **合规声明粒度** | 一次性还是每次 | **每次发布**都需重做脱敏 / 伦理 / 版权声明——每个已发布版本都是独立不可变制品（见 §6.5）。 |
| **私有发布的 DOI** | 私有是否铸 DOI | 铸。私有的已发布版本同样铸 DOI（解析到受限落地页），与「已发布不可删」一致（见 §6.6）。 |
| **授权的传递性** | 按用户授权是否外溢 | 授权控制「谁可发起关联」；数据集被关联进研究项后即成组内共享资源、其成员皆可用。「授权某用户」≈「信任该用户及其协作研究项」（见 §4.3）。 |
| **PI ≠ 负责人** | PI 是否有生命周期权限 | 无。生命周期权限**仅负责人**；研究项 PI 若非负责人，不能发布 / 授权 / 撤回本研究项内数据集——数据集强绑定到负责人个人。 |
| **DOI 实现** | 真接 DataCite 还是内部串 | 待定：先用内部类 DOI 字符串（`elys:dataset/{asset_id}/v{version}`）打通，真接 DataCite API 后续评估。 |
| **通知载体** | 站内 / 邮件 | 待定：撤回通知引用方，先站内通知，邮件后续按需补。 |
