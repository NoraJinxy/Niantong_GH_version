## 一句话

安全、可追溯、可维护已经在 v1 落地一部分；**性能、可用性、限流、备份**多数是生产前必补项。验收用指标说话，不写"高性能"这种空话。

## 1. 安全

| 项 | 当前 | 目标 |
|---|---|---|
| 登录 | 用户名 + 密码 + bcrypt + JWT | 加多因素 / 单点登录（仅作未来选项，不接 SSO/ORCID） |
| Token | access + refresh，前端存 `localStorage` | 切 HttpOnly cookie + CSRF |
| 算法 | HS256（默认） | 切 RS256 + 密钥轮换 |
| 鉴权 | 系统权限 + 研究项权限双层 | 增加细粒度操作日志 |
| 传输 | HTTP（备案前） | HTTPS（备案后 + TLS 1.3） |
| 数据存储 | 研究项数据目录鉴权 + DB / Redis 仅本机监听 | 加 DB 备份 + 增量备份策略 |
| 凭证 | 部署 SSH key 与人工 key 分离 | `SECRET_KEY` 轮换计划 |
| 合规 | 不写凭证到 wiki / 不开放外网 DB | 个人信息保护法 / 人类遗传资源管理条例 |

详见 [2-70 安全边界](2-70-安全边界与合规设计.md)。

## 3. 性能（验收指标 · 参考 wiki1）

| 场景 | 目标 | 当前 |
|---|---|---|
| 1 GB EEG 文件导入 | < 30 s | 同步阻塞，未压测 |
| 64 通道 × 10 min 数据 PSD | < 5 s | 未实现 |
| 64 通道 × 10 min ICA | < 60 s | 未实现 |
| 100 通道波形滚动 | ≥ 30 fps | 未实现（依赖未来 LOD + 二进制传输） |
| 单服务器并发分析会话 | ≥ 10 | 未做压测 |

> 这些都是 wiki1 给出的目标值，**当前尚未实测**。真正接入异步执行器后做基准。

## 4. 可用性

| 项 | 目标 |
|---|---|
| 系统可用率 | ≥ 99.5%（工作时间） |
| 故障恢复 | 服务重启 < 1 min；DB 备份每日 |
| 文档站点 | 可用率 ≥ 99%（静态站点，宝塔托管） |

## 6. 可扩展性

| 项 | 目标 |

| 多服务器 | 入口服 + 多计算服 horizontally 扩展（备案后切公司机房） |

## 7. 合规

- 符合 **个人信息保护法**、**人类遗传资源管理条例**。
- EEG 数据保留授权记录、脱敏记录。
- 公共数据使用保留 license、来源、引用。
- 数据**默认存本地**，不上传公有云；云端只存去标识化元数据。
