## 一句话现状

平台已经形成账号、研究项、数据导入、文件归档和工作流定义底座。算法执行、统计、科研作图、机器学习等能力仍在规划或静态预览阶段；需求文档必须清楚区分“已实现”和“建设目标”。

## 1. 产品目标

念析要解决科研级 EEG 工作中 **数据散、流程散、参数散、结果散** 的问题，把研究项、被试、原始数据、工作 FIF、分析流程、结果记录、统计和出图统一到可追溯 Web 工作台中。

产品价值不止是上传文件或运行脚本，而是让科研团队围绕同一套研究项数据、分析流程和结果记录长期协作。

## 3. 用户与场景

| 用户 | 关注点 | 典型场景 |
|---|---|---|
| PI / 管理者 | 研究项、成员、权限、结果可追溯 | 创建研究项、分配成员、审计数据流 |
| 研究员 | 数据导入、质控、分析流程复用 | 上传 BrainVision/EDF/BDF，生成 FIF，配置工作流 |
| 数据分析人员 | 参数、节点、批处理、结果输出 | 复用 Pipeline、比较分析结果 |
| 系统维护者 | 部署、备份、安全与容量 | 维护入口服、计算服、数据库和研究项数据目录 |

## 4. 模块优先级

| 优先级 | 模块 | 原因 |
|---|---|---|
| P0 底座 | M0 账号权限 · M1 数据管理 · M3 工作流基础 | 决定数据、权限和流程是否可追溯 |
| P1 主流程 | M2 质控 · M4 预处理 · M5 ERP/PSD/TFR | 最常用科研流程 |
| P2 增强 | M6 微状态 · M7 脑连接 · M8 溯源 · M10 统计 · M11 出图 | 增强科研分析与表达能力 |
| P3 智能 | M12 机器学习与 AI 辅助 | 依赖规范数据、规范结果和任务接口 |

## 5. 当前能力快照

| 维度 | 当前 |
|---|---|
| 后端路由 | 9 个 router：auth / dashboard / studies / datasets(资产·采集记录·挂载·文件·导入) / dataset_versions / pipelines |
| 数据库 | 用户、角色权限、研究项、成员、被试、采集记录(`recordings`)、上传版本、工作流定义与运行、结果、异步任务等表已落地（6 个 schema 文件） |
| 前端路由 | 登录、仪表盘、研究项、数据集管理、工作流、结果浏览、撤回审核、波形详情已接；其余观察、统计、作图、ML 多为静态预览 |
| 导入格式 | BrainVision / EDF / BDF，统一生成 canonical FIF（同步 + 异步 worker） |
| 工作流 | 8 个 NodeSpec 已注册（滤波 FIR/Butterworth/Notch 已合一为 `eeg/filter/apply`），Dispatcher 对全部 8 节点有真实 handler；预处理 / ICA / Epoch / ERP 可跑通 |
| 已实现模块 | M0 · M1 |
| 部分接入 | M2 · M3 · M4 · M5（执行器已接：滤波 / ICA / Epoch / ERP） |
| 规划模块 | M6 - M12 |
