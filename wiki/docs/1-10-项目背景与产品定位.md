## 一句话

念析是面向**科研级 EEG 团队**的数据 + 分析 + 协作平台，靠"研究项化数据治理 + 可追溯工作流 + 结构化协作入口"与单机脚本和公共数据平台错位竞争。

## 1. 背景问题

EEG 科研工作常见的不是单一工具缺失，而是**长期治理难**：

| 痛点 | 现状 |
|---|---|
| **工具碎片化** | 数据反复在 EEGLAB / FieldTrip / BrainVision Analyzer 等工具之间导出导入 |
| **复现性差** | GUI 操作难以精确记录和复现；参数靠口头或截图传递 |
| **本地绑定** | 商业软件依赖单机安装，无法远程协作 |
| **门槛高** | 需要掌握 MATLAB 或 Python 编程，非工程背景的研究者难入手 |
| **元数据散** | 原始数据格式多，实验元数据、行为数据、分析结果分散存放 |
| **追溯成本** | 论文出图、统计参数、预处理参数容易脱节，半年后回看难复现 |

## 2. 产品定位

| 维度 | 念析定位 |
|---|---|
| 目标用户 | 神经科学研究者 · 临床电生理医生 · BCI 开发者 |
| 使用场景 | 实验室日常分析 · 多中心协作 · 论文图表 · 临床辅助 |
| 核心价值 | **一站式 EEG 流程 + 降低门槛 + 提升复现性** |
| 技术差异化 | Web 端访问 + 本地计算保证数据安全 + Python/MNE 生态保证算法前沿 |
| 协作模式 | 研究项化、可审计、可委托给 AI 助手继续作业 |

念析不是"再写一个文件网盘"，也不是"再封装一次 MNE 脚本"。它是**围绕研究项数据、分析流程、派生产物和科研结果**建立协作闭环。

强调四件事：

1. **研究项化数据治理** — 12 位 Study ID 主键 + 数据目录隔离
2. **流程化 EEG 分析** — 节点 + DAG + 参数版本化
3. **结果 / 参数 / 版本可追溯** — `recording_versions` · `pipeline_executions` · 派生产物 lineage
4. **结构化协作入口** — 人 + LLM（Codex/Claude/Trae）共读同一套 wiki

## 3. 与同类产品的错位

| 产品类 | 强项 | 念析的差异 |
|---|---|---|
| OpenNeuro / 公共数据平台 | 数据开放共享、数据发现 | 念析做**私有研究项**数据管理；可以提供公共数据索引或示例，但核心是协作工作台 |
| EEGLAB / FieldTrip / MNE-Python（单机） | 算法丰富 | 念析在 MNE 之上加**流程治理 + Web 协作 + 结果追溯** |
| 商业临床软件（BrainVision Analyzer 等） | 临床合规 + 报告导出 | 念析面向科研，开放节点 / 脚本扩展，不绑定厂商 |
| 通用工作流（Airflow / Prefect） | 任务调度通用 | 念析的节点和数据模型**为 EEG / BIDS 量身设计**，不是裸 DAG |

## 4. 念析的"必须做"与"必不做"

| 必须做 | 必不做 |
|---|---|
| EEG 数据导入 + 治理（BrainVision/EDF/BDF）| 实时 EEG 采集（不做硬件接管） |
| BIDS 兼容存储 + 派生产物 | 通用统计软件全功能替代（仅内置 EEG 常用方法） |
| 可视化工作流（LiteGraph + NodeSpec） | MRI / fMRI 处理（仅支持溯源时的 MRI 模板） |
| 团队协作 + RBAC | SSO / ORCID / 机构统一身份（不接） |
| 结果版本与可追溯 | 一次性脚本运行 |
| 与 LLM 协同的 wiki 体系 | 全自动"AI 写论文"（AI 只做辅助、不抢决策权） |

## 5. 长期产品判断

- 短期（v1）：在"私有研究项 + 团队协作 + 可追溯流程"上建立壁垒，**不与公共数据平台正面竞争**。
- 中期（v2-v3）：开放节点市场、模板、示例数据；引入资源档位（PI / PI Plus / PI Pro）做商业化。
- 长期：成为科研团队 EEG 分析的"工作台 + 知识库 + AI 助手编排"统一入口。
