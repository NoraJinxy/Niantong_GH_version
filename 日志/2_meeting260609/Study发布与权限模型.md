## 3. 目标模型（爸爸提议，0609 演进）

- 发布**两级**：**Dataset**（原始数据）+ **Study**（研究项全貌）
- **Output 无 publish 轴**，可见性继承所属 Study
- **Study 可独立发布**（不强制先发 dataset）= 公开 工作流（方法）+ 结果（output）+ 数据引用关系；别人可**加载（引用）**其结果
- **原始数据内容公不公开，由各 dataset 自己的 `visibility` 决定**（解 B4 隐私）
- **可复现性分档**：数据公开 → ✅ 可重跑验证；数据私有 → 📊 仅可引用结果、不可重跑

## 4. 核心原则

| # | 原则 | 说明 |
|---|---|---|
| **P1** | **向下取齐（精确化，0609）** | 不阻止 study 发布；只挡**数据内容**——私有 dataset 的脑电数据不因 study 公开而泄露，访问者只见引用关系 + 非敏感元信息。安全性保留、实用性提升 |

| **P3** | **加载 = 引用，非拷贝** | 单一事实源；撤回则引用失效 |
| **P4** | **撤回需审核 + 断引用** | 见 §6 |

## 6. 撤回讨论（爸爸点名："什么时候才能撤回"）

撤回（withdraw）破坏性强——**断掉所有引用方**。所以不能随意撤。
**复用 Dataset 现成流程**：`withdraw_requested`（撤回审核中）→ `withdrawn`（已撤回），Study 对齐。

**什么时候"才能"撤回——按理由分级：**

| 撤回理由 | 处理 |
|---|---|
| 伦理 / 隐私 / 法律（事后发现） | **最高优先，快速批准、强制撤**，引用立即失效 |
| 数据有错 / 要更新 | **引导发新版本**而非撤回——旧版留给已有引用，新引用用新版（像 dataset 版本化） |
| "我不想公开了"（无正当理由 + 有人引用） | **谨慎、高门槛**：类比论文发表后不能随便撤稿；走审核 + 宽限期 |

**建议流程**：申请撤回 → 审核 → **通知所有引用方** → 宽限期（如 30 天）→ 生效。给引用方时间重跑 / 找替代 / 导出。

> ⚠️ **关键红线**：撤回断的是「**新引用 + 重跑时的解析**」；**引用方已经算完的结果（他们自己的 output）不受影响**——否则撤回会摧毁别人已发表的工作。这条必须明确。

## 7. 建设性意见 / 要补的待厘清点（我提）

| # | 点 | 说明 |
|---|---|---|
| **B1** | **动态一致性** | study public 后，依赖的某 dataset 被撤回 public 怎么办？必须联动：要么**阻止被引用的 dataset 撤回**、要么 study **自动降级**。这是"向下取齐"的动态维护成本，不能只在发布那一刻查一次 |
| **B2** | **活体 vs 快照** | study 是活的（owner 继续改），发布的是当前快照还是冻结？建议：**发布 = 冻结一个快照版本**（像 dataset version），owner 在工作版本继续改、要重新发布。否则"发布的 study 一直在变"对引用方不稳定 |
| **B3** | **发布单位** | study 里有试跑垃圾、失败 execution、缓存——一刀全公开会暴露这些。建议发布只含 **keep 的结果 + active pipeline + 引用的数据**，不含试跑 / 失败 / 缓存 |
| **B4** | **隐私张力** ✅ **已解（0609）** | 由「study 可独立发布、数据内容自决」解决（§3/§5）：隐私数据的 study 也能发，只公开方法+结果，原始数据按 dataset `visibility` 不公开。**新代价**：数据私有则该 study 不可复现（仅可引用结果）——已纳入"可复现性分档" |
| **B5** | **谁能发布** | owner 发起 + admin 审核（P1 的 admin 确认前置数据集）。审核流程要设计 |
| **B6** | **公开结果勿含个体隐私** | 数据私有但结果公开时，要确保 output 本身不可重识别——聚合结果（ERP / 统计）安全；**单试次 / 重建连续数据可能反推个体**（EEG 可重识别性）。发布前对个体级 output 应提示 / 拦截 |
