## 0. 本轮 5 项决策（2026-06-09）

1. **「已发布·私有」亦不可删** —— 已发布（含私有）一律只能撤回，不能删除；仅未发布可删。
2. **共享授权对象 = 用户** —— `dataset_members` 按用户授权（非按研究项）。
3. **发布 / 授权 / 撤回 = 仅负责人** —— 不含创建者 / PI / 编辑；管理员仅保留撤回审核、紧急下架、隔离等平台治理职责。
4. **发布为 PII / 伦理 / 版权关口** —— 未发布→已发布时强制勾选「已脱敏」确认，并声明伦理与版权，否则不能发布。
5. **撤回审核中禁止新关联** —— 已有关联保留，但不接受新关联（修正现有代码「允许新挂载」的行为）。

此前已附带决定（同批清理）：资产状态 `dataset_assets.status` 的 `working` / `active` 合并（`active` 实际几乎不生效）；版本旧字段 `dataset_versions.status`（已被 `state` 取代）清理。

> 「未发布」态在现有代码中以旧枚举值表示，**全栈统一为 `unpublished`**（含数据库 CHECK、接口返回值、前端判断与显示文案，详见 §5）。
> **「导入 / 关联 / 加载」三件事别混**（详见 §8.1）：导入 = 外部文件进平台造数据集；关联 = 研究项接上已有数据集（数据不搬动）；加载 = Pipeline 的 LoadData 节点运行时读数据。三者中英文均不混用。

### 1.2 两根正交轴（概念模型）

- **发布状态轴**（版本级 `DatasetVersion.state`）：决定能否修改 / 删除、是否冻结、是否已铸 DOI。
- **可见范围轴**（资产级 `DatasetAsset.visibility`）：决定谁可见、谁可关联。
- **第三轴（内部记账）`DatasetAsset.status`**：working / archived / deleted / quarantined，不作界面徽章；working / active 已决定合并。
- **核心原则：发布 ≠ 分享。** 发布仅冻结并铸 DOI，可见范围**默认私有、不自动转共享**；是否对外可见，由负责人在发布后单独决定。
- **平台前提：所有用户均为注册账户**，未注册仅可见主页等公开信息、不触及任何数据集；故三档可见范围全在登录边界内，「公开」= 全平台注册用户，**无匿名访问**。

### 1.3 发布状态轴 · 权限

| 发布状态 | 文件可改 | 能删? | 出口动作（谁） |
|---|---|---|---|
| 未发布 `unpublished` | ✅ | ✅ **整体删除**（负责人） | 发布 / 删除 |
| 已发布 `published` | ❌ 冻结 | ❌ 只能撤回 | 开放可见范围↑ / 申请撤回 / 开新版 |
| 撤回审核中 `withdraw_requested` | ❌ | ❌ | 管理员批准 / 驳回 |
| 已撤回 `withdrawn`（终态） | ❌ | ❌ | 仅可开新版本前进 |

### 1.4 可见范围轴 · 权限（开放度逐级提高，**仅暴露已发布版本**）

| 可见范围 | 谁能读 | 谁能关联到自己研究项 | 谁来设 |
|---|---|---|---|
| 私有 `private`（发布默认） | 负责人 / 管理员 / **主研究项成员** | 仅主研究项 | 发布即此档 |
| 共享 `shared`（邀请制） | ＋ 负责人**按用户**授权的人 | ＋ 被授权用户的研究项 | 负责人授权 |
| 公开 `public` | 任何注册（登录）用户 | 任何研究项 | 负责人 |

### 1.5 状态流转

| 从 → 到 | 谁 | 条件 |
|---|---|---|
| created → 未发布 | bootstrap | 建数据集即进入 |
| 未发布 → 已发布 | **仅负责人** | 填 SemVer；**强制脱敏确认＋伦理/版权声明**；可见范围默认私有 |
| 未发布 → 删除 | 负责人 | 该资产无任何已发布/已撤回版本，整体硬删 |
| 已发布 → 未发布(v+1) | 负责人 | 开新版；旧版本仍可用；同时只能一个进行中版本；v+1 可单独丢弃 |
| **可见范围开放** | 负责人 | **只升不降、无降级接口**：私有→共享/公开可跳级开放；不可逆释放（要可撤销协作改用私有 + 团队成员，见 §8.3） |
| 已发布 → 撤回审核中 | 负责人 | 必填理由 |
| 撤回审核中 → 已撤回 | 管理员 | 批准，通知所有引用方 |
| 撤回审核中 → 已发布 | 管理员 | 驳回，清空撤回字段 |
| 已发布 / 审核中 → 已撤回 | 管理员（紧急下架） | 跳审核、事后补审计 |

### 1.6 13 条规则（审核基准）

1. 两轴正交：发布状态轴管 可改/可删/冻结/DOI；可见范围轴管 谁能看/谁能关联。
2. 发布≠分享：发布只冻结+铸 DOI，可见范围默认私有、不自动转共享。
3. 发布为 PII/伦理/版权关口：发布强制脱敏确认＋伦理/版权声明。
4. 删除：未发布可整体删除；已发布（含私有）一律不可删、只能撤回；已发布资产上的 v+1 未发布版本可单独丢弃。
5. 可见范围**只升不降、不提供降级接口**：私有→共享→公开可跳级开放，但任何降级都无入口。共享/公开 = 不可逆释放；要可撤销的协作请用私有 + 团队成员（见 §8.3）。
6. 私有 = 负责人 + 管理员 + 主研究项成员可见。
7. 共享 = 邀请制：负责人按用户授权（`dataset_members`），仅被授权者可读/可关联。**非「任何登录用户可见」。**
8. 公开 = 任何**注册（登录）用户**可读 / 任何研究项可关联（平台无匿名访问；未注册仅见主页等公开信息，不涉及数据集）。
9. 操作权限：发布/授权/撤回申请 = 仅负责人；撤回审核 = 管理员；紧急下架 = 管理员。（`superadmin` 角色保留，用于**管理员管理 / 平台治理**，与数据集生命周期无关。）
10. 撤回审核中：禁止新关联；已有关联保留。
11. 已撤回 = 终态墓碑，禁新关联，只能开新版本前进。
12. 可见范围为资产级，但仅暴露已发布版本；未发布版本始终仅主研究项可见。
13. 关联网关：跨研究项关联要求 版本已发布 且 (公开 或 用户已被授权)；私有仅主研究项。

## 8. 关键辨析

### 8.1 「导入 Import」「关联 Link」「加载 Load」三件事

| | 导入 Import | 关联 Link | 加载 Load |
|---|---|---|---|
| 中文 / English | 导入 / Import | 关联 / Link | 加载 / Load |
| 代码 | `/recordings/import` | StudyDatasetMount | LoadData 节点 |
| 含义 | 外部文件（EDF/BDF…）进平台、造出数据集 | 研究项接上一个**已有**数据集、使其可用（数据不搬动） | Pipeline 的 LoadData 节点**运行时**把数据读入流程 |
| 心理图像 | 文件从外面进来 | 两个东西连根线 | 跑的时候把数据读进来 |

取舍：原「挂载 Mount」对医生 / 心理学背景用户偏术语，改用更友好的**「关联 Link」**；**「加载 Load」专留给** Pipeline 的 LoadData 节点（本就叫 Load Data）。三个词中英一一对应、互不混用。代码标识 `StudyDatasetMount` / `mount` 内部可暂留（用户不可见）。

### 8.2 「已撤回」不并入「未发布」（保留四态）

| | 未发布 Unpublished | 已撤回 Withdrawn |
|---|---|---|
| 是否曾发布 | 否 | 是 |
| DOI / 引用 | 无 | 有，须永久保留 |
| 可编辑 / 可删 | 可改、可整体删 | 冻结，墓碑留存 |
| 语义 | 全新草稿 | 曾发布版本的墓碑 |

若把已撤回并入未发布，则他人已引用的版本会变回可编辑草稿、可被悄悄改写——破坏「不可变发布」与跨研究项引用完整性，并丢失「何时发布、何时因何下架」的审计。**继续工作的正确路径是开新版本 v+1**（前向演进），而非复用旧版本槽位。故保留四态。

### 8.3 两种「给别人用」是不同的事：可撤销的团队 vs 不可逆的释放

| | 私有 + 团队成员 | 共享 / 公开 |
|---|---|---|
| 怎么做 | 数据集保持私有，把人加进研究项（主研究项成员） | 把可见范围开放为共享 / 公开 |
| 能否收回 | **能**——随时移除成员、断其后续访问 | **不能真正收回**——已开放即等于把数据交出去，对方可能已复制（优盘可要回，已复制的数据要不回） |
| 适用 | 可控的内部协作 | 郑重的对外释放（类比论文发表） |

故可见范围**只升不降、不提供「取消共享」接口**：要可撤销 → 用私有 + 团队成员；要释放 → 接受其不可逆。这与 §6-E「不提供降级接口」一致。

## 9. 进一步梳理：新发现的待决项与边界规则

三处冲突之外，本轮深查又发现以下问题。**9.1**（H、I，已决策）；**9.2 为边界规则**（已给建议，可采纳或否决）。

### 9.1 H、I（已决策）

**H. 「按用户授权」与「研究项共享关联」的权限外溢** —— ✅ **已定：选 a**。授权控制「谁可发起关联」；数据集一旦被关联进研究项，即成为该研究项的组内共享资源，其成员均可使用。即「授权某用户」≈「信任该用户及其协作研究项」——共享非逐人滴水不漏，会随被授权者带进其研究项。

**I. 「取消共享」** —— ✅ **已定：不提供降级接口**。可见范围严格单向、不可逆释放。
- **要可撤销地给特定人用** → 保持数据集**私有**，把人加进**研究项团队**（主研究项成员），随时可移除、断其后续访问。
- **共享 / 公开 = 把数据交出去**：开放即不可逆——优盘可以要回，但对方可能已复制，无法真正收回。故不设「取消共享」入口，以免给出做不到的承诺。
- 详见 §8.3「可撤销的团队 vs 不可逆的释放」。

### 9.2 边界规则（已给建议）

- **J. 开放可见范围需已有已发布版本**：纯未发布资产恒私有，不能开放为共享/公开（无已发布内容可分享）；至少一个版本已发布后方可开放。
- **K. 唯一已发布版本被撤回后**：资产可见范围保持原值，但非成员只看到墓碑（无可暴露的已发布版本），不自动改回私有。
- **L. 发布合规声明为「每次发布」**：每开新版本并发布都需重做脱敏/伦理/版权声明（每个已发布版本都是独立不可变制品），非一次性。
- **M. published+private 仍铸 DOI**：私有的已发布版本同样铸 DOI（解析到受限落地页，Zenodo 同模式），与「已发布不可删」一致；建议保留。
- **N. `can_read` 改造的连锁与性能**：签名加 `db` + 查主研究项成员 + 查 `dataset_members`，调用点众多（详情/列表/文件读取/关联），需用 join 避免 N+1；属实现注意项。
- **O. PI ≠ 负责人则无数据集生命周期权限**：按「仅负责人」决策，研究项 PI 若非负责人，不能发布/授权/撤回本研究项内数据集（与 §6-D 相关）；即数据集强绑定到负责人个人，须确认可接受。
