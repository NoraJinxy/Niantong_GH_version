### P3 · retention 三层解耦

| ID | 接线点 | 推荐 |
|---|---|---|
| P3-a | 「不写盘」与文件式节点传递冲突 | **照常写盘+登记行**，标 keep=false/cache_eligible=false/立即过期由 GC 清（「不写盘」降级为文档措辞）|
| P3-c | keep→false（取消保留）归宿 | **统一视同删除、走回收站**可反悔；PATCH schema 删掉 retention_expires_at 字段 |
| P3-d | 缓存命中复用旧行的 keep 对账 | keep = 旧值 OR 本次解析值；缓存行 expires 刷新（cache.py + dedup 两条路径都做）；删死函数 cache_retention_for_role |
| P3-e | P3 单独部署时 cache_eligible 取值 | **P3+P4 合并一次部署**（改动高度重叠）；若分步则 P3 过渡期沿用拓扑规则（intermediate→缓存+7天）|
| P3-f | 删 retention_status 后 cleanup 契约 | P3 内同步重写过滤为 `keep=false AND deleted_at IS NULL AND expires<now`，删请求体 retention_statuses；物理清盘留 P5 |
| P3-g~l | 删除/恢复走 DELETE+restore 端点、TTL 7天、UI 开关并入双击面板、split 整节点一开关、grep 归零口径、草稿残键 strip 丢弃 | 全按推荐（详见审计）|

### P4 · 节点缓存评分

| ID | 接线点 | 推荐 |
|---|---|---|
| P4-a | 删 cache 块后 executor 门控失效 | 门控改调评分函数 `if not is_cache_eligible(spec): return None`，**与评分函数同次提交** |
| P4-b | node_hash 含 cache 块 | 从 hash 移除 cache 块；**compute_cost/footprint 绝不进 hash**（改权重不破缓存）|
| P4-c | interactive 节点（ica/apply）缓存 | 评分外**双保险**：interactive=true 强制 not-eligible，防缓存跳过 waiting_user_input |
| P4-d~k | 新建 cache_policy.py、STORAGE_WEIGHT 模块常量=2、缺标签默认不缓存、LoadData 删 cache 块、explosive 只接受不实现流式、评分写进 job metadata 可观测 | 全按推荐 |

### P5 · GC 清盘 + 回收站

| ID | 接线点 | 推荐 |
|---|---|---|
| P5-a | blocker 挡 GC 致缓存永不可清 | **input 快照行只作档案不挡 GC**，仅 running/queued execution 引用挡清盘；用户删 keep 仍全量拦截 |
| P5-b | 硬删 vs tombstone + sha256 唯一索引坑 | **硬删行 + dependency FK 改 SET NULL + 唯一索引加 `WHERE deleted_at IS NULL`**（顺带修回收站期重算撞约束的现行 bug）|
| P5-c | celery beat 不存在 | worker 命令加 `-B` 内嵌 beat（改 deploy.sh 一行）+ beat_schedule 周期 1 小时 + 新写全局 GC task(study_id=None)；水位用 `shutil.disk_usage` |
| P5-e | restore 端点「已有」实则 P3 砍掉了 | 新增 `POST /outputs/{id}/restore`（deleted_at→NULL 且 keep→true）|
| P5-h | cleanup 是「扩展」还是「重写」 | **重写**为单一 run_storage_gc 两阶段（缓存到期清 / 回收站到期清），废弃旧软删中转 |
| P5-g/i | 全局 admin GC 端点(has_role admin)、回收站 UI 并入 ResultsPage「结果\|回收站」视图、purge_at 服务端下发 | 全按推荐 |

## C. 非阻塞（已代决，摘要）

- **G-a commit 粒度**：每个 P ≥1 commit，P2 单枚原子，P3 拆「DDL+后端」「前端」两枚；git add 按路径白名单，**永不 add `_old/`**（submodule 常驻脏）
- **W-a wiki 节奏**：每个 P 完成追加 `9-02` 明细一条 + mkdocs build；规范/总览页留 P7 一把
- **F-a 失败处置**：**fail-stop**——静态失败本阶段重试（封顶）；云端失败停在该 P、保留 commit 不 revert、写失败交接等人；线性依赖不许带病往下
- **G-b 收尾合并**：**不自动合 master**，停在 feature 分支等人工验收
- **V-a 本地 pytest**：建议 backend 建 .venv 装 pytest，跑 save_settings/node_hash/cache_policy 无 DB 子集（把验证从「语法」提到「逻辑」）
- **P0-c 云端验证自动化**：P3 动手前给 `run.py` 补退出码断言（status!=completed→exit 1；P3 后加「末端 keep=true / 仅 ica cached」断言），自动化直调 venv python 绕过交互 cmd
