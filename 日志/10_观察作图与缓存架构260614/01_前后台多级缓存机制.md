## 0. 一句话目标

讲清 Niantong 缓存的**两个正交世界**（节点结果缓存 / 绘图数据缓存），逐层拆解键、淘汰、命中与端到端流，并定出 elys「**搬哪些、怎么搬、改什么**」。

---

## 1. 心智模型：两个正交的缓存世界

很多人误以为缓存是一栈。实际是**两套互不相干**的缓存，搞混就理不顺：

| | 世界① 节点结果缓存 | 世界② 绘图数据缓存 |
|---|---|---|
| 缓存什么 | 流水线每个节点的产物（Raw/Epochs/Evoked/TFR/ICA 对象） | 绘图用的波形/像素切片（窗口/TFR切片/ICA成分） |
| 缓存键 | **`trace_code`** 四元组字符串 | **`parts` 数组**（去时间戳后） |
| 跨前后端 | **是**（前端判定 + 后端持久） | **否**（纯前端三级瀑布；后端只出原始数据不缓存波形） |
| 目的 | 增量执行：改一个节点只重算它和下游 | 绘图秒开：平移/缩放/换通道不重复请求 |
| 决策权 | **100% 在前端**；后端是无状态查表器 | 前端自查瀑布 |

唯一接缝：**节点重算 → 新 dataId → 绘图层凭新 id 重走世界②的瀑布**（§4）。

## 2. 世界① 节点结果缓存（trace_code，跨前后端）

### 2.1 缓存键 = trace_code 四元组

`trace_code = D{数据码}_N{节点类型码}_P{参数码}_I{上游码}`——把数据处理血缘（provenance，"这份数据是哪个文件、过哪个节点、什么参数、什么上游"）**烧进缓存键**。构造在前端 `../../Niantong-eeg-analysis/frontend/js/core/PipelineRun.js`（`generateNodeTraceCode` ~660-772）：

- **D 段**：load data 取选中文件签名 hash；下游节点**继承上游 D 段**（`tc.split('_')[0]`）→ 数据指纹沿管线传播。
- **N 段**：节点类型 hash。
- **P 段**：只取「稳定参数」（剔除 `executed/output/_*/status/progress/timestamp` 等动态字段，再对 key 排序后序列化）→ 根治「参数没改也判变」。
- **I 段**：所有上游 hash 合并再 hash → 上游一变，下游必变。

> 文档 `../../Niantong-eeg-analysis/docs/TRACEABLE_CODE_SYSTEM.md`。后端另有等价 md5 版 `generate_node_hash`（`pipeline_cache_manager.py` ~1477），但**只服务 `/generate_*_hash` 端点，不参与命中**——命中只认 trace_code 字符串。

### 2.2 后端四层（生命周期各不同）

| 层 | 存储 | 存什么 | 关键文件 | 生命周期 |
|---|---|---|---|---|
| **A 主力** | 磁盘 `DATA/<user>/<project>/1_processing/...` + `node_output_registry.json` | 节点产出 `.fif/.h5` 实体 + `_node_meta_<trace>.json` | 持久（随项目数据） |
| B | 磁盘 `trace_cache/<trace>.json` | 轻量 JSON 元数据（不含大对象） | 持久 |
| C（默认关） | `/tmp/...` | 旧 session/node JSON+FIF | 会话级；`EEG_ENABLE_SESSION_CACHE` 默认 `0` |
| D | 进程内存 `session.variables` | 活的 MNE 对象 | 进程内，24h 闲置清 |

要点：**实体落盘的是「Save Node Output」**（`session_manager.py` `save_to_bids_derivatives` ~1591），且**只有用户勾了 `if_save=True` 才落盘**；cache manager 只「事后登记」。文件名带 `_<trace_code>` 后缀 → **改参数后新产物不覆盖旧产物**（这也是磁盘只增不减的根因，见 §7）。

### 2.3 命中判定：乐观登记、悲观校验

后端 `find_node_output_by_hash`（`pipeline_cache_manager.py` ~938）三道闸：

1. 注册表有 `registry[trace_code]`？否 → MISS；
2. `node_hash` 二次校验（前端**故意传 null** 跳过，押注 trace_code 唯一性）；
3. `_node_meta_<trace>.json` 在磁盘？否 → 删注册项 + MISS；
4. 所有 `.fif/.h5` 产物都在？缺任一 → 删注册项 + MISS。

三级 fallback：语义 fallback（同 `D_N_P` 前三段，限 reference/ICA 类）→ node_type 别名 fallback（重命名兼容）→ 退全局注册表。

**反直觉点**：后端没有「重算」概念。`hit:false` 只意味「产物不在」，由前端决定重算。后端 = 纯「内容寻址存储 + 按需 rehydrate」。

### 2.4 前端节点缓存（只存引用）

前端 `PipelineCacheManager.js` 的 `nodeCache`（Map）→ sessionStorage(`eeg_pipeline_cache`) → `POST /api/pipeline/cache/sync`。**只存 `output_id`/`data_info` 引用，不存大数组**——本质是「哪个 trace 对应哪个后端产物 id」的索引。

### 2.5 端到端：改一个节点参数怎么走

管线 `LoadData → Filter → Epoch → Average`，只改 Filter 高通频率：

```
LoadData：P段没变 + 运行态匹配 → reuseRuntimeNodeOutput 复用内存 Raw，不碰后端
Filter（被改）：hasParamChanged=true（只比 P 段 split('_')[2]）
   → 先乐观问后端 POST /api/pipeline/cache/find_node_output {trace_code:新, node_hash:null}
       (a) 命中（以前跑过这套新参数 + 文件还在）→ .fif 回灌内存，不重算
       (b) 未命中 → invalidateDownstreamForParameterChange：Epoch/Average 全标脏并清缓存
                  → 真调算子重算 Filter → 勾了 Save 就落盘+register
Epoch：被标脏 → 重算
Average：hasUpstreamChanged（上游在 nodesToExecute）→ 重算
净效果：LoadData 零成本；Filter+下游重算 = 「改 1 节点只重算它和下游」
```

### 2.6 增量执行内核

`invalidateDownstreamForParameterChange` + `getDownstreamNodes`（BFS 顺连接）+ `nodesToExecute` 集合 + `hasUpstreamChanged`。脏标记沿拓扑下传；**数学保证 = trace_code 的 I 段**：上游重算→上游 trace 变→下游 I 段变→下游 trace 变→下游必 MISS。无需逐层显式传播。

> 设计文档：`../../Niantong-eeg-analysis/docs/INCREMENTAL_PIPELINE_EXECUTION_GUIDE.md`。注意 Niantong 里增量执行有**三套并行实现 + 补丁层**，真正接生产的是 `PipelineRun.js` 内联版——elys 只吸收这一套，别把历史层也搬过来。

## 3. 世界② 绘图数据缓存（纯前端三级瀑布）

### 3.1 五层 + cache key

| 层 | 介质 | 存什么 | 上限 | 跨刷新 | cache key |
|---|---|---|---|---|---|
| L1 | JS Map | 解码后 EEG 窗口 | 24 窗 | 否 | `start6\|stop6\|picks\|decodeMode` |
| L2 | JS Map | 哈希分块（不重传） | 240 块 | 否 | 块 SHA1 |
| **L3 地基** | **IndexedDB** | EEG/TFR/ICA payload | ~GB（保留≥500MB空闲） | **是** | `[ns, normalizePlotDataId(id), …]` |
| L4 | sessionStorage | 数据集摘要元信息 | TTL 60s | 60s 内 | `EEG_SUMMARY_CACHE:session:data` |
| L5 | JS 对象 | ERP 绘图态 + 覆盖式切片复用 | 60MB | 否 | `type:key` 命名空间 |

关键技巧 `normalizePlotDataId`：把 dataId 里 **≥9 位的纯数字段（时间戳）剔掉**再拼 → 同数据集不同 run/时间戳仍命中同持久键（跨会话复用）；前缀带版本号（`eeg-window-v2-...`）→ 改语义即一刀切失效旧持久缓存。

> ⚠️ Niantong 配套文档 `DATA_INTERACTION_AND_CACHE_MECHANISM.md` 画的是「四层」，**漏了最重磅的 L3 IndexedDB**（唯一跨刷新、GB 级，整套地基）。elys 文档别跟着漏。

### 3.2 UnifiedPlotCacheAccess 三级瀑布（设计最干净的一块）

`cacheFirstLoad`：**内存 → IndexedDB → 网络**：
1. 内存命中 → `{source:memory}`；
2. IndexedDB 命中 → 回填内存 → `{source:indexeddb}`；
3. 全 miss → 网络 → 同时回填内存 + 异步回填 IDB → `{source:network}`。

EEG/TFR/ICA 三通道共用同一个 IndexedDB 库 + 同一内存预算，靠 parts 第一段 namespace 区分。**「缓存优先」只实现一次**，各通道只提供「如何读写自己内存 Map」「如何发网请」。elys 应原样吸收这个抽象。

### 3.3 二进制 + Web Worker + 分块去重

- 自定义二进制协议：magic `EEGBIN01` + JSON 头 + float32/64 体（替代 JSON，省 60-70%）。
- 内容寻址分块：按时间块算 SHA1，客户端已有的块（`X-EEG-Known-Hashes`）服务端不再下发，只传新块 + manifest。
- Web Worker 零拷贝解码（3 模式：窗口/TFR/ICA），transferable 移交，主线程 fallback；还在 worker 内直接算 uPlot 堆叠偏移。

### 3.4 预取 / 去抖 / 覆盖式复用

- 预取（生产版）：EEG 沿**时间轴**、TFR 沿**通道维**，手写 `requestIdleCallback` 空闲拉数据塞满 L1+L3；token/planKey/idle-slot 三件套，`document.hidden`/去抖期间暂停。
- 去抖：交互 150ms 合并请求。
- 覆盖式复用（L5）：请求小时间窗时若大窗已缓存，现切一段不发网请。

> 注意：`SmartDataCache.js`/`PrefetchManager.js`（文档大书特书的「行为预测/网络自适应智能预取」）**仅被 example 引用、未接生产**，且 key 精度 `toFixed(3)` 与生产 `toFixed(6)` 不一致——elys **不要吸收这套**，走生产手写预取。

## 4. 两世界的接缝

节点重算后世界①拿到新 `dataId`（回灌进程内存 D 层），**不会把波形直接塞进绘图缓存**——前端节点缓存只存引用。要可视化时，绘图层（世界②）凭新 `dataId`/`tfr_id`/`ica_id` **重走瀑布**。

⚠️ **stale-pixels 风险**：L3 持久键用 `normalizePlotDataId` 剔时间戳，若新旧产物去时间戳后 dataId 相同且 start/stop/picks 不变，可能命中旧波形。Niantong 用 `forceNetwork`/`bypassCache` 旁路兜底——elys 须**确保每条「改参后重看」路径都带旁路**，否则数据新、像素旧（列入 §7）。

## 5. elys 接入方案：搬什么 / 怎么搬 / 改什么

### 5.1 世界②（绘图缓存）—— 高保真吸收

- **直接吸收**的抽象：`UnifiedPlotCacheAccess`(三级瀑布) + `PersistentPlotDataCache`(IndexedDB L3) + 二进制协议 + Web Worker 解码 + 生产预取(EEG时间轴/TFR通道) + 去抖 + L5 覆盖式复用。
- **Vue/TS 化**：
  - 缓存层是**纯 TS 模块**（非 Vue 组件），放 `src/composables/plotting/` 或 `src/lib/plotCache/`；Worker 用 Vite 原生 `new Worker(new URL('./decodeWorker.ts', import.meta.url), {type:'module'})`。
  - **绝不把大 TypedArray/ArrayBuffer 放进 Pinia/reactive**——会被响应式代理吞性能。缓存 Map/IndexedDB 句柄用 `markRaw`/模块级单例；组件持有用 `shallowRef`。
  - Pinia 只存「轻状态」（当前 dataId、选中通道、时间窗、source 标记），大数据走缓存模块。
- **不吸收**：`SmartDataCache`/`PrefetchManager`/`EEGVisualizationOptimizer`/`RenderOptimizer`（未接线存量）。

### 5.2 世界①（节点结果缓存）—— 吸收机制，对齐 elys 存储模型

- **吸收**：trace_code 四元组 + 增量执行（拆段比对 + 脏标记拓扑传染）+ 后端「无状态查表 + 按需 rehydrate」+ 悲观三闸命中。
- **对齐 elys**：Niantong 的「Save Node Output → `1_processing/<source>/sub-/ses-/...`」要映射到 **elys 现有存储布局与 StudyOutput**（见 memory `storage-layout-current-vs-target`、`dataset-study-domain-model`）。注册表 `node_output_registry.json` 在 elys 应落到哪、是否进 DB 索引——**待定**（§7）。
- **升级点**（吸收时顺手修 Niantong 的债）：
  - 前端弱 32-bit JS hash → elys 可统一用更强 hash（如 FNV/xxhash/SHA），降碰撞；
  - `node_hash=null` 跳校验的「宽松命中」要不要保留跨 session 复用、还是用强 hash 后恢复二次校验——**待定**（§7）。

### 5.3 接入分期

- **P1**：世界② 绘图缓存（让六视图秒开真实数据）——观察页落地的前提，随 [`./02`](./02_信号作图页.md)/[`./03`](./03_伪迹审核页.md)/[`./04`](./04_地形图与ICA成分页.md) 一起。
- **P2**：世界① 节点结果缓存 + 增量执行，对齐 StudyOutput；接 elys 流水线（litegraph）。
- **P3**：磁盘配额/清理策略产品化（见 §7 风险 2），disk_monitor 等价看板。

## 7. 风险与改进（吸收时要带着判断）

1. **弱 hash 碰撞 → 误命中**（真实正确性隐患）：前端 trace_code 各段 32-bit JS 字符串 hash + 后端默认跳过 md5 二次校验。理论上不同参数撞同 P 段 → 误取旧产物（靠文件存在性兜底，但不防内容错配）。**elys 改进**：换强 hash / 恢复二次校验。
2. **层 A 磁盘只增不减**（运维隐患）：产物带 `_<trace>` 后缀，每改参数+勾 Save 多一份几十 MB FIF；`cleanup_old_cache` 只扫 `cache_dir/*.json` 够不着实体。**elys 改进**：产物保留策略（按版本/LRU/手动）+ 配额看板。
3. **stale-pixels**（§4）：确保每条改参重看路径带 `forceNetwork`/`bypassCache`。
4. **三套预取/缓存冗余**：只吸收生产手写版，丢弃 SmartDataCache 系。
5. **文档失真**：Niantong 缓存文档漏 IndexedDB L3、代码示例是简化版——elys 文档以代码为准。
6. **重复缓存是设计非 bug**：同一结果同时在 D 层内存 + A 层磁盘 + B 层 JSON 元数据，三者生命周期不同、互为降级链（内存丢→读盘→读元数据），别当冗余删。
