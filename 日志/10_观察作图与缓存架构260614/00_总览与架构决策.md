## 0. 一句话目标

把 Niantong（早期静态 HTML+JS 形态）已经打磨得相当成熟的**六个观察作图视图**——时域(ERP/Raw 波形)、频域(频谱/PSD)、时频(TFR/CWT)、地形图(topomap)、ICA 成分、伪迹审核——**行为与布局极大吸收、配色与样式换成 elys 主体设计**地搬进 elys（Vue3），并在其上长出一个**论文级、可细粒度编辑、所见即所得出图**的作图模块。

## 3. 架构基石：两个平面 + 单一事实源 FigureSpec

发展作图模块的全部需求（论文级、自由度、前台细粒度元素编辑、后台所见即所得矢量/位图）能否同时成立，只取决于一个选择：**图的「事实」存在哪。**

### 3.1 两个平面（别用一套技术硬扛两件事）

| 平面 | 干什么 | 数据量 | 渲染技术 |
|---|---|---|---|
| **实时探索面** | 浏览原始 EEG、平移缩放、伪迹/ICA 审核 | 海量（几十导联×万点） | **Canvas / uPlot**（性能优先，非矢量） |
| **论文出图面** | 把降维结果排版成投稿图、细粒度编辑、出图 | 小（已聚合） | **SVG / D3 + FigureSpec**（矢量、元素可编辑、可导出） |

桥梁 = FigureSpec：在探索面「把此视图送去作图」= 把降维后的小数据快照成一份 FigureSpec。两平面共享 spec，渲染技术各取所需。

### 3.2 单一事实源 FigureSpec（所见即所得的唯一正解）

- **反模式**（Niantong 后端那段 matplotlib 出图就是死代码，正是踩过坑）：前台一套渲染、后台导出另一套（matplotlib/cairo）→ 字体/间距/kerning 必然漂移，**永远做不到所见即所得**。
- **正解**：图的唯一事实是一份**声明式场景图 `FigureSpec`（JSON）**：`figure → panels[] → {axes, scales, marks[], annotations[], theme}`。前台编辑改的是这份 spec，后台导出渲染的是**同一份 spec、同一套渲染器**。预览=导出。
- 顺带解决「细粒度元素操作」：spec 里每个可见元素（轴/刻度/显著性横杠/图例/子图）都是可寻址节点，前台选中=定位 spec 节点、拖拽=改属性、撤销重做=spec 历史快照；SVG 渲染让「点中哪个元素」由 DOM 事件免费提供。
- **导出链路**：矢量（PDF/SVG）= 前台 SVG 本体直接转；位图（PNG/TIFF，300–600 DPI、字体内嵌）= 后台 **headless 浏览器（Playwright）** 喂同一 FigureSpec 出图，像素吻合预览。

> 注：六个观察页**第一期不强制全部接入 FigureSpec**——它们先以「探索面」形态用 uPlot/Canvas 落地（吸收原版行为）；FigureSpec/出图编辑器是**作图模块第二期**的事，但**现在就把每个图的渲染拆成「可被 FigureSpec 复用的渲染器」**，避免二期返工（尤其 topomap 渲染器，见 [`./04`](./04_地形图与ICA成分页.md)）。

## 4. 套件清单：需要几个、各干什么、必要性

| # | 套件 | 职责 | 必要性 | 效率/说明 |
|---|---|---|---|---|
| 1 | **uPlot** | 实时探索面 Canvas 时序（时域波形/ICA时序/概览带 + TFR 热图坐标外壳） | **必要** | 海量多通道时序唯一可行；现 elys 观察页是手绘 `<svg>` 假数据，撑不住真实数据 |
| 2 | **D3**（+ 可选 Observable Plot） | 论文出图面 SVG 引擎、自由度来源（scales/axes/shape/contour/legend） | **二期必要** | 论文怪癖（断轴/精确 mm·pt/显著性括号/子图编号/自定义 colormap）只能靠底层库；高层库会撞墙 |
| 3 | **litegraph.js**（npm，已有） | 流水线节点画布 | 已有，**与作图无关** | 不为作图新增；选型见 §5 |
| 4 | **jsPDF + svg2pdf.js** | 前端矢量导出（可选） | 可选 | 若导出全交后台 headless 浏览器，可不引 |
| 5 | **headless 浏览器（Playwright）** 后端 | WYSIWYG 高 DPI 位图/PDF | **二期必要（做后台出图就需要）** | 唯一保证像素吻合；更轻替代 `resvg`/`cairosvg` 但 webfont/滤镜可能漂移 |

**自研、无现成库**：FigureSpec 数据模型、交互编辑器（选择/拖拽/属性/撤销）、**topomap 插值**（照搬 Niantong 的 IDW + Canvas ImageData，等值线用 `d3-contour` 微包）。

**明确不要引**（效率/必要性双输）：
- **Konva / Fabric.js**：raster 场景图，与「矢量 SVG + 声明式 spec」路线对冲，还重；
- **Plotly / ECharts / Highcharts**：高层成品图，自由度被框死，论文怪癖搞不定，体积大；
- **后台 matplotlib 出图**：双渲染器漂移，违背 WYSIWYG。

> 净增量：一期只需 **uPlot**；二期作图模块再加 **D3 + 后端 headless 浏览器**（+ 可选 jsPDF）。其余要么已有、要么自研。

## 5. litegraph.js（npm）vs litegraph.min.js（Niantong 文件）—— elys 该用哪个

二者**是同一个库的两种分发方式**，不是两个东西。Niantong 的 `litegraph.min.js`(492KB) 是 0.7.16 的 CDN 打包文件；elys 的 [`litegraph.js@^0.7.18`](../../elys_project/frontend/elys-web/package.json) 是 npm 包（更新）。

| 维度 | npm `litegraph.js`（elys 现状，✅推荐） | 文件 `litegraph.min.js`（Niantong 旧法） |
|---|---|---|
| 加载 | ES import，Vite 打进统一 bundle | `<script>` 全局，污染 `window.LiteGraph` |
| 体积/效率 | 随主包 minify/tree-shake/code-split/hash 缓存 | 永远整包 492KB，无摇树 |
| 版本管理 | lockfile 锁定，`npm update` 升级 | 手动换文件 + `?v=` 手动破缓存 |
| TS 支持 | 类型可接入（vue-tsc 可查） | 无类型，全 `any` |
| 工程化 | HMR / 同源 / CSP 友好 | CDN→本地回退土法 |

**结论：elys 用且只用 npm 的 `litegraph.js`（现状即正确，别动）。** 搬 `litegraph.min.js` 进来零收益、纯倒退。

**额外提醒（非紧急）**：jagenjo 原版 `litegraph.js@0.7.x` 已多年少维护、类型薄。流水线编辑器继续长大后可考虑迁到维护活跃的 TS 分支（如 ComfyUI 团队 `@comfyorg/litegraph`）。现在不动，记着即可 → 列入 [`./05`](./05_待讨论问题清单.md)。

## 8. 总体路线（分期）

- **一期 · 探索面落地**：六视图按「吸收原版行为+布局、配色换 elys」用 uPlot/Canvas/SVG 复刻；接真实数据端点 + 多级缓存（[`./01`](./01_前后台多级缓存机制.md)）。交付物 = 可对真实 EEG 操作的观察页。
- **二期 · 作图模块**：引入 FigureSpec + D3 出图引擎 + 交互编辑器 + 后台 headless 出图；把探索面视图「送去作图」。交付物 = 论文级可编辑出图 + 矢量/位图导出。
- 每个视图的细分期见各自文档第 7 节。
