# 研究项页面 UX 优化 · 修改清单与决策（2026-06-15）

## 背景

对「研究项」页（`StudiesPage.vue` + 右栏 `StudyOverviewTab.vue`）做一次面向**临床用户**（医生 / 心理 / 神经科学家，非工程师）的体检式优化。

衡量尺子（沿用项目 persona 纲领）：**让脑电分析显得简单、专业，而不是暴露系统有多少零件。** 凡是只有工程师才懂、临床用户不必懂也不该懂的词与信息，要么换成人话，要么藏进渐进披露（「技术信息」折叠），要么直接删。

> 名词铺垫：**渐进披露 (progressive disclosure)** = 默认只露最关键信息，技术细节收进「展开才看」的折叠区，避免一上来就把用户淹没。

## 用户批示（本轮三条补充）

1. **`节点`保留**：用户认为"6 个节点"临床用户能理解，不改。
2. **`数据资产` → `数据集`**：前台页面**全局**替换。
3. **`缓存` / `临时`（结果状态）一律不暴露给用户**：结果只对用户区分「保存 / 不保存 / 已删除」，内部的缓存/临时态不进用户视野。
4. **顶部导航栏不动**：七个顶级项偏多属全站问题，本轮"说不动的就不动"。

## B. 结果状态：不再暴露「缓存 / 临时」

内部保留模型三态（`keep` 用户保留 / `cache_eligible` 系统缓存 / `deleted_at` 回收站）对用户收敛成 **保存 / 不保存 / 已删除**。共有三套重复的标签逻辑，统一口径：

| 文件 | 函数 / 位置 | 改法 |
|---|---|---|
| `views/study/StudyOverviewTab.vue` | `retentionStatusLabel` | 缓存/临时 → 「不保存」；非保存药丸配色转 muted |
| `views/ResultsPage.vue` | `retentionLabel` / `retentionBadgeClass` | 缓存/临时 → 「不保存」；徽章配色对齐已有筛选标签（筛选区本就叫"不保存"） |
| `views/ResultsPage.vue` | 详情「技术信息」折叠 | 删除「系统缓存 是/否」一行（内部态，临床无用） |
| `views/ResultsPage.vue` | 「更多」菜单 | "清理缓存 / 临时数据" → "清理未保存的结果" |
| `composables/pipeline/pipelineFormatters.ts` | `formatArtifactRetention` | 缓存/临时 → 「不保存」（共享 formatter，一处管多处） |
| `composables/pipeline/pipelineFormatters.spec.ts` | retention 断言 | 期望值同步为「不保存」 |

## C. 研究项页信息架构（StudiesPage + StudyOverviewTab）

- **C-1 副标题瘦身**：原两句堆砌"组织协作/质控/工作流/运行记录/数据资产/挂载"像 IT 系统说明书。改成一句暖话：「把数据、分析流程和结果按项目集中管理，并一眼看出每个项目下一步能做什么。」
- **C-2 搜索占位去英文**：「搜索名称、code 或描述」→「按名称或描述搜索」。
- **C-3 `挂载` → `关联`**：左栏空标签"未挂载数据集"→"未关联数据集"；右栏"已挂载的数据集"→"使用的数据集"；决策文案"导入或挂载数据集"→"导入或关联数据集"。
- **C-4 左栏列表行瘦身**：去掉与右栏详情重复的「挂载标签」和「数据/工作流/运行」三枚计数药丸（同一组数字一屏出现三遍），合并为**单枚阶段药丸**（待导入数据 / 待配置流程 / 运行中 / 可继续分析 / 同步中）。阶段对临床用户比裸计数更直观。
- **C-5 叙事顺序：保留工程师序（数据→流程→运行→结果）**：经用户确认，右栏卡片顺序仍为 研究进度 → 工作流与运行 → 结果——「建议下一步」决策卡留在研究进度卡底部、「结果」留在工作流与运行卡内，**不做**"决策卡置顶 / 结果前置"的临床序重排（曾实现后按用户要求回退）。
- **C-6 去掉重复的「进入工作区」**：详情页头部的"进入工作区"与决策卡按钮指向同一页，删头部那个、留决策卡那个（决策卡按钮随状态自适应，更聪明）；删除后"移入回收站"独占头部，降低误点主操作旁破坏性按钮的风险。
- **C-7 权限信息归位**：「研究进度」四宫格里的第 4 格（🔒「N 人 · 角色 · 可发起运行」）不属于"进度"，从进度网格移除；成员数 / 你的角色 / 是否可发起运行并入底部「元信息」。
- **C-8 存储配额下沉**：`存储配额(GB)` 是运维/计费概念，从「元信息」正文移进「技术信息」折叠，不占临床视野。
- **C-9 `重放` → `重跑`**：运行模式标签（`StudyOverviewTab` 本地映射 + 共享 `pipelineFormatters.formatExecutionMode` + `pipelineConstants` 选项），统一口径。
- **C-10 「使用的数据集」隐藏版本标签**：研究概览原显示 `v{版本标签}`（默认工作版本裸露成 `vworking`）+「可升级」⇡ 标记——版本是后台架构、临床用户在概览不需要也看不懂，整块拔掉，只留「数据集名 + N 名被试」。数据集管理页（Share / Lifecycle）仍走 `formatVersionLabel` 显示「工作版本」（那才是管版本的地方）。连带清掉变死的 `isMountUpgradable` 与 `.is-upgradable` / `.upgrade-marker` CSS。

## D. 结果数据类型去黑话（evoked 等 MNE 术语 → 大白话）

结果的 `data_type` 枚举此前直接显示原始值（`evoked` / `tfr` / `psd` / `ica` / `epochs` / `raw` / `filtered_raw` / `json`），对非神经科学背景用户是黑话。新增共享 `formatDataType()`（`pipelineFormatters.ts` + spec）映射成大白话：原始数据 / 滤波后数据 / 分段数据 / **ERP 波形**（evoked）/ 时频图（tfr）/ 功率谱（psd）/ ICA 成分 / 指标数据（json）（含预留 源定位 / 微状态 / 脑连接）；未知类型回退原文、不致空白。

- **只包显示文本**：研究概览「结果」列表（`StudyOverviewTab`）、结果页（`ResultsPage`）的类型标签 / 筛选 chip / 详情标签都改走 `formatDataType`。
- **不动逻辑**：筛选匹配（`d.data_type === …`）、按类路由（`observeRoute`）、下载文件名、`dataTypeClass` / `dataTypeIcon` 仍用原始枚举；`ResultsPage` 详情「技术信息」折叠里的「数据类型枚举」也保留原文（给排障看）。
- **保留**：`节点`、工作流 `v1` 版本号、BIDS 结果名（`sub-093_task-erp_…`）——是真实科学标识、神经科学语境通用，不属"后台架构"。

## 刻意不动（范围决策，避免误伤）

- **`节点`**：按用户批示保留。
- **顶部导航栏 / ✨ 图标**：全站问题，本轮不动。
- **admin / 数据集生命周期里的`审计`**：那是真实合规语境（审计日志、撤回留痕），合理保留；只删研究项页那条面向临床的"可查看结果和审计信息"。
- **`formatJobStatus` 的 `cached→缓存`**：那是**运行步骤状态**（该步走缓存未重跑），不是"结果状态"，且在工程向工作流页；按用户"（结果状态）"限定词不动。
- **节点拆分粒度 / 工作流编辑器内部术语**：超出本轮范围。
