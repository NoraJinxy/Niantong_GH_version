## 1. 摘要（TL;DR）

- **三根存储 → 两根**：数据归资产 `storage/datasets/{asset}/`，产物归研究项 `storage/studies/{study}/`；删 legacy `studies/{id}/` data_root 整支。
- **三条数据线**：A 原始（永久只读）、B 标准 FIF（可重建工作副本）、C 派生产物（按保留策略清理）。
- **修三大债**：① FIF 双写（一条记录落 10 文件，5 个是 fifdata 镜像）→ 单写 derivatives；② 一文件被索引 3 行（raw_source/original_upload/raw_bids_data）→ 一文件一行；③ raw_bids 幽灵 → 纯逻辑视图不落盘不入库。
- **状态两轴 + 粒度**：发布状态(未发布/已发布) × 可见性(私有/共享/公共) × 可见粒度(仅描述/数据本身)；**发布≠公开**；状态是 DB 标志不是目录；发布=冻结清单零复制。

## 3. 设计原则

1. **数据归资产，产物归研究项**：原始 + FIF 属 `DatasetAsset`；执行输出/派生/预览/导出属 `Study`。
2. **磁盘只存真实字节**：disk 只有 `sourcedata`（原件）+ `derivatives`（FIF + 真实 sidecar）。raw_bids 永不落盘。
3. **一物理文件 = 一索引行 = 一角色**：删同一字节的多角色重复行。
4. **一份 FIF、一个落点、一条指针**：取消双写，所有指针指向唯一 derivatives 副本。
5. **raw_bids 是计算视图**：BIDS 命名树由 `bids-tree` 现算；要 BIDS 包按需导出 `exports/`。
6. **状态是 DB 标志，不是目录**：私有/共享/发布 写库字段，权限在 API 层用「状态+成员」判定。

> 黑话铺垫：**资产**=用户视角的"数据集"，独立物理身份；**研究项**=拿数据集跑分析的工作空间；**sidecar**=BIDS 元数据小文件（`_channels.tsv` 通道、`_events.tsv` 事件、`_eeg.json` 采集参数）；**append-only**=只追加不改，新内容写新文件、旧文件永不动；**provenance**=来源记录（这份 FIF 从哪个原件、什么参数转来的）。

## 4. 数据集状态模型（发布状态 × 可见性 × 可见粒度）

> 2026-06-07 修订（取代"三态合一"旧稿）：状态不是单轴，而是 **两条正交轴 + 一个粒度**。"发布"管不可变性、"可见性"管谁能看，两者**解耦**——**发布 ≠ 公开**。取消 working/草稿 叫法，发布前统称"未发布"。

### 4.1 轴 A · 发布状态（管不可变性 / 生命周期）

| 状态 | 可变? | 含义 |
|---|---|---|
| **未发布 unpublished** | ✅ 可增删改 | 还在整理；**强制私有**（见轴 B） |
| **已发布 published** | ❌ 不可变 | 冻结快照、可引用、可注册 DOI；可见性转为**可自由配置** |
| **已撤回 withdrawn** | ❌ 终态 | 需管理员审核；保留墓碑（见 wiki 3-25） |

### 4.2 轴 B · 可见性范围（管谁能看）

| 范围 | 谁能看 | 何时可设 |
|---|---|---|
| **🔒 私有 private** | 仅 owner + 本研究项团队成员 | 任何时候（未发布时**锁定为此**） |
| **👥 共享 shared** | owner + 被授权协作者 / 研究项 | **仅已发布后** |
| **🌐 公共 public** | 所有人（可检索） | **仅已发布后** |

### 4.3 粒度 C · 可见程度（管能看多深；共享/公共才有意义）

| 粒度 | 别人能看到 | 别人不能 |
|---|---|---|
| **仅描述信息 metadata** | 名称 / 描述 / 被试数 / 任务 / 引用信息 / 存在性 | **下载或使用数据本身**（可"申请访问"） |
| **数据本身 data** | 描述 + 下载 / 使用原始数据与 FIF | — |

### 4.4 组合与铁律

```text
未发布  →  必然 私有 · 数据仅本研究项可用                （可变，建设期）
已发布  →  私有                                          （冻结，仅自己用的可引用版本）
        →  共享 + 仅描述  /  共享 + 数据本身              （给特定协作者，按粒度）
        →  公共 + 仅描述  /  公共 + 数据本身              （对所有人，按粒度）
```

1. **发布前只能私有**：未发布数据仅 owner + 本研究项团队可见可用，不能共享 / 公开。
2. **发布 ≠ 公开**：发布只做"冻结 + 可引用"，默认仍私有；之后 owner 再单独开可见性。
3. **可见性单向棘轮（owner）**：发布后 owner 可手动推进 私有→共享→公开（可跳级），**只进不退**、一旦开放不可自行收回（"曾公开"不可逆）；唯一"下架"是管理员审核的**撤回**（仅限重大问题，版本级终态，非可见性降级）。
4. **两层访问闸**：能看到"它存在 / 它的描述"（元数据闸）≠ 能"拿到数据"（数据闸）；后者需粒度 = 数据本身。

### 4.5 对各层的影响（本次修订重点）

**🗄️ 数据库**
- 回到两轴（"合并成单 state"旧设计**作废**）：
  - `dataset_versions.state` = 发布状态轴：`draft`(=未发布) / `published` / `withdrawn`（现 schema **已有，沿用**）。
  - `dataset_assets.visibility` = 可见性轴：`private` / `shared` / `public`（现 schema **已有，沿用**）。
- **新增字段** `dataset_assets.disclosure_level ∈ {metadata, data}`（可见粒度，默认 `metadata` 保守）——现 schema **无，需加**。
- **新增约束** `state=draft(未发布) ⟹ visibility=private`（service 强制，DB 可加 CHECK / 触发器）。
- 极致"不同人不同权限" → `dataset_members`（按收件人记范围 + 粒度），列 17 节 F-7 进阶；MVP 先用 asset 级 visibility + disclosure_level。

**⚙️ 后端**
- 发布接口：只冻结 + 可引用，**不动 visibility**（保持当前值，默认 private）。
- 可见性接口 `PATCH /dataset-assets/{id}` {visibility, disclosure_level}：**仅已发布后允许**；未发布想设 shared/public → 403。
- **两道访问闸**：
  - 元数据闸（看描述 / 存在）：owner、本研究项团队恒通；shared/public 对授权方通。
  - 数据闸（下载数据）：额外要求 `disclosure_level=data` 且在授权范围内——`/dataset-files/{id}/download`、`/bids-tree` 数据节点、打包下载都加此校验。
- 发现 / 列表接口：他人可见 = 已发布且对其可见的资产；metadata-only 返回描述、但 download 返回 403 +「可申请访问」。
- （可选）申请访问流程：metadata-only → 用户申请 → owner 批准 → 升级该用户的数据权。

**🖥️ 前端**
- 徽章拆两层：**发布状态**（未发布 / 已发布）+ **可见性**（🔒私有 / 👥共享 / 🌐公共）+ 粒度小标（仅描述 / 含数据）。
- 未发布态：可见性置灰锁定显示"私有（仅本研究项）"，主行动 = 发布。
- 已发布态：出现「分享设置」面板——选 私有 / 共享 / 公共 + 仅描述 / 数据本身 +（共享时）选协作者。
- 发布按钮文案：「发布（冻结为可引用版本）」，旁注"发布 ≠ 公开，可见性发布后单独设"。
- 他人视角：发现页对 metadata-only 显示描述卡 +「申请访问数据」；data 级直接可下载；2 桶对无数据权者显示"描述可见，数据无权 / 可申请"。

**📁 文件存储**
- **几乎零影响**：可见性 / 粒度是 DB + API 访问控制，**不改物理布局**，文件不因 private/shared/public 或 metadata/data 搬动。
- 唯一关联：发布仍写 `releases/v{semver}.json` 冻结清单（不可变边界在"发布"，不变）。
- metadata-only 的实现 = 数据文件**原地不动**，仅 download 端点按 `disclosure_level` 拒绝。
- 反证设计原则 6 成立——状态模型再复杂，存储层纹丝不动。

### 4.6 描述与元数据的可编辑性（2026-06-07 新增规则）

| 内容 | 未发布 | 已发布 |
|---|---|---|
| **描述信息** | ✅ 自由编辑 | 🔒 **只读**（冻结） |
| **补充信息（addenda）** | — | ✅ 可**追加**，但**需管理员审核**后才公开 |
| **负责人 / 出身 / 主研究项 / 使用许可** | ⛔ 不展示（私有草稿，无发表元数据） | ✅ 展示 |
| **如何引用 / DOI** | ⛔ 不展示 | ✅ 展示（多格式 + 复制） |
| **文件数 / 标准 FIF 数** | ✅ 概览只读展示 | ✅ 概览只读展示 |

规则要点：
1. **描述：发布前可改，发布后只读**——已发表元数据冻结，保证引用稳定（类比论文）。
2. **发布后仅可"追加补充信息"**（勘误 / 补充说明 / 新被试说明），且**走管理员审核**（复用撤回审核的 admin 流程，写 `audit_events`），审核通过才对外可见。
3. **发表元数据（出身/引用/许可）只在发布后出现**——未发布是私有草稿，没有这些面向外部的字段。
4. **文件数 + 标准 FIF 数在概览只读可见**——属"一览概要"一部分（借鉴 OpenNeuro 在 metadata 展示文件数），只读、不可在概览编辑。
5. **描述结构化**——描述不是一坨 blob，拆成「**摘要 / 采集方法 / 使用说明 / 伦理**」几段（借鉴 PhysioNet 的 Abstract / Methods / Usage Notes / Ethics），科研数据更专业可信；编辑 / 只读 / 追加规则同上，按段呈现。DB 用 `dataset_versions.metadata_json.description{abstract,methods,usage,ethics}` 结构化存储。

**各层增量影响**：
- 🗄️ DB：新增 `dataset_addenda`（或 `dataset_versions.metadata_json.addenda[]`）：`content / submitted_by / status(pending|approved|rejected) / reviewed_by / reviewed_at`。
- ⚙️ 后端：`PATCH 描述` 仅未发布允许（已发布 → 403）；`POST …/addenda`(status=pending) + 管理员 `POST …/addenda/{id}/review`。
- 🖥️ 前端：描述卡 未发布=「✎ 编辑」/ 已发布=「🔒只读 + ＋添加补充信息(需审核)」；出身/引用/许可块 `仅发布后`；概览加只读「文件 N · 标准 FIF N」行。
- 📁 文件存储：**零影响**（纯元数据 + 审核流，不碰文件）。

## 6. 数据线 A · 原始数据

### 6.1 生命周期关键规则

先把黑话钉死：**采集记录（recording）**=一个人做一次某任务采的一段脑电（subject/session/task/run 四件套唯一）；**记录版本（recording_version）**=这段脑电上传了第几回。

命运线：
```text
上传 → archive_uploads() 落盘（原样、原名、写新 upload-{seq}）
     → materialize_recording_import()：算 checksum 查重 → 转 FIF → 写库
     → subjects / recordings / recording_versions / dataset_files
```

四条规则：
1. **新的人/新任务 = 新建采集记录**：四件套有一不同就在 `recordings` 加一行。
2. **同段脑电重传 = 加版本不覆盖**：`recording_versions` 加 `version_seq`，旧版转 `replaced`，数据保留。
3. **原始文件只增不改（append-only）**：`archive_uploads` 永远写新 `upload-{seq}`，从不改/删旧文件。
4. **完全相同上传被指纹拦截**：入库前算合并 SHA-256，库里已有同指纹 → 409 不重复入库（datasets.py:2949）。

### 6.2 磁盘（目标）

```text
datasets/{asset_id}/sourcedata/original_uploads/sub-XXX/upload-{seq}/
  ├── manifest.json          ← 这批上传清单
  └── sub093.vhdr / .eeg / .vmrk   ← 原名保留，只读
```
（目录按被试归组，见 17 节 F-1 决策。）

### 6.3 数据库

| 表 | 对原始数据存什么 |
|---|---|
| `subjects` | 被试身份（sub-093）+ 年龄/性别/组别 |
| `recordings` | 主表：`source_path`（主原件）、`source_format`、`current_version_id` |
| `recording_versions` | 原始数据的版本：`source_dir`、`source_main_file`、`source_files`(JSON)、`status` |
| `dataset_files` | 文件索引：role=`original_upload`（**目标：一原件一行**） |

### 6.4 前端

- 📥 桶（文件管理器）：按被试/记录归组，可下载，标"永久保留"。
- 数据概要卡：被试数/任务/时长（用聚合字段，不数文件行）。

## 7. 数据线 B · 标准 FIF

### 7.1 定位（wiki 4-20 §4）

canonical FIF = **MNE-ready 工作副本，不是权威源**（权威是原件）。可懒生成、可按策略清理、可重建（只要原件 + 转换参数 + 转换器版本在）。

### 7.2 现状：双写（要修的核心债）

`generate_canonical_fif`（datasets.py:1929）对一条记录产出：

| 落点 | 文件 | 性质 |
|---|---|---|
| **derivatives（新）** | `_raw.fif` · `_eeg.json` · `_channels.tsv` · `_events.tsv` · `_provenance.json` | 应保留 |
| **fifdata（旧镜像）** | `_raw.fif` · `_eeg.json` · `_channels.tsv` · `_events.tsv` · `_import.json` | **应删** |

即**一条记录 10 个物理文件，5 个是 legacy 镜像**（`shutil.copy2`，代码注释 `legacy_mirror: True`）。且 `recordings.fif_path` 指向旧镜像，`dataset_files.canonical_fif` 指向新副本 → 指针分裂。

### 7.3 目标：单写 + 单指针

- 砍 `legacy_fif_base` / `legacy_*` / 镜像 copy2 段（datasets.py:2087-2104）；`ensure_fifdata_dataset_files` 下线。
- 只写 `derivatives/canonical-fif/`；`recordings.fif_path` 与 `dataset_files.canonical_fif.storage_uri` 同指这唯一副本。

### 7.4 磁盘（目标）

```text
datasets/{asset_id}/derivatives/canonical-fif/sub-XXX/[ses-XX/]eeg/
  ├── sub-XXX_task-YYY_eeg.fif        ← 标准 FIF（唯一副本）
  ├── sub-XXX_task-YYY_eeg.json       ← provenance
  └── sub-XXX_task-YYY_channels.tsv / _events.tsv / _eeg.json   ← 真实 sidecar
```

### 7.5 数据库

| role | 说明 |
|---|---|
| `canonical_fif` | 唯一 FIF，`recordings.fif_path` 同指 |
| `canonical_fif_provenance` | provenance.json |
| `sidecar`（channels/events/eeg_json） | 真实生成的 BIDS 元数据 |

### 7.6 前端

- ✨ 桶：可下载、标"可直接分析 / 可重建"。
- events.tsv/channels.tsv 不当"文件"卖，挪到采集记录的"事件/通道"详情或 QC（用户关心内容不关心文件）。

## 8. 数据线 C · 派生与研究项产物

### 8.1 归属

派生数据（清洗/epochs/ICA/ERP/图/报告）由 Pipeline 执行产出，**属研究项**，登记在 `derived_datasets` 表，落 `storage/studies/{study}/`。不进数据集文件管理器，在「派生数据/结果」页呈现。

### 8.2 磁盘（目标 = 现 STUDY_STORAGE_DIRECTORIES）

```text
studies/{study_id}/
  ├── executions/         ← Pipeline 每次运行工作区
  ├── derived/            ← 派生数据集
  ├── exports/            ← 按需导出（含 BIDS 包）
  ├── previews/           ← 预览图
  ├── temp/               ← 临时
```

## 21. 导入失败与回滚（健壮性）

import 是"先落盘再入库"，各阶段失败的处理（事实源 `materialize_recording_import` / `generate_canonical_fif`）：

| 阶段 | 失败表现 | 处理 |
|---|---|---|
| 落盘 `archive_uploads` | 路径重复 | 422，不入库 |
| 查重 | checksum 命中已有记录 | 409，写 `manifest.status=duplicate`，不入库 |
| 转换 `generate_canonical_fif` | 目录已存在 / MNE 读写失败 | 409 或抛错；**all-or-nothing 回滚**：已 move 的 canonical 目录 + legacy 目录一起 `rmtree`（datasets.py:2101-2104），避免"磁盘有目录、DB 无记录"的孤儿（孤儿会以 409 挡住后续同 seq 重试） |
| 写库 | DB 约束冲突 | 上层 rollback；磁盘文件靠上一步的回滚兜底 |
| 任意失败 | — | `manifest.update({status:failed, error})`（datasets.py:3434），保留排错日志 |

> **目标方案下回滚更简单**：取消 legacy 镜像后，回滚只需删 derivatives 一处，不再两处协调。

## 22. 重传与版本切换流程

同一条采集记录重传（事实源 `get_next_upload_seq` / materialize duplicate 分支）：

```text
1. get_next_upload_seq：取该 recording 的 max(version_seq)+1，并跳过磁盘已存在的 upload-{seq}
2. 新原件写新 sourcedata/.../upload-{seq}/（旧的不动 = append-only）
3. recording_versions 加一行 status=current；旧版 → replaced
4. recordings.current_version_id 指针挪到新版；source_path / fif_path 更新到新版
5. 新 FIF 写新 derivatives 目录；旧 FIF 随旧 recording_version 保留（可回滚）
6. 若新上传 checksum 与现有完全相同 → 409，不产生新版本
```

要点：重传**永不覆盖**旧版，错了能回滚；前端"采集记录"展开可看版本历史 v1/v2，标 current/replaced。

## 23. 挂载与跨研究项引用

研究项不"拥有"数据集，靠**挂载（mount）**引用（事实源 `study_dataset_mounts` + `/mounts` 端点）：

| 数据集状态 | 谁能挂载 | 锁定到 |
|---|---|---|
| 私有 | 仅主研究项 | live 数据 |
| 共享 | 被授权研究项 | live 数据 |
| 发布 | 任何研究项 | 具体 release 版本（`dataset_version_id`） |

- 引用登记：`dataset_version_references`（kind=mount / execution_input），**撤回时遍历此表通知引用方**（schema 已建）。
- Execution 输入冻结：`pipeline_execution_inputs` 启动时快照 `dataset_file_id/storage_uri/sha256`（4-70 §7）——历史执行不依赖"当前数据"，只依赖自己的输入快照。
- 删除保护：`study_dataset_mounts.dataset_asset_id ON DELETE RESTRICT`——被挂载的资产不能被直接删。

## 24. 审计与并发锁

- **审计**（`audit_events`，3-50 §1）：上传/重传/挂载/发布/撤回/紧急下架/清理/权限变更 **必留痕**，含 `event_scope` + `snapshot`。落地时 publish/withdraw/emergency/mount_upgrade 全覆盖。
- **并发锁**（`study_locks`，3-50 §1）：同一 Pipeline 同时一人编辑、一个 active Execution。
- **数据集并发**（新增考量）：私有/共享态可变，需防同一资产并发上传写乱 seq。建议：导入按 `recording` 粒度串行（`get_next_upload_seq` 已靠"目录存在则 +1"兜底冲突），必要时加资产级软锁。

## 25. bids-tree 投影逻辑（逻辑视图怎么算）

## 28. 页面信息架构与导航（状态自适应 tab）

> 2026-06-07 决定：tab 结构随**版本发布状态 + 角色**自适应——发布前=建设工具集，发布后=只读消费视图。

### 28.1 状态 × 角色 矩阵

| 视角 | 发布前（未发布·私有锁定） | 发布后（已发布） |
|---|---|---|
| **owner** | 概览 · 采集记录 · 导入 · 质控 + 概览「**发布**」按钮 | 概览 · 数据详情 + 概览「**管理/分享**」按钮（数据详情含质控报告段） |
| **协作者 editor** | 同 owner（可编辑），无发布按钮 | 概览 · 数据详情（只读） |
| **他人 · 公开+含数据** | 不可见 | 概览 · 数据详情（只读·可下载） |
| **他人 · 公开+仅描述** | 不可见 | 概览 +「**申请访问**」 |

### 28.2 关键规则

1. **tab 跟版本状态**：发布后「开新版本」→ 新草稿 → 该版本又回到"发布前"四 tab（导航随版本生命周期循环）。
2. **发布 = 概览里的按钮**（非 tab）：点击弹"发布前检查清单"modal（SemVer / 会冻结什么 / 发布≠公开 / 联动质控状态，不阻塞）。
3. **管理/分享 = 概览里的按钮**（发布后，owner-only）：设可见性 私有/共享/公共 + 粒度、申请撤回、开新版本、加补充信息。**位置与"发布"按钮一致**（概览右上），用户记住"治理动作永远在概览右上"。
4. **导航不蒸发**：发布后 采集记录/导入/质控 收纳进"数据详情"（子段/按钮），给过渡提示，不让用户找不到。
5. **质控双向可达**：质控状态在每条记录上有徽章，点徽章跳质控详情，避免信息孤岛。
6. **命名一致性（待定 F-15）**：发布前"采集记录" vs 发布后"数据详情"是同一份数据两个名——建议统一，或明确"数据详情 = 采集记录 + 文件 + 质控报告 的只读超集"。

### 28.3 各 tab / 区职责

- **概览**：科学名片（结构化描述 + 一览概要 + 文件数/FIF 只读 + 发布后:出身/引用/许可）+ 状态相关按钮（发布前=发布；发布后=管理/分享）。
- **采集记录（发布前）**：按被试浏览 + 管理，文件 2 桶展开，质控徽章。
- **导入（发布前）**：加数据；发布后消失（开新版本才回来）。
- **质控（发布前=tab / 发布后=数据详情内的段或按钮）**：质量总览（N 条·M 通过·K 待审）+ 按记录质控详情。
- **数据详情（发布后）**：采集记录 + 文件 + 质控报告 的只读合并视图（内部分段，避免单 tab 过载）。

> 决策补充：F-15 命名一致性（待拍板）；其余沿用 §3–§4.6 两轴模型与编辑规则。
