## 1. 一句话背景

数据集页面把后台结构原样端给用户（UUID / 路径 / sha256 / 三套状态轴），文件层又有真实债（FIF 双写、幽灵索引行、三根存储）。本轮重新设计了**存储两根 + 三条数据线 + 状态两轴棘轮 + 状态自适应 tab + OpenNeuro 式概览**，并已落地第一个后端批次。

## 2. 核心问题（为什么重构）

**文件 / 存储层（代码坐实的真债）**：
- **三根存储**：`storage/datasets/`、`storage/studies/`、legacy `studies/{id}/`（data_root）并存。
- **FIF 双写**：`generate_canonical_fif` 同一份 FIF 既写 `derivatives/elys-canonical-fif/` 又 `copy2` 一套到 legacy `fifdata/`——一条记录落 10 文件、5 个纯镜像（`ConversionParams.legacy_mirror=True`）。
- **一文件索引 3 行**：每个原件写 `raw_source`+`original_upload`+`raw_bids_data` 三行 → 计数虚胖（界面"原始上传 6"实为 3 文件×2 角色）。
- **raw_bids 是幽灵**：磁盘无 `raw_bids/` 文件夹，却有 `raw_bids_data` 索引行（指回原件）。
- **指针分裂**：`recordings.fif_path` 指旧 fifdata、`dataset_files.canonical_fif` 指新 derivatives。

**UI / 信息架构层**：
- 5 个 tab（概览/导入/采集记录/文件索引/技术信息）混了"读数据 / 写数据 / 调试"三种事。
- 概览被版本 / 发布机器压垮，真正的"数据概要"被挤到下面。
- 技术信息（UUID / 路径 / sha256 / 文件统计）默认暴露给不懂代码的脑电研究员。
- 三套状态轴（`status` / `visibility` / `version.state`）并列，用户要同时理解。

## 3. 已拍板的关键决策（设计基线）

> 详见 `文件管理目标方案.md` 对应章节；这里给结论。

1. **存储两根**（§3、§9）：数据归资产 `storage/datasets/{asset}/{sourcedata,derivatives,qc,releases}`；产物归研究项 `storage/studies/{study}/{executions,derived,exports,previews,temp}`。**删 legacy `studies/{id}/` data_root 整支**。
2. **三条数据线**（§5–8）：A 原始（永久只读）/ B 标准 FIF（可重建工作副本，可清理）/ C 派生（研究项产物，按 retention 清理）。数据集文件管理器只管 A+B。
3. **文件角色精简**（§10）：一物理文件 = 一行 = 一角色。删 `raw_source` / `raw_bids_*`；留 `original_upload` / `canonical_fif` / `canonical_fif_provenance` / `sidecar` / `qc_report`。
4. **raw_bids = 逻辑视图**（§11）：永不落盘、不入库；按 BIDS 浏览走 `GET /dataset-assets/{id}/bids-tree` 实时投影；要 BIDS 包按需导出 `exports/`。
5. **FIF 单写**（§6）：只写 derivatives，`recordings.fif_path` 与 `canonical_fif` 同指唯一副本。**（已落地，见第 4 节）**
6. **状态 = 两轴 + 棘轮（最终模型，§3/§4）**：
   - **发布状态轴**：未发布（可变·私有锁定）→ 已发布（不可变·可引用）→ [撤回]。
   - **可见性轴（owner，发布后）单向棘轮**：私有 → 共享 → 公开（可跳级），**只进不退、不可自行收回**。
   - **粒度**：仅描述 / 数据本身（metadata/data）。
   - **发布 ≠ 公开**：发布只冻结、保持 private、不动可见性。
   - **唯一"下架"**：管理员审核的撤回（重大问题，版本级终态，非可见性降级）。
7. **描述结构化 + 可编辑性**（§4.6）：描述拆「摘要/采集方法/使用说明/伦理」；发布前可编辑，发布后只读 + 可追加补充（需管理员审核）。
8. **状态自适应 tab（§28）**：发布前 = 概览/采集记录/导入/质控 + 概览「发布」按钮；发布后 = 概览/数据详情 + 概览「管理/分享」按钮（含质控段）。按 角色×状态 显隐。
9. **概览 = OpenNeuro 式科学名片**：数据概要（被试/任务/时长/模态/最近导入 + 文件数/FIF 只读）+ 结构化描述 + 出身/引用/许可（仅发布后）。已 web 调研 OpenNeuro/Zenodo/PhysioNet 验证（结论见 §3 调研对照，Sources 在对话）。

## 7. 必读的坑 / 警告（血泪）

1. **🩸 删 auto-share 不能单独做**：`_ensure_version_mountable`(dataset_assets.py:259-273) **只看 `version.state`、不看 `visibility`**。单删 `dataset_lifecycle.py:352-356` 的 auto private→shared 会让"已发布+private"仍被任意 Study 挂载 = **泄露**。必须与"挂载/访问按 visibility 判定"**同批**（Phase 2）。
2. **🩸 多 agent 发现要 adversarial verify**：四轨 agent 报过一个"安全漏洞"（can_write 参数反），实测是**会崩/误拒**不是"谁都能进"——定位准、严重性判断偏。agent 结论务必复核再采信。
3. **FIF conversion-dict 多消费方**：`generate_canonical_fif` 返回 dict 被 `create_dataset_upload_record`/`materialize_recording_import`/manifest/worker 多处消费，删键要同步否则 KeyError。
4. **T3↔T10 强耦合**：删 raw_bids 行 + bids-tree 改投影必须同批，否则 BIDS 视图断裂。
5. **T5 去 versions 层 = breaking**：`storage_uri` 是已落库字段，改格式波及 file_browser/dataset_bootstrap/worker，全仓 grep `versions/`+`elys://datasets` 再动。
6. **无 git + 无本地运行环境**：改动只能 py_compile，真验证在云端；没 git 没法 diff/回滚 → 见第 5 节②。
7. **同批部署窗口**：schema 改 + 后端代码必须同一批 DROP 重建 + deploy_remote，否则读不存在的列 / 写已删的列。
