## 10. 建议近期实施顺序

### 第一组：Pipeline / Run 语义收口

1. 新增 `POST /projects/{project_id}/pipelines/{pipeline_id}/runs` alias。
2. `PipelineRunCreate` 增加 `run_mode`、`save_policy`。
3. Run response 返回 `run_mode`、`save_policy`。
4. 运行前检查 Pipeline 状态：
   - `analysis` 只允许 `active`。
   - `trial` 可允许 `draft`。
   - `archived/deleted` 禁止运行。
5. validator 检查 NodeSpec 是否有 executor。
6. 文档把 Run 状态统一为 `completed`。

## 11. 当前结论

当前程序已经实现了主干：

```text
Dataset Asset / Study Mount
  -> Pipeline Definition
  -> Run Snapshot
  -> pipeline_run_inputs
  -> async_tasks/task_events
  -> node_runs
  -> artifacts
  -> run_manifest
  -> dependency-aware cleanup
```

但要符合当前最新产品定义，还需要优先补齐：

1. Pipeline/Run API 和状态语义收口。
2. `run_mode/save_policy` 真实进入 Run 创建。
3. Pipeline 状态运行规则。
4. Pipeline 编辑并发控制。
5. Task cancel/retry/SSE。
6. Dataset 导入和转换的真实异步化。
7. 文档中“当前实现”和“目标设计”的边界标注。

短期不建议做大规模表名和目录迁移。先把 API、状态、锁、任务和文档口径打硬，平台就能更稳地进入前端体验和真实部署回归阶段。
