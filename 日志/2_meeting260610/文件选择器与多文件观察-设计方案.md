# 文件选择器与多文件观察 · 设计方案

> 配套「研究项数据浏览器」（C 全屏方案）的文件选择 + 多文件对比观察。本文回答：用户怎么从一堆数据里挑出"想一起看的那几个文件"，以及挑选逻辑怎么复用 LoadData 那套。

---

## 1. 背景

C 全屏后，研究项的 `数据 / 工作流 / 结果` 三页都铺满。其中"数据浏览器"要把**源数据（采集记录 recordings）**和**结果（派生输出 study_outputs）**放在一棵 BIDS 树里一起看。光有树还不够——用户真正的诉求是**挑出一组文件同时观察、互相对比**。

> 黑话铺垫：**BIDS** 是脑电数据的标准目录规范（按 被试 / 会话 / 任务 / 轮次 组织）；**派生（derived）** 指原始数据经处理后产出的中间或最终结果。

---

## 2. 核心需求（用户的 4 个典型场景）

| # | 场景 | 一句话 |
|---|---|---|
| A | 跨被试 · 同条件 | 所有被试在 `Stimulus/S9` 条件下的 ERP，叠一起看组效应 |
| B | 单被试 · 跨条件 | `sub-093` 在不同条件（go / nogo）下的 ERP，看条件差异 |
| C | 同源 · 处理前后 | 同一段 `sub-093 task-rest`，滤波**前** raw vs 滤波**后** filtered，看滤波效果 |
| D | 同源 · 不同参数 | 同一段数据，1–40Hz vs 1–30Hz 两种滤波范围的结果，调参对比 |

**共同本质**：这四个都是「**固定几个维度、放开另几个维度**」——也就是在一个多维数据立方体上切一刀。

---

## 3. 数据的维度（多维立方体）

每个文件（源或派生）都能用这几根轴定位，正好是 `study_outputs` / `recordings` 已有的字段：

| 轴 | 字段 | 取值例 |
|---|---|---|
| 被试 | `bids_subject_id` | sub-093 / sub-094 / …（或「总体平均」grand-average） |
| 会话 / 任务 / 轮次 | `session / task / run_label` | task-rest |
| 条件 | `condition` | Stimulus/S9、go、nogo |
| 处理阶段 | `data_type` + `produced_by_node_type` | raw（源）→ filtered_raw → epochs → evoked |
| 参数 | `produced_by_params` | filter: 1–40Hz / 1–30Hz |
| 来源 | 源 / 派生 | recording vs study_output |

四个场景就是固定/放开的不同组合：

- **A** = 固定 `condition`、固定 `data_type`，放开 `subject`
- **B** = 固定 `subject`、固定 `data_type`，放开 `condition`
- **C** = 固定 `subject+task`，放开 `data_type`（raw ↔ filtered）
- **D** = 固定 `subject+task+data_type`，放开 `produced_by_params`

> 结论：**不用为每个场景做一个专门 UI**，只要一个「多维筛选器」——每根轴能选「全部 / 某一个 / 多个」，四个场景自然都覆盖。

---

## 4. 选择器交互（复用 LoadData 那套）

LoadData 现成的模式可以直接搬：**左边按维度筛 → 候选列表 → Include/Exclude → Selected 篮子**。

```
┌ 维度筛选 ──────────┐   ┌ 候选文件 ──────┐   ┌ Selected 篮子 ─┐
│ 被试  [全部▼]       │   │ ☑ sub-093 ERP  │   │ sub-093 ERP    │
│ 条件  [Stimulus/S9] │ → │ ☑ sub-094 ERP  │ → │ sub-094 ERP    │
│ 阶段  [evoked]      │   │ ☐ sub-095 ERP  │   │ …              │
│ 参数  [全部]        │   └────────────────┘   └────────────────┘
└────────────────────┘        ↑ Include / Exclude       ↓「一起观察」
```

- **每根轴一个下拉/多选**：默认「全部」，选一个就是固定该维度，选多个就是放开但限定范围。
- **Include / Exclude**：和 LoadData 一致——先用筛选粗筛，再手动勾掉个别离群文件。
- **Selected 篮子**：选中的文件进篮子，点「一起观察」送到右侧观察台。
- **快捷预设**（可选）：把四个高频场景做成一键按钮（「跨被试看这个条件」「这个被试看所有条件」「和处理前对比」「换个参数对比」），点一下自动配好筛选轴——降低认知负担。

---

## 5. 观察台（多文件怎么一起看）

- **叠看（overlay）**：多条波形叠在同一张图、不同颜色——适合 A/B/C/D 全部，对比最直观（ERP 叠加是 EEG 最常见看法）。
- **分屏（grid）**：每个文件一格——适合波形差异大、叠一起糊成一团时。
- 两种模式一个开关切换；默认叠看。
- 源（raw）和派生（filtered/evoked）用**颜色族**区分（源蓝、结果绿），叠看时一眼分清谁是谁。

---

## 6. 后端数据契约（要补的端点）

现状：源在 `data`（recordings 查询）、派生在 `results`（study_outputs 查询），**两套**。数据浏览器要合一：

- **新增聚合端点** `GET /studies/{id}/browser-tree`：按 `被试 > 任务 > {源 recordings + 派生 study_outputs}` 返回一棵树，每个叶子带上 §3 的全部维度字段（供前端筛选 + 分色）。
- **维度元数据**：返回各轴的可选值（有哪些被试 / 条件 / 阶段 / 参数组合），供筛选下拉填充——和 LoadData 的 `resolve` 端点同思路。
- 观察单文件走现成的 `GET /outputs/{id}/preview` · `/timeseries`；多文件观察 = 前端并发取各文件 timeseries 后叠图，**后端不用新接口**。

---

## 7. 「总体平均」与「个体」并存

爸爸提到既有每个人的数据、也有总体平均（grand average）。处理：

- grand-average 也是一条 `study_output`（`bids_subject_id` 记为特殊值如 `grand-average` 或空），在树里挂在「全体 / 跨被试」分组下，和单被试并列。
- 选择器的「被试」轴多一个选项「总体平均」，于是「看总体平均 vs 看某几个被试」也落在同一套筛选里。

---

## 8. 实施阶段（建议）

1. **后端**：`browser-tree` 聚合端点（源+派生合一树 + 维度元数据）。
2. **前端组件 P1**：BIDS 树 + 单文件双击观察（先把"看得到数据"做实）。
3. **前端组件 P2**：多维筛选器 + Include/Exclude + Selected 篮子（复用 LoadData 组件逻辑）。
4. **前端组件 P3**：多文件叠看 / 分屏观察台。
5. **可选 P4**：四场景快捷预设按钮。

> 风险点：`produced_by_params` 维度（场景 D 调参对比）依赖节点参数被规范记录——目前 params 是自由 JSONB，要约定"滤波范围"等关键参数的稳定取值路径，筛选轴才能可靠归类。
