# 派生数据集（DerivedDataset）模型设计与实施方案

文档生成时间：2026-05-23 17:32:59 +08:00

## 背景

当前 Pipeline 跑完后，产物分散在两张表里：

- `pipeline_artifacts` — 每个节点产出的文件级记录
- `analysis_results` — 经过 Save 节点登记的"正式结果"

两套概念让用户混淆："artifact 和 result 有啥区别？"。同时缺少跨 Run 浏览、批量重命名、按被试聚合等基础能力。`analysis_results` 表存在但没有 list 接口，前端完全不可见。

由于本地代码尚无线上数据，决定**直接合并为单一 `derived_datasets` 概念**，不需要双轨过渡。

## 一、最终目标

`derived_datasets` 成为唯一用户可见的产物概念。`pipeline_artifacts` 和 `analysis_results` 两张表都不再存在。前端、API、文档统一用 `derived_dataset`。

物理文件落到磁盘的方式保持现状（按 Run 隔离），但用户不通过路径访问，永远通过 DB 查询。

## 二、核心设计原则

1. **数据库是事实源，文件系统是缓存**。用户从不通过路径访问数据，永远通过 DB 查询。
2. **存储与显示分离**。物理文件用稳定 ID 命名；用户看到的是 `display_name`，可批量编辑。
3. **追溯通过 DB 字段，不通过文件名前缀**。不复刻 Letswave 的 `ica_ep_bp_butt_sub01.lw6` 模式。
4. **同一份数据可在多个视角出现**。`按 Run / 按被试 / 按 Pipeline / 按结果类型` 是不同的视图，但物理只有一份。
5. **永久 vs 临时是显式策略**。`retention_status` 五档行为明确。
6. **可重算优先于必保留**。能从输入 + 定义 + 参数重建的就不一定永远存。

## 三、数据模型

### 新表 `derived_datasets`

```sql
CREATE TABLE derived_datasets (
  id                       UUID PRIMARY KEY,
  study_id                 VARCHAR NOT NULL,

  -- 来源追溯
  produced_by_run_id       UUID REFERENCES pipeline_runs(id),
  produced_by_node_id      VARCHAR,
  produced_by_node_type    VARCHAR,
  produced_by_params       JSONB,
  upstream_dataset_ids     JSONB DEFAULT '[]',  -- list[UUID]
  upstream_recording_ids   JSONB DEFAULT '[]',  -- list[UUID]

  -- 数据语义
  data_type                VARCHAR NOT NULL,
  subject_id               UUID NULL,
  bids_subject_id          VARCHAR NULL,
  session                  VARCHAR NULL,
  task                     VARCHAR NULL,
  run_label                VARCHAR NULL,
  condition                VARCHAR NULL,

  -- 用户层面
  display_name             VARCHAR,
  description              TEXT,
  tags                     JSONB DEFAULT '[]',

  -- 物理存储
  storage_uri              VARCHAR NOT NULL,
  logical_path             VARCHAR,
  file_role                VARCHAR,
  file_size                BIGINT,
  sha256                   VARCHAR(64),
  mime_type                VARCHAR,

  -- 生命周期
  retention_status         VARCHAR NOT NULL DEFAULT 'current',
                           -- current | pinned | cached | temporary | deleted
  retention_expires_at     TIMESTAMP NULL,

  -- 预览索引
  preview_json             JSONB,

  -- 元数据
  created_at               TIMESTAMP NOT NULL,
  created_by               UUID,
  updated_at               TIMESTAMP NOT NULL,
  deleted_at               TIMESTAMP NULL
);

CREATE INDEX idx_derived_study           ON derived_datasets (study_id, retention_status, created_at DESC);
CREATE INDEX idx_derived_subject_type    ON derived_datasets (study_id, bids_subject_id, data_type);
CREATE INDEX idx_derived_run             ON derived_datasets (produced_by_run_id);
CREATE INDEX idx_derived_tags            ON derived_datasets USING GIN (tags);
CREATE UNIQUE INDEX idx_derived_sha256   ON derived_datasets (study_id, sha256) WHERE sha256 IS NOT NULL;
```

### 字段说明

| 字段组 | 说明 |
|---|---|
| 来源追溯 | `produced_by_run_id + node_id + node_type + params` 是这个产物的"出生证"；`upstream_dataset_ids` 是直接上游派生数据，`upstream_recording_ids` 是最终溯源到的原始 recording |
| 数据语义 | `data_type` 用枚举（raw / filtered_raw / ica_cleaned / epochs / evoked / psd / tfr / connectivity / microstate / source_estimate / metadata）；`subject/session/task/run_label/condition` 让筛选 chip 直接复用 LoadData 那套 |
| 用户层面 | `display_name` + `description` + `tags` 是用户可编辑层；用户改这些不影响物理文件 |
| 物理存储 | `storage_uri` 指向真实文件位置；`sha256` 用于潜在的内容去重 |
| 生命周期 | `retention_status` 五档 + `retention_expires_at` 定时清理时间 |
| 预览索引 | `preview_json` 存通道数、采样率、事件计数等轻量元数据，前端列表不需要打开文件就能展示 |

## 四、Save 节点语义变更

旧 Save：写一行 analysis_results，复制文件元数据。

新 Save：**不写文件，只 promote 上游派生数据**

```python
def run_save_result(context, upstream_datasets):
    """Promote upstream derived datasets to retention=current/pinned with metadata."""
    display_name_tpl = context.params.get("display_name") or ""
    retention = context.params.get("retention", "current")
    tags = context.params.get("tags") or []
    for ds in upstream_datasets:
        ds.retention_status = retention
        ds.retention_expires_at = None
        if display_name_tpl:
            ds.display_name = _apply_template(display_name_tpl, ds)
        if tags:
            ds.tags = list(set([*ds.tags, *tags]))
    return upstream_datasets
```

NodeSpec 改为：
- 去掉 `outputs`（Save 是终点）
- 属性：`display_name`（支持 `{subject} {task} {condition} {data_type}` 模板）、`retention`（current / pinned）、`tags`（数组）

## 五、Retention 默认策略

| 节点类型 | 默认 retention |
|---|---|
| LoadData（不产生派生数据） | 不适用 |
| Filter / ICA / Reference / Resample | `cached`（自动清理候选） |
| Epoch / ERP / PSD / TFR / ... | `cached` |
| 被 Save 节点引用的产物 | 升级为 `current` 或 `pinned` |
| `save_output=true` 的节点直接产出 | `current`（不进 cache）|

清理任务按 `retention_status + retention_expires_at` 决定何时回收。被下游 Run 依赖的产物不可清理。

## 十、关键决策（已与用户确认方向）

1. **概念合并**：走"派生数据集"合并方案。删除 pipeline_artifacts 和 analysis_results 两张表。
2. **Save 节点保留**：但语义改为 promote 上游 derived_dataset（不再写新文件）。
3. **中间产物默认 retention=cached**：被 Save 引用的升级为 current / pinned。
4. **upstream 关系**：用 `upstream_dataset_ids JSONB` 数组 + GIN 索引；不另起 dependencies 表。
5. **sha256 去重**：记录字段但物理上仍按 Run 隔离存储；逻辑去重在前端列表层做。
6. **数据类型枚举**：raw / filtered_raw / ica_cleaned / epochs / evoked / psd / tfr / connectivity / microstate / source_estimate / metadata。

## 十一、实施方案概览

分阶段实施，每步独立可交付：

1. **数据模型与迁移** — 新表 + 删旧表
2. **Schema + Store 层** — 数据契约与文件落地
3. **Dispatcher 改造** — 各执行器写入新表
4. **Save 执行器重写** — promote 语义
5. **路由替换 + 新增列表接口** — 后端 API 闭环
6. **前端类型与 API client** — 跟着后端契约更新
7. **PipelinePage 适配** — Run 抽屉与 Save 节点 UI
8. **新增 `/results` 页面** — 跨 Run 浏览
9. **NodeSpec 与文档更新** — Save 节点 + docs_v2
