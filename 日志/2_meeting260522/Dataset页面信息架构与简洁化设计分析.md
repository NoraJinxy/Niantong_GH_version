# Dataset 页面信息架构与简洁化设计分析

文档生成时间：2026-05-23 00:27:20 +08:00

## 1. 背景

当前 Dataset 页面已经完成 Dataset-first 导入主流程，但页面把数据集资产、配套 Study、挂载关系、working 文件索引、批量导入状态、底层文件角色等信息同时暴露在主界面上。对于数据处理型功能网站来说，这会让页面显得“工程调试化”，用户在完成高频任务时需要穿过过多底层信息。

页面应当更像一个简洁精致的数据处理工作台：默认帮助用户快速判断“我有哪些数据集、当前选中数据集是否可用、是否需要导入、导入进度如何、后续能不能进入工作流”，底层 ID、mount、文件索引明细、逻辑路径、校验信息只在需要追溯、排错或审计时展开。

## 2. Dataset 页面的核心职责

Dataset 页面建议承担四个职责：

1. 管理数据集资产：创建、搜索、筛选、选择数据集，查看数据集当前状态。
2. 导入原始数据：把 EDF/BDF/BrainVision 等原始数据导入 Dataset working 版本。
3. 观察导入结果：确认导入批次、Recording 数量、文件角色生成状态、失败项和可重试项。
4. 进入后续处理：让用户知道该 Dataset 是否已经可以用于 QC、Pipeline/Run 或预览分析。

Dataset 页面不应默认承担“完整文件浏览器”和“后端调试面板”的职责。文件级索引、UUID、mount_id、Study ID、dataset_files 细节应进入详情抽屉、审计信息、开发者信息或高级模式。

## 3. 当前页面主要问题

### 3.1 默认暴露了过多底层标识

当前页面直接展示 Dataset UUID，例如 `088c2f07-bb17-455d-96ea-0e76989eaf04`。这类 ID 对普通用户没有判断价值，只在排错、接口联调、日志追踪时有用。

同类问题还包括：

- Dataset Asset ID
- Study ID
- mount_id
- mount_name
- dataset_files 技术名词
- original upload / Raw BIDS / canonical FIF 的完整技术链条

建议默认隐藏这些信息，只保留用户可理解的名称、状态、数量、时间和下一步动作。

### 3.2 文件索引列表过早、过长、过细

截图中 working 文件索引默认展示一行行逻辑路径。文件数量达到数百时，页面主视觉被路径列表占满，但用户通常更关心：

- 有多少名受试者
- 有多少条 Recording
- 有多少文件
- 原始文件、BIDS 逻辑文件、FIF 文件是否生成完成
- 是否存在失败、缺失或等待处理项

单个文件名和完整逻辑路径只适合在“文件索引详情”中按需查看。主界面默认展示文件明细会降低效率，也让页面显得不够优雅。

### 3.3 导入队列状态过于展开

批量导入时，每组数据都展开显示较多说明块。60 组文件时，用户需要上下滚动很长距离，整体进度、失败项、待处理项反而不突出。

导入过程应该默认用紧凑队列表格或列表呈现，一行代表一组 Recording，展示 subject、task、格式、状态、进度、错误摘要。详细文件组成、original/Raw BIDS/canonical FIF/dataset_files 状态应通过行展开查看。

### 3.4 主界面信息层级不够清晰

当前页面上方统计、左侧目录、右侧详情、文件索引、导入区域之间的层级比较接近，导致用户不容易判断当前最重要动作是什么。

建议将主行动线明确为：

1. 选择或新建 Dataset
2. 查看 Dataset 摘要与健康状态
3. 点击“导入数据”进入导入区
4. 完成后查看导入批次摘要
5. 进入 QC 或 Pipeline

## 4. 默认应该暴露的信息

默认暴露的信息应围绕用户决策，而不是围绕数据库结构。

### 4.1 数据集目录默认字段

左侧或主列表中建议展示：

- 数据集名称
- code
- 状态：工作中、可用、归档、导入中、存在错误
- 可见性：私有、团队、公开
- Recording 数量
- 受试者数量
- 总体量
- 最近更新时间或最近导入时间

不建议默认展示：

- Dataset UUID
- Dataset Version ID
- Study ID
- mount_id
- storage_uri
- 服务器路径

### 4.2 数据集详情默认字段

选中数据集后，详情页默认展示：

- 名称、描述、状态
- code
- 最近导入时间
- 数据规模：subjects / recordings / files / size
- 文件角色生成概况：原始数据、BIDS 逻辑视图、canonical FIF
- 质量概况：待 QC、通过、警告、失败
- 当前可执行动作：继续导入、查看记录、进入工作流、刷新状态

Dataset UUID 可放到“更多信息”或“技术信息”中，默认折叠，并提供复制按钮。

### 4.3 导入区默认字段

导入区默认展示：

- 当前导入目标：数据集名称
- 是否已准备好导入
- 文件选择入口：选择文件、选择文件夹、拖拽
- 批量队列摘要：总组数、可导入、已完成、失败、跳过
- 总进度条
- 紧凑导入队列

不建议默认展示：

- Study ID
- Dataset Asset ID
- mount_name
- original upload / Raw BIDS / canonical FIF / dataset_files 的逐项说明

这些内容可以放在“导入详情”展开区中。

## 5. 默认不应该暴露，但需要保留入口的信息

以下信息对系统追溯重要，但不应成为普通用户默认视图：

- Dataset UUID
- Dataset Version ID
- Study ID
- mount_id
- mount_name
- storage_uri
- sha256
- dataset_files 逐文件逻辑路径
- canonical FIF 物理路径
- 原始服务器路径
- API 返回的技术字段
- 审计事件 ID

建议统一放入：

- “技术信息”折叠面板
- “文件索引”独立标签页
- “查看详情”抽屉
- 管理员或开发者模式

服务器绝对路径仍然不应暴露给普通用户。

## 6. 推荐页面结构

建议把 Dataset 页面拆成三个清晰区域。

```text
顶部工具条
数据集管理    搜索数据集...    状态筛选    新建数据集    导入数据

左侧：数据集列表
- 数据集名称 / code
- 状态标签
- recordings / subjects / size
- 最近更新

右侧：数据集工作台
Tab 1 概览
  - 数据规模
  - 导入状态
  - 文件角色生成概况
  - 最近导入批次
  - 下一步动作

Tab 2 导入
  - 拖拽/选择文件
  - 批量队列
  - 总进度
  - 错误与重试

Tab 3 Records
  - subject / task / session / run
  - 状态 / 版本 / QC

Tab 4 文件索引
  - 默认只展示摘要
  - 搜索、筛选、分页
  - 按需展开逻辑路径

Tab 5 技术信息
  - UUID / mount / Study / version / sha256
  - 仅排错和审计使用
```

如果希望进一步简化，可以把“文件索引”和“技术信息”合并为一个“更多”区域，默认折叠。

## 7. 文件索引如何呈现

文件索引不建议在 Dataset 概览页默认逐行展示。更合适的方式是：

### 7.1 概览页只展示摘要

默认展示五个数字即可：

- 原始文件数
- Raw BIDS 文件数
- canonical FIF 文件数
- 派生文件数
- 总体量

再加一个状态：

- 已完成
- 生成中
- 部分缺失
- 存在错误

### 7.2 文件明细进入独立标签页

用户点击“查看文件索引”后再进入明细。明细区应支持：

- 按角色筛选：original、raw_bids、canonical_fif、derivative、metadata
- 按 subject / task 搜索
- 分页或虚拟滚动
- 默认每页 30 或 50 条
- 展开行查看逻辑路径、大小、sha256、创建时间
- 一键复制逻辑路径

不要在主概览页直接铺开 720 条文件。

### 7.3 目录树只作为辅助视图

如果用户需要理解 BIDS 目录结构，可提供“目录树视图”。但目录树默认应按层级折叠，只展开到 subject 或 task，不要一次性展开到每个文件。

## 8. 导入队列如何呈现

批量导入应优先表达“任务队列”，不是“表单列表”。

### 8.1 选择文件后的默认视图

建议每组 Recording 一行：

```text
[ ] sub-ADMU025    task-ec    EDF    1 file    ready
[ ] sub-ADMU025    task-eo    EDF    1 file    done
[ ] sub-ADMU032    task-ec    EDF    1 file    failed
```

行内可编辑 subject、task、session、run，但不要让输入框占满整个页面。默认显示为文本，点击后编辑，或在行右侧提供“编辑”按钮。

### 8.2 总进度固定在底部或导入区顶部

批量导入时，总进度比单组说明更重要。建议：

- 显示 `18 / 60 已完成`
- 显示失败数和可重试数
- 提供“只看失败”“重试失败”“取消剩余”
- 进度条固定在导入区顶部或底部，滚动时仍可见

### 8.3 单组详情按需展开

每一组的详细信息折叠显示：

- 原始文件列表
- BrainVision 三件套完整性
- original upload 状态
- Raw BIDS 状态
- canonical FIF 状态
- dataset_files 写入状态
- 后端返回错误

成功项默认收起，失败项自动展开。

## 9. 交互原则

1. 默认流程应简单：新建 Dataset 后自动准备配套 Study，不要求用户理解 Study/mount。
2. 用户看到的是“数据集”和“记录”，不是“数据库对象”和“挂载关系”。
3. 高频信息默认展示，低频追溯信息折叠。
4. 成功状态应轻量化，不要每条成功记录都使用大面积绿色块。
5. 失败状态要突出，并提供明确动作：查看原因、重试、跳过、重新选择文件。
6. 列表应紧凑，适合几十到几百条数据。
7. 长路径、UUID、hash、storage_uri 只在详情中展示。
8. 对同一批导入，用户应能快速看到整体进度和失败项，而不是逐条读过程说明。

## 10. 建议优先级

### P0：立即优化默认信息暴露

- 默认隐藏 Dataset UUID、Study ID、mount_id。
- “当前导入目标”只展示数据集名称、状态和“已准备好”。
- working 文件索引默认改为摘要，不展示逐文件路径。
- 上传组件默认隐藏 Dataset Asset ID、mount_name、Study ID。

### P1：重构导入队列展示

- 把导入组从大块卡片改为紧凑队列。
- 顶部或底部增加总进度条。
- 成功项收起，失败项自动展开。
- subject/task/session/run 改为行内编辑或批量编辑。

### P2：增加 Dataset 概览指标

- 增加 recordings、subjects、文件体量、最近导入时间。
- 增加文件角色生成状态。
- 增加最近导入批次摘要。

### P3：文件索引独立化

- 增加“文件索引”标签页或抽屉。
- 支持角色筛选、搜索、分页。
- 只在明细区展示逻辑路径和文件角色。

### P4：技术信息独立化

- 新增“技术信息”折叠区域。
- 放置 Dataset UUID、Study ID、mount_id、version_id、sha256 等追溯字段。
- 提供复制按钮，避免污染主界面。

## 11. 推荐的页面文案口径

建议减少工程词汇，替换为用户任务语言：

- `Dataset Asset ID` 改为折叠区内的 `数据集技术 ID`
- `mount_name` 改为折叠区内的 `挂载名`
- `dataset_files` 改为 `文件索引`
- `canonical FIF` 可在概览中显示为 `标准 FIF`
- `Raw BIDS` 可显示为 `BIDS 逻辑视图`
- `original upload` 可显示为 `原始上传`
- `Study` 在 Dataset 页默认称为 `处理工作空间`，只有技术信息中再出现 Study

## 12. 目标体验

优化后的 Dataset 页面应让用户在 5 秒内回答四个问题：

1. 我现在选中的是哪个数据集？
2. 这个数据集有多少数据，是否导入完成？
3. 如果要继续导入，我应该点哪里？
4. 如果导入失败，我应该处理哪几条？

而不是让用户先理解 UUID、mount、dataset_files、Study 与文件路径之间的关系。

## 13. 后续实现建议

下一步可按以下顺序改造：

1. 先改信息隐藏和摘要展示，不改接口。
2. 再把文件索引列表迁移到独立标签页或抽屉。
3. 再重构 BidsUploadPanel 的批量队列视觉。
4. 最后根据需要补充后端聚合字段，例如 subjects_count、recordings_count、latest_import_batch、file_role_counts。

这样可以先快速改善界面复杂度，同时避免一次性重写 Dataset 导入主流程带来风险。
