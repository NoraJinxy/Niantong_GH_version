# 前端 Dataset / Study / Pipeline / Run 功能规划简要说明

## 1. 文档定位

本文是面向前端设计的简要功能规划，用于说明 Dataset、Study、Pipeline、Run 四个核心对象在页面中的含义、边界和交互关系。

配套文档：

- `日志/2_meeting260522/前端页面与Dataset-Study-Pipeline-Run规则差异分析.md`
- `日志/2_meeting260522/前端Dataset-Study-Pipeline-Run改造实现工作计划.md`

## 2. 总体原则

前端不应只是把后端表和文件目录展示出来，而应把用户的工作流组织成四个可理解的对象：

- Dataset：我有哪些可用数据。
- Study：我在哪个研究项里组织协作和分析。
- Pipeline：我要怎么处理数据。
- Run：某一次到底用了什么数据、什么参数、产生了什么结果。

这四个对象的关系是：

```text
Dataset 数据集
  被 Study 引用或挂载
Study 研究项
  管理成员、数据、工作流和执行记录
Pipeline 工作流
  定义处理逻辑和选择规则
Run 执行项
  固定一次运行的输入、参数、输出和追踪记录
```

## 3. Dataset 前端功能规划

Dataset 是前端的数据资产入口，用户看到的是“可用数据”，不是服务器文件夹。

前端应支持：

- 上传脑电原始数据，例如 BrainVision、EDF、BDF。
- 展示数据导入状态，包括 original upload、Raw BIDS 逻辑视图、canonical FIF。
- 展示 Recording、Session、Run、Task、Marker 等可筛选维度。
- 展示 dataset_files 中的文件索引、文件角色、校验状态、预览和下载入口。
- 提供批量筛选、批量选择和快速定位能力，避免用户理解底层目录结构。

前端不应突出展示：

- 服务器绝对路径。
- `source_path`、`fif_path`、`bids_root` 这类实现字段。
- 要求用户直接操作文件目录。

MVP 中，Dataset 可以先表现为 Study 内的 working Dataset，不急于做公开发布、共享市场或复杂版本发布。

## 4. Study 前端功能规划

Study 是前端的研究工作空间，用来承载协作、数据引用、工作流和执行记录。旧后端接口可以继续叫 `/projects`，但前端产品语义应逐步改为 Study / 研究项。

前端应支持：

- 创建、查看、归档、恢复研究项。
- 展示研究项成员、角色、运行权限、编辑权限。
- 展示 Study 已挂载或关联的数据集。
- 展示 Study 下的 Pipeline 列表、Run 列表、Artifact 列表。
- 展示最近活动，例如上传、重传、运行、取消、重试、固定输出、清理输出。
- 展示运行锁和编辑锁，让用户知道当前谁在编辑或运行。

Study 页面不拥有 Dataset 的底层文件，只负责引用数据、组织分析和呈现协作状态。

## 5. Pipeline 前端功能规划

Pipeline 是工作流定义，前端用于编辑“怎么处理数据”，不是保存“这一次具体处理了哪些数据”。

前端应支持：

- 可视化编辑节点、连线、参数。
- 保存 Pipeline definition，并携带 `expected_version` 防止覆盖他人修改。
- 展示 Pipeline 状态，例如 draft、active、archived。
- 根据状态限制运行：draft 只允许试跑，archived 禁止新 Run。
- 配置 LoadData 的选择规则，例如筛选条件、数据范围、marker 条件。
- 校验节点是否有真实 executor，避免运行时才失败。
- 支持 Pipeline 编辑锁，避免多人同时修改同一个工作流。

关键边界：

- Pipeline 可以保存“选择规则”。
- Pipeline 不应标准保存“本次命中的具体 dataset_id / dataset_file_id”。
- 具体数据选择应在 Run 创建时通过 `selection_override` 固定。

## 6. Run 前端功能规划

Run 是一次执行项，前端用于回答“这一次到底发生了什么”。

前端应支持：

- 创建 Run，并选择 `run_mode`：
  - trial：试跑、探索、看单个被试或少量数据。
  - analysis：正式分析。
  - replay：复现历史运行。
  - system：系统任务或后台任务。
- 创建 Run，并选择 `save_policy`：
  - temporary：临时结果。
  - current：当前结果。
  - pinned：固定保留结果。
  - discard：运行后不保留主要输出。
- 在 Run 创建时设置 `selection_override`，固定本次使用的数据选择。
- 展示 Run 状态、输入快照、节点执行、任务事件、输出 Artifact、manifest、lineage。
- 支持取消、重试、查看错误、查看日志。
- 对 Artifact 提供固定、取消固定、隐藏、清理缓存等语义操作。

关键边界：

- Run 保存事实。
- Pipeline 保存定义。
- 后续追溯结果时，应以 Run 的输入快照和 manifest 为准，而不是重新读取“当前数据”。

## 7. 页面组织建议

### Dashboard

Dashboard 应作为四对象总览：

- Dataset：数据资产数量、导入状态、近期上传。
- Study：我参与的研究项、最近活动。
- Pipeline：最近编辑或运行的工作流。
- Run：正在运行、失败、等待处理、最近完成的执行项。

Dashboard 不应继续内嵌完整上传流程，也不应把服务器目录作为主要信息。

### Study 列表页

Study 列表页应展示：

- 研究项名称、状态、成员角色。
- 数据概况。
- Pipeline / Run 概况。
- 最近活动。
- 归档、恢复、清理等管理操作。

### Study 详情页

Study 详情页建议按以下区域组织：

- Overview：摘要、成员、权限、锁状态。
- Data：挂载 Dataset、Recording、文件状态。
- Pipelines：工作流列表。
- Runs：执行项列表。
- Artifacts：输出结果。
- Activity：审计和协作记录。

### Import 页面

Import 页面应成为 Dataset 导入入口：

- 选择 Study 或 working Dataset。
- 上传原始数据。
- 展示导入、Raw BIDS 逻辑视图、canonical FIF 生成状态。
- 展示可进入选择器的数据维度。

### Pipeline 页面

Pipeline 页面应承担两件事：

- 编辑工作流定义。
- 发起 Run 并查看 Run 详情。

但需要在 UI 上明显区分“保存 Pipeline”和“创建 Run”。

## 8. MVP 优先级

P0 必须先做：

- 前端术语从 Project-centric 收口到 Study / Dataset / Pipeline / Run。
- Dashboard 改为四对象总览。
- Study 列表和详情页隐藏服务器目录。
- Import 页面表达为 Dataset 导入。
- Pipeline 不再把具体数据命中作为标准保存内容。
- Run 创建和详情能展示 mode、policy、inputs、tasks、artifacts。

P1 随后做：

- Pipeline 编辑锁。
- Run cancel / retry。
- Task events 或轮询状态。
- Artifact 固定、隐藏、清理。
- Study 活动时间线。

P2 暂缓：

- Dataset 发布与共享市场。
- 观察、统计、作图、机器学习页面真实接入。
- 高级 lineage 图谱编辑。
- 完整多人实时协同编辑。

## 9. 当前结论

前端设计的核心不是多加几个页面，而是把用户心智从“项目目录和文件路径”切换为“数据资产、研究空间、工作流定义、运行事实”。

最重要的边界是：

- Dataset 管数据资产。
- Study 管协作空间。
- Pipeline 管处理定义。
- Run 管执行事实。

只要这个边界清楚，后续数据选择器、运行追踪、协作权限、结果清理和分享发布都会更容易落到产品界面中。

## 12. 第 4 步 Dashboard 功能规划落地

更新时间：2026-05-22 10:40:36 +08:00

Dashboard 已按前端规划落到四对象总览：

- Dataset：显示 Dataset Asset 摘要和导入入口。
- Study：显示研究项数量、最近研究项和 Study 管理入口。
- Pipeline：显示有限工作流摘要和编辑入口。
- Run：显示少量最近执行项、运行中/等待中数量和追踪入口。

本次调整确认了一个前端边界：

- Dashboard 只做摘要和导航，不承载完整上传。
- 上传进入 Dataset 导入页。
- Study 管理进入研究项列表页。
- 工作流定义和执行项追踪进入 Pipeline / Run 页面。
- 原始文件路径、canonical FIF 路径、服务器存储目录不在首页展示。

当前 Dashboard 的最近活动仍是前端聚合结果，后续应由 Study activity 或 audit_events summary API 替代。

## 13. 第 5 步 Study 列表功能规划落地

更新时间：2026-05-22 11:15:30 +08:00

Study 列表页已按规划从“项目目录管理”改为“研究项协作空间管理”：

- Study 是列表主对象，旧后端 Project 只作为接口兼容存在。
- 列表卡片展示 Study ID、我的角色、成员权限、最近活动。
- 数据概况显示为 Recording，而不是把旧 datasets 表条目直接称为完整 Dataset。
- Pipeline 和 Run 作为 Study 下的工作流和执行摘要展示。
- 回收站、恢复、清理使用 Study 治理语义。

本次进一步明确了清理边界：

- Study 清理不应物理删除 Dataset 原始资产。
- 已被 Run / Artifact 依赖的数据和输出不应被破坏。
- 前端已在危险操作中说明依赖保护语义，但最终阻断仍依赖后端检查。

当前列表页仍用有限前端聚合生成摘要。后续更合理的做法是补 `StudyOverview` API，一次返回成员、数据、Pipeline、Run、Artifact 和最近活动摘要。

## 14. 第 6 步 Study 主页功能规划落地

更新时间：2026-05-22 11:50:53 +08:00

Study 详情页已经从旧 Project Detail 收口为 Study 研究项主页，当前落地后的功能边界如下：

- Overview：展示 Study 状态、兼容标识、成员与权限、运行空间配额。旧 project id 只作为兼容标识，不作为文件目录入口。
- Data：展示 Dataset Mount 和 Recording 摘要。Dataset Mount 表示 Study 引用的数据资产；Recording 表示采集记录或旧 datasets 兼容记录。
- Pipelines：展示 Study 下的工作流定义摘要，只表达 Pipeline 状态、版本和节点数，不混入某次 Run 的事实数据。
- Runs：展示最近执行项摘要，包含 run mode、save policy、状态和时间，强调 Run 是一次执行事实。
- Artifacts：展示最近 Run 输出摘要，使用 Artifact 语义，不暴露服务器绝对路径。
- Activity：当前是已有对象时间聚合；正式协作审计应由后端 Study activity / audit_events 提供。

本次也确认了 Study 主页不应该承载的内容：

- 不做完整上传流程，上传入口跳转到 Dataset 导入页。
- 不展示 `source_uploads`、`fifdata`、`derivatives` 等旧目录解释。
- 不展示 `bids_root`、`source_path`、`fif_path` 等服务器路径字段。
- 不在 Study 主页继续做旧 QA mock/review；质量审核应在 Dataset/Recording 详情或 QC 模块中重新设计。
- 不伪造后端未提供的活动流、文件树、下载或预览能力。

当前前端实现仍是 MVP 兼容形态：Study 主页通过现有 `/projects`、Recording、Pipeline、Run、Artifact API 做有限摘要。后续如果后端提供 `StudyOverview`、Dataset File tree、Artifact preview/download、Study activity API，这个页面可以从“前端聚合”升级为“后端摘要驱动”。
