# 工业级 EEG 智能预处理与质量控制工具设计评估

## 1. 核心定位

目标不是做一个“黑箱式端到端 EEG 去噪大模型”，而是做一个面向科研和工程应用的 **工业级 EEG 分析工具**：

> 通过任务模板、自动化推荐、可解释质量控制、可重复 pipeline、人工复核和完整审计日志，帮助研究者稳定、低门槛、可复现地完成 EEG 预处理与质量管理。

核心原则：

- **不做黑箱端到端去噪**
- **不覆盖原始数据**
- **不自动删除高风险数据**
- **推荐可以自动化，执行必须可确认**
- **中间过程必须可重复、可解释、可审计**
- **每一步处理都应能生成日志、报告和回滚记录**
- **不同 EEG 任务应使用不同预处理模板，而不是一套通用流程**

---

## 2. 为什么不做端到端黑箱去噪

端到端去噪模型看起来先进，但不适合作为工业级科研工具的核心模块。

主要问题：

1. **不可解释**：用户很难知道模型删掉了什么，审稿人也很难相信模型没有改变真实脑信号。
2. **容易误伤真实神经活动**：额叶 ERP 可能被误认为眼电；高频脑活动、gamma、HFO 可能被误认为肌电；病理波、局灶异常可能被误认为噪声。
3. **难以复现和审计**：如果模型只输出 cleaned EEG，而没有 artifact estimate、处理理由和保真检查，很难进入严肃科研流程。
4. **风险与工业工具目标冲突**：工业级工具应强调稳定、透明、可控，而不是“看起来干净”。

因此，更合理的路线是：

> 做可解释的 AI 质控、自动化推荐、辅助决策和可审计工作流，而不是直接让 AI 黑箱清洗 EEG。

---

## 3. 重新定义评估维度

| 维度 | 含义 |
|---|---|
| 工业优先级 | 是否值得做进产品核心功能 |
| 用户价值 | 是否能显著降低使用门槛、节省时间 |
| 可解释性 | 用户能否理解为什么这样处理 |
| 可重复性 | 是否能固定参数、生成日志、复现实验流程 |
| 实现难度 | 工程和算法实现难度 |
| 风险等级 | 是否容易误删真实脑信号、误导用户或影响论文可信度 |
| 推荐形态 | 应该自动执行、自动建议，还是只做报告提示 |

评分说明：1 = 低，3 = 中，5 = 高。

## 5. 第一优先级：工业级平台底座

这些不是最“炫”的 AI 模块，但决定工具能不能真正用于科研与工程项目。

| 优先级 | 模块 | 原因 |
|---|---|---|
| 1 | 数据导入标准化 | 后续所有流程的基础 |
| 2 | 通道/导联/montage 检查 | EEG 分析最容易出错的基础环节 |
| 3 | 事件码/trigger 检查 | 直接决定 epoch 和条件分析是否可信 |
| 4 | pipeline 版本化与日志 | 工业级可重复性的核心 |
| 5 | 批处理队列 | 多被试分析必需 |
| 6 | 自动 QC 总览报告 | 让用户快速知道数据能不能用 |
| 7 | 人工复核与回滚 | 可信工具的底线 |

这一部分应作为第一版核心架构。

---

## 6. 第二优先级：自动化推荐与低门槛体验

自动化推荐非常重要，但它不应该是黑箱自动处理，而应是：

> 推荐 + 解释 + 用户确认 + 可回滚。

| 模块 | 推荐内容 | 处理策略 |
|---|---|---|
| 任务类型向导 | ERP/SSVEP/MI/静息态/睡眠/HFO/临床 | 用户选择或系统辅助判断 |
| 预处理模板推荐 | 不同任务推荐不同 pipeline | 可编辑、可保存 |
| 滤波参数推荐 | ERP、SSVEP、MI、HFO 使用不同滤波策略 | 必须显示风险提示 |
| epoch 范围推荐 | 根据任务和事件码推荐切段 | 用户确认 |
| baseline 推荐 | ERP 任务自动检查 baseline 合理性 | 用户确认 |
| 参考方式推荐 | 根据导联和任务建议 | 只建议，不默认改 |
| reject 阈值推荐 | 根据数据分布自适应建议 | 用户确认 |
| ICA 使用建议 | 判断是否适合跑 ICA、数据 rank 是否合理 | 系统诊断 |

## 7. 第三优先级：可解释 AI 质控

这是产品的“智能核心”，但仍然不是黑箱去噪。

| 模块 | 推荐方式 | 为什么适合工业工具 |
|---|---|---|
| 坏通道检测 | 给出异常原因：flatline、噪声、低相关、漂移 | 可解释、可复核 |
| epoch 质量评分 | 给出每个 trial 的质量分和异常类型 | 适合批处理 |
| 伪迹类型识别 | 标记眼电、肌电、心电、工频、运动 | 不直接删数据，风险可控 |
| AI 辅助 ICA 判断 | 给 IC 类别概率和证据图 | 接近现有科研习惯 |
| 任务特异性 QC | ERP/SSVEP/MI/HFO 分别给专业指标 | 体现工具专业度 |
| 预处理前后保真检查 | 看真实脑信号是否被改变 | 建立用户信任 |

## 8. 不同任务的推荐模板

工业级 EEG 工具不能给所有 EEG 使用同一套 pipeline。至少应该按任务类型拆分模板。

### 8.1 ERP / MMN / P300 模板

| 环节 | 推荐重点 |
|---|---|
| 高通 | 保守，避免过高高通改变慢成分 |
| 低通 | 根据 ERP 成分选择 |
| baseline | 必须检查 baseline window 是否干净 |
| 眼电 | 推荐 ICA/回归/ICLabel 辅助，但必须检查额叶信号保真 |
| epoch reject | 检查条件平衡 |
| QC | 峰值、潜伏期、拓扑、trial 数 |

### 8.2 SSVEP / ASSR 模板

| 环节 | 推荐重点 |
|---|---|
| 频率检查 | 目标频率及谐波是否可见 |
| 滤波 | 不能破坏目标频段和相位 |
| 工频 | 检查是否与刺激频率/谐波冲突 |
| epoch | 稳态窗口选择很关键 |
| QC | SNR、相干、相位锁定、频谱峰 |
| 保真 | 处理前后目标频率功率是否被改变 |

### 8.3 MI 模板

| 环节 | 推荐重点 |
|---|---|
| 频段 | μ/β 节律 |
| 空间模式 | C3/C4/Cz 附近质量 |
| 伪迹 | 肌电和运动伪迹特别重要 |
| epoch | cue 后时窗选择 |
| QC | ERD/ERS、左右手条件平衡 |
| 模型 | CSP/Riemannian/EEGNet baseline |

### 8.4 HFO / 高频分析模板

| 环节 | 推荐重点 |
|---|---|
| 滤波 | 极其谨慎，避免制造伪高频 |
| 肌电 | 高风险，不能激进去除 |
| 工频谐波 | 必须严格检查 |
| 坏通道 | 高频噪声通道要特别标记 |
| 保真 | 处理前后高频功率、瞬态事件、拓扑 |
| 风险提示 | 明确提示肌电与 HFO 混淆风险 |

### 8.5 静息态模板

| 环节 | 推荐重点 |
|---|---|
| 分段 | 连续数据分窗 |
| 漂移 | 慢漂移检查 |
| 眼电 | 眨眼和眼动状态很重要 |
| 频谱 | alpha peak、1/f、工频 |
| QC | 每段质量评分 |
| 保真 | 功率谱和连接指标稳定性 |

## 9. 自动化推荐分级

自动化不应只有“自动”或“不自动”两种状态，而应分层。

| 等级 | 名称 | 系统行为 | 例子 |
|---|---|---|---|
| Level 0 | 只报告 | 不建议处理，只显示问题 | 该被试坏通道比例较高 |
| Level 1 | 弱推荐 | 给出建议，但用户决定 | 建议检查 Fp1 是否为眼电污染 |
| Level 2 | 强推荐 | 默认选中，但执行前确认 | 建议插值 T7，因为低相关且高噪声 |
| Level 3 | 自动执行 | 风险极低、可完全复现的操作 | 格式转换、日志记录、生成报告 |

建议自动化等级：

| 操作 | 自动化等级 |
|---|---|
| 数据格式读取 | Level 3 |
| 生成 QC 报告 | Level 3 |
| 标记坏通道 | Level 1–2 |
| 插值坏通道 | Level 2 |
| 删除 epoch | Level 1–2 |
| 删除 ICA component | Level 1–2 |
| 改参考方式 | Level 1 |
| 改滤波策略 | Level 1 |
| 眼电处理 | Level 1–2 |
| 肌电处理 | Level 1 |
| 端到端清洗 | 不做 |

## 10. 工业级可信度机制

### 10.1 不覆盖原始数据

原始数据永远只读。所有处理生成派生数据。

### 10.2 每一步有 lineage

记录内容包括：

- 输入文件
- 软件版本
- 算法版本
- 参数
- 时间
- 操作者
- 输出文件
- 随机种子
- 被修改的通道 / epoch / IC

### 10.3 每个推荐都有证据

坏通道推荐应显示：

- 方差异常
- 邻近相关低
- 频谱异常
- flatline 时间比例
- 拓扑位置
- 原始波形片段

眼电 IC 推荐应显示：

- IC scalp map
- time course
- 频谱
- 与 EOG 相关
- 眨眼锁定平均
- 分类概率

### 10.4 每个高风险操作有保真检查

删除 IC 或插值通道后，应比较：

- ERP 峰值是否变化过大
- SSVEP 目标频率是否变化过大
- HFO 频段是否被削弱
- 条件差异是否反转
- trial 数是否失衡
- 拓扑是否发生异常改变

### 10.5 报告可以直接进入论文补充材料

报告内容包括：

- 坏通道列表
- 插值通道
- reject epoch 数
- 每个条件剩余 trial
- ICA 删除 IC
- 滤波和参考参数
- QC 指标
- 预处理前后图

## 11. 不建议做的方向

| 方向 | 原因 |
|---|---|
| 端到端 AI clean EEG | 黑箱、难解释、容易误伤真实脑信号 |
| 黑箱去噪 | 无法说明删掉了什么 |
| 一键自动删除 IC/epoch/channel | 高风险，不适合科研工具 |
| 没有证据的自动推荐 | 用户无法信任 |
| 没有日志的自动处理 | 不可复现 |
| 所有任务共用同一 pipeline | 忽视 ERP/SSVEP/MI/HFO 等任务差异 |
| 只追求“看起来更干净” | 可能破坏真实效应 |

## 12. 建议的产品路线

### 第一阶段：可信平台底座

目标：让 EEG 数据分析变得可导入、可检查、可批处理、可复现。

核心模块：

1. 数据导入标准化
2. 通道和 montage 检查
3. 事件码和 trigger 检查
4. pipeline 版本化
5. 批处理队列
6. 自动 QC 报告
7. 人工复核与回滚

### 第二阶段：自动化推荐系统

目标：降低使用门槛，让非专家也能选择合理的预处理流程。

核心模块：

1. 任务类型向导
2. ERP/SSVEP/MI/HFO/静息态模板
3. 自动滤波建议
4. epoch 和 baseline 推荐
5. 参考方式建议
6. ICA 使用建议
7. reject 阈值建议

### 第三阶段：可解释 AI 质控

目标：提高效率和一致性，但不做黑箱清洗。

核心模块：

1. 坏通道检测
2. epoch/trial 质量评分
3. 伪迹类型识别
4. AI 辅助 ICA 决策
5. 预处理前后保真检查
6. 自动生成方法段和补充 QC 表

### 第四阶段：团队化与长期智能化

目标：形成长期产品壁垒。

核心模块：

1. 用户自定义模板库
2. 团队协作与审批
3. 实验室级 pipeline 复用
4. 人机共训和主动学习
5. 跨设备、跨 montage 适配

## 14. 最终结论

你要做的不是：

> AI 替研究者黑箱清洗 EEG。

而是：

> AI 帮研究者把 EEG 预处理做得标准、可解释、可复现、可审计。

这个方向比黑箱大模型更适合工业级科研工具，也更容易获得用户、审稿人和科研团队的信任。

最终产品应定位为：

> 面向科研的工业级 EEG 智能预处理与质量控制平台。系统不黑箱清洗数据，而是通过任务模板、质量评估、可解释推荐和可追溯流程，帮助研究者高效、稳定、可复现地完成 EEG 预处理。
